# Pretrained GPT-2 through LeanExe

This plan expands the [Development Plan](../plan.md).  On 2026-09-17 the
user paused proof development and requested a working pretrained GPT-2
124M model with a 128-token context.  The user approved pinned Transformers
and safetensors dependencies in the existing PyTorch environment, followed
by FP32 arithmetic and packed binary tensors for LeanExe/WASM.

## Model and comparison boundary

Preserve the original twelve-layer architecture, width 768, twelve heads,
3,072-wide feed-forward layer, and 50,257-entry vocabulary.  QKV and output
projections have biases.  The vocabulary projection shares the input
embedding.  LayerNorm uses epsilon 1e-5, and GELU uses the original tanh
formula.  Load checkpoint weights as external binary data.

The [CPU reference](../data/gpt2-124m/README.md) checks pinned file hashes
and produces text with the original tokenizer.  Compare WASM logits and
intermediate tensors against this reference.  Its first command bounds
the combined prompt and completion at 128 tokens.  The WASM command uses
the same limit and retains attention keys and values for the current prefix.

## Compiler and runtime work

The existing binary64 intrinsics provide the pattern for binary32
arithmetic.  Add binary32 operations, conversions, and packed weight reads,
then compare Lean, IR, and Wasmtime execution.  Current array push and set
operations copy the array.  Indexed tensor construction needs one output
allocation, following the existing array-map emitter.

The host accepts binary tensor files and keeps a Wasmtime instance resident
across calls.  Measurements cover a GPT-sized matrix multiplication, one
complete block, all twelve blocks with the tied vocabulary projection,
and cached token steps through position 127.

## Exact execution proofs

The user resumed formal proof development on 2026-09-17.  The target is
checked agreement between the generated WASM and the Lean algorithm for
runtime weights and contexts through 128 tokens.  Numerical error bounds
and exact-byte packages remain deferred.

The [packed-read proof](../proofs/talos/lean/Project/PackedRead/Spec.lean)
connects the emitted `i32.load` to `LeanExe.Packed.getUInt32LE!` for every
represented byte array and valid offset.  It proves termination and
complete store preservation.  Shared memory lemmas will support packed
output construction and the tensor loops that follow.

Talos models binary32 arithmetic.  Pinned Lean 4.34.0-rc2 gives `Float32`
addition, subtraction, multiplication, division, and square root pure logical
definitions through `Float32.Model`.  The arithmetic proof must relate these
definitions to Talos's raw-bit operations.  Precision conversions remain
opaque in Lean and are outside the GPT-2 arithmetic call set.  An earlier
assessment that all these operations were opaque was incorrect.

The [addition](../proofs/talos/lean/Project/ProofKit/F32Add.lean),
[subtraction](../proofs/talos/lean/Project/ProofKit/F32Sub.lean),
[multiplication](../proofs/talos/lean/Project/ProofKit/F32Mul.lean),
[division](../proofs/talos/lean/Project/ProofKit/F32Div.lean), and
[square-root](../proofs/talos/lean/Project/ProofKit/F32Sqrt.lean)
theorems establish exact equality between the source intrinsics and Talos's
binary32 operations for all input words, including exceptional values.

The [cached-step theorem](../proofs/talos/lean/Project/Gpt2CachedStep/Spec.lean)
proves termination and exact cache and logit bytes for the generated public
entry.  Its accepted-input proof composes embedding, all twelve blocks,
cache extension, final normalization, vocabulary projection, and temporary
release.  Invalid weight length, token, position, or cache length produces
empty outputs and preserves the store.  The theorem assumes represented
protected inputs, a valid heap, a UInt64-representable position, and enough
capacity for each required allocation.  It imposes no bound on weight values.

The user requires emitted-WASM agreement with the Lean source it was compiled
from.  The conditional token-step theorem leaves the three invocation
obligations above open.  Tokenization in and out is assumed.  Comparing the
cached Lean algorithm with the separate full-prefix Lean algorithm is outside
this proof target.
