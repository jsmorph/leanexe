# Order book tests

`run.sh` compares [the order book's program](../../Demos/OrderBook/Program.lean) with [its specification](../../Demos/OrderBook/Spec.lean) and with a Python reference, `reference.py`, written from [the requirements](../../Demos/OrderBook/requirements.md).  The Python scripts carry PEP 723 metadata without dependencies and run through `uv run`.  Every command below runs from the repository root.

`uv run tests/orderbook/reference.py STREAM` runs a command stream from the empty book.  It reads `STREAM` as little-endian unsigned 64-bit words, takes them as consecutive seven-word records, and prints one record per line to stdout: an `event W0 W1 W2 W3 W4 W5 W6` line for each event in order, then `next N` with the id that the next accepted order would receive, then `bid ID ACCOUNT PRICE QTY` for each resting bid and `ask ID ACCOUNT PRICE QTY` for each resting ask, each side in priority order with the best first, and last `top BIDPRICE BIDQTY ASKPRICE ASKQTY`, with 0 for both values of an empty side.  All numbers are in decimal.  A file whose length is not a multiple of 8 bytes produces a message on stderr and exit status 2.

`uv run tests/orderbook/streams.py --seed S --commands N --out FILE [--profile P]` writes `N` seven-word records drawn from `random.Random(S)`, so the seed and the profile determine the file.  The profile `mixed`, the default, draws limits of all three times in force, markets, cancels, and reduces from three accounts, at prices from 500 to 510 and small quantities; `full` places 4,096 non-crossing GTC orders and then mixes orders that meet the full book, crossing orders, cancels that free slots, and reduces; `edges` puts words at the edges of their ranges and includes unknown kinds; and `truncated` writes the `N` records of `mixed` followed by one to six words, a shorter final record.  The generator imports `reference.py` from its own directory and runs each record through the reference's book, so that it can name the ids and accounts of resting orders.

`uv run tests/orderbook/make_edges.py OUT` writes the hand-written streams into the directory `OUT`, one `.bin` file per case, named for the case it covers, such as `self-trade-stop-behind-trade.bin` and `three-words.bin`.  The `book-full-*` streams start with the same 4,096 non-crossing GTC orders, which the docstring of `fill` in `make_edges.py` describes.  Running the script again rewrites the same files with the same contents.

`tests/orderbook/run.sh` builds `orderbook-compare`, the program of [`Compare.lean`](../TestSupport/OrderBook/Compare.lean), through `tools/leanrun`, and writes every stream under `build/orderbook/`.  Its `write` mode writes the samples of [`Samples.lean`](../../Demos/OrderBook/Samples.lean), each single record as a stream, and the streams of [`Edges.lean`](../TestSupport/OrderBook/Edges.lean), some of which start from a next id other than 1, and `make_edges.py` writes its streams.  `streams.py` writes the random streams: seeds 1 to 3 of 1,000 commands, seed 4 of 10,000, and seed 5 of 100,000 in the profiles `mixed`, `edges`, and `truncated`, and seeds 1 and 2 of 6,000 commands, seed 3 of 20,000, and seed 4 of 100,000 in the profile `full`.  On each stream, `orderbook-compare stream` checks the program's events, book, and top of book against `Spec.run` and prints them in the reference's format, and on each stream that starts from next id 1 the driver runs `reference.py` and compares the two outputs with `cmp`.  The driver prints one summary line with the counts, writes each failure to stderr, and exits with status 1 on any failure.  It needs `uv` on the search path and keeps uv's cache in `build/orderbook/uv-cache` unless `UV_CACHE_DIR` is set.
