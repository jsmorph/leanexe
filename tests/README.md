# Test suites

## Selecting tests

| Change or question | Checks and their scope |
|---|---|
| The modules and checks that a change reaches | [`tools/affected`](../tools/affected) prints the changed and affected modules, the targets to build, the names for `tests/verified/run.sh --cases`, and the other checks of the changed files, as [the tools guide](../tools/README.md#repository-checks) describes. |
| Documentation or repository layout | [`tools/check-doc-links.mjs`](../tools/check-doc-links.mjs) checks local links, section anchors, and reachability from the root README.  [`tools/source-layout`](../tools/source-layout) checks source imports and the verified module registry. |
| Runtime or pipeline | [`tests/verified/run.sh`](verified/run.sh) runs the cases of every registered module, and fails on a module without a case unless [the list of other drivers](verified/no-cases.txt) names it: [`tests/modules/run.sh`](modules/run.sh) runs the module cases of `euler` and of `shapes`, and [`tests/gpt/run.sh`](gpt/run.sh) those of `gpt`.  [`tests/modules/chunks.py`](modules/chunks.py) runs command streams on a book side through the verified `insert.wasm` whole, in chunks, and one command at a time, and it needs `uv` and the Wasmtime host. |
| Verified compiler or a pure program it compiles | [`tests/verified/run.sh`](verified/run.sh) builds its targets, emits modules, validates them with `wasm-tools`, and compares their cases in the Wasmtime host with native Lean.  Cases can state retained blocks and allocation limits as well as results.  The driver skips a check whose inputs keep the hash of a recorded pass, and `--no-cache` runs every check, as [the manual's section on recorded checks](../docs/verified-manual.md#recorded-checks) explains.  `--fast`, for development only, builds the package without the kernel's checks ([fast builds](../docs/verified-manual.md#fast-builds)), and [the manual's module cases](../docs/verified-manual.md#module-cases) describe focused runs.  [`tests/verified/emit-modules.sh`](verified/emit-modules.sh) writes every registered module into a directory and, with `--compare BASELINE`, requires each to equal the file of the same name in `BASELINE`. |
| Axioms of the repository's declarations | [`tests/verified/AllAxioms.lean`](verified/AllAxioms.lean), run with `lake env lean --run` after a build of `LeanExe`, `Examples`, `Demos`, `Verified`, `Library`, and `TestSupport`, walks the constants that the declarations of those libraries use and fails on an axiom other than `propext`, `Classical.choice`, and `Quot.sound`, with a chain of uses to each.  It covers the declarations that no `#print axioms` names, which the build's audit of the axiom reports leaves out. |
| Encoding or decoding | [`tests/decoder/DecodeTest.lean`](decoder/DecodeTest.lean) decodes the modules that `wasm-tools json-from-wast` extracts from the official WebAssembly testsuite, and it needs `wasm-tools` and the directory of the extracted modules.  [`tests/decoder/TableProfile.lean`](decoder/TableProfile.lean) covers the narrow table and export forms that WASI uses.  [The encoding guide](../LeanExe/Encoding/README.md#tests) gives their setup. |
| Talos, the WebAssembly semantics of the theorems | [`tests/talos/run.sh`](talos/run.sh) runs the testsuite runner of the pinned CodeLib revision over the official WebAssembly testsuite.  It fails on a failed command, an interpreter error, or exhausted fuel, and on any difference from the report that CodeLib commits.  It needs CodeLib's `vendor/testsuite` submodule and `wasm-tools` 1.251.0, and its outputs are in `build/talos/`. |
| Numerical algorithms | [`tests/verified/run.sh`](verified/run.sh) checks numerical byte and file theorems and runs the native accuracy checks under [test support](TestSupport/Numerics).  The [algorithm guides](../Library/README.md) state test inputs, reference comparisons, and the scope of the proved results. |
| Hash functions or their fixtures | The vector checks of [`tests/TestSupport/Hashing`](TestSupport/Hashing) compare the programs and the transcriptions of their specifications with the vectors that [Test inputs](../data/README.md) describes: the Lake executables `sha3-vectors`, `crc-vectors`, `siphash-vectors`, and `xxhash64-vectors`, and `Sha2Vectors.lean` and `HmacVectors.lean` under `lake env lean --run`. |
| Regular expressions, SplitMix64, or the CIC filter | [`tests/regex/run.sh`](regex/run.sh) checks `Library.Regex.matchWith` in native Lean against `Library.Regex.Spec.answer` and Python's `re.fullmatch` ([the regular-expression tests](../Library/Regex/README.md#tests)).  [`tests/prng/compare.py`](prng/compare.py) compares `prng.wasm` in the Wasmtime host with SplitMix64 as Sebastiano Vigna's reference C code computes it ([SplitMix64](../Library/Random/SplitMix64/README.md#building-running-and-testing)).  `uv run tests/cic/reference.py` runs the self-test of [the CIC filter's Python reference](cic/reference.py), whose outputs the filter's arm64 Image must write ([the CIC filter's tests](../Library/Numerics/Filters/Cic/README.md#tests)).  Each needs `uv`. |
| Packed bytes, WASI compilation, or stream effects | [`tests/wasi/run.sh`](wasi/run.sh) checks proofs, reflection, decoding, ownership, Lean action execution, and Wasmtime behavior, and it runs the drivers of [code generation](wasi/codegen-run.sh), [reflection](wasi/reflection-run.sh), [the scripted host](wasi/script-host-run.sh), [the Wasmtime host](wasi/host.sh), [acceptance](wasi/acceptance-run.sh), [`readAll`](wasi/readall-run.sh), [the flat call examples](wasi/sys-example-run.sh), and the running sums.  `--foundations-only` selects its proof and semantic checks, and the full mode needs `wasm-tools` and the Wasmtime host.  [The WASI manual](../docs/wasi.md#tests) explains the groups. |
| Flat WASI calls | [`tests/wasi/sys-run.sh`](wasi/sys-run.sh) checks the generated files against the pinned witx and runs the frame tests of the flat calls in Wasmtime 44, as [the manual's WASI and Linux tests](../docs/verified-manual.md#wasi-and-linux-tests) describe.  It needs the Wasmtime host, `wasm-tools`, and `uv`. |
| The Linux call layer | [`tests/linux/sys-run.sh`](linux/sys-run.sh) checks the generated table against the pinned syzlang files and runs the frame test of each described call natively and under `qemu-aarch64`, as [the manual's WASI and Linux tests](../docs/verified-manual.md#wasi-and-linux-tests) describe.  It runs no Lean, and it needs an AArch64 Linux host, the C compiler that `CC` names, `qemu-aarch64` or the emulator that `QEMU_USER` names, `uv`, and `systemd-run`. |
| AArch64 Linux executables | [`tests/linux/a64-elf.sh`](linux/a64-elf.sh) writes `flip.elf` and `stamp.elf`, [`a64-wasi.sh`](linux/a64-wasi.sh) `readall.elf`, `environ.elf`, `clockrandom.elf`, `sys.elf`, `args.elf`, and the demos' `histogram.elf`, `choice.elf`, and `manifest.elf`, [`a64-wasi-preopen.sh`](linux/a64-wasi-preopen.sh) `prestat.elf`, and [`a64-wasi-files.sh`](linux/a64-wasi-files.sh) `files.elf`.  Each script has the kernel check the theorem files of the executables that have them and runs its executables on the host's processor and under `qemu-aarch64`, and the demos' drivers run the demos' executables.  [`a64-wasi-clocks.sh`](linux/a64-wasi-clocks.sh) runs the stubs of `clock_time_get` and `random_get` at the edges of their requests, and the WASI scripts compare each command with its module in the Wasmtime host.  The scripts need an AArch64 Linux host with `qemu-aarch64`.  [The manual's WASI and Linux tests](../docs/verified-manual.md#wasi-and-linux-tests) give the other tools and the options of each script, and [the AArch64 document](../docs/a64-bare-metal.md#the-linux-target) gives the runs. |
| Integer or binary64 running sum | [`tests/running-sum/run.sh`](running-sum/run.sh) and [`tests/running-sumfp/run.sh`](running-sumfp/run.sh) check the applications' arithmetic, stream behavior, and compiled execution, and `tests/wasi/run.sh` runs them.  They need `uv`, `wasm-tools`, and the Wasmtime host.  The [integer](../Demos/RunningSum/README.md) and [binary64](../Demos/RunningSumFp/README.md) guides state the output and termination premises. |
| Random-residue histogram | [`tests/random-histogram/run.sh`](random-histogram/run.sh) checks the hashes of the reviewed specification, the axioms of the theorems, and the AArch64 back end's acceptance of the command's module, from which it writes the AArch64 Linux executable.  It runs the command in the Wasmtime host, on the host's processor, and under `qemu-aarch64`, as `RUNNERS` selects, with arguments that it must refuse and with values of N, whose ten counts must sum to N, and with a file size limit on the native and QEMU runners.  It runs the executable under `strace`, also with replies that `strace` injects.  It runs the module in the Wasmtime host with fixed random bytes from `--random-bytes`, and each output and status must equal the specification's.  It needs `wasm-tools`, GNU `sha256sum`, the Wasmtime host, `qemu-aarch64` or the emulator that `QEMU_USER` names, and for the native runner an AArch64 Linux host with `strace`.  [The demo's guide](../Demos/RandomHistogram/README.md#building-running-and-testing) states the theorems and the cases. |
| Unbiased random choice | [`tests/random-choice/run.sh`](random-choice/run.sh) checks the hashes of the reviewed specifications and the axioms of the theorems and writes the command's module and its AArch64 Linux executable.  It runs the command in the Wasmtime host, on the host's processor, and under `qemu-aarch64`, as `RUNNERS` selects, with arguments that it must refuse and with values of N and K, for which it must write K values in [1, N], one run under `/usr/bin/time -v`, and with a file size limit on the native and QEMU runners.  It runs the executable under `strace`, also with replies that `strace` injects.  It runs the module in the Wasmtime host with fixed random bytes from `--random-bytes`, and each output and status must equal the specification's.  It needs `wasm-tools`, GNU `sha256sum`, the Wasmtime host, `/usr/bin/time`, `qemu-aarch64` or the emulator that `QEMU_USER` names, and for the native runner an AArch64 Linux host with `strace`.  `BUILD=no` skips the steps before the runs and runs the module and the executable that a run of the driver left in `build/random-choice`.  [The demo's guide](../Demos/RandomChoice/README.md#building-running-and-testing) states the theorems and the cases. |
| SHA-256 manifest checker | [`tests/manifest-check/run.sh`](manifest-check/run.sh) checks the hashes of the reviewed specification and the axioms of the theorems and writes the command's module and its AArch64 Linux executable.  It runs the command in the Wasmtime host over a preopened test directory and the executable, with the directory as descriptor 3, on the host's processor and under `qemu-aarch64`, as `RUNNERS` selects.  The verdicts of each run must equal those of GNU `sha256sum -c`, except FAILED for each name that leaves the directory, and the executable's runs under `strace`, also with faults that `strace` injects, must make only the expected calls.  It needs `wasm-tools`, GNU `sha256sum`, the Wasmtime host, `qemu-aarch64` or the emulator that `QEMU_USER` names, of QEMU 9.2 or later, the first release that implements `openat2`, and for the native runner an AArch64 Linux host with `strace`.  [The demo's guide](../Demos/ManifestCheck/README.md#building-running-and-testing) states the theorems and the cases. |
| Translation to C | [`tests/native/run.sh`](native/run.sh) compares translated calls with Talos.  [`tests/native/verified.sh`](native/verified.sh) compares registered modules with Wasmtime, and [`tests/native/bytes.sh`](native/bytes.sh) compares the byte and literal examples with the cases that `tests/wasi/run.sh` checks in Wasmtime.  [`tests/native/clight.sh`](native/clight.sh) compares the Lean semantics with CompCert's interpreter on random programs, and [`tests/native/clight-rocq.sh`](native/clight-rocq.sh) compares the Rocq evaluator with the Lean semantics on the programs that `clight.sh` writes, with `coqc` and a CompCert tree whose proofs are built.  [`tests/native/subset.sh`](native/subset.sh) checks that every registered module lies in the translator's subset, and [`tests/native/bench.sh`](native/bench.sh) times workloads in C and in the Wasmtime host on an idle machine.  The drivers other than `subset.sh` need CompCert 3.18, `bench.sh` also needs the Wasmtime host, and [the translator design](../docs/native-translator.md#trust-argument-and-validation) explains what each comparison covers. |
| Aligned native translation | [`tests/native/aligned.sh`](native/aligned.sh) tests the requirement for aligned theorems.  `tests/native/verified.sh --aligned` runs the corpus modules that meet that requirement. |
| Bare-metal programs through CompCert | [`tests/baremetal/run.sh`](baremetal/run.sh) checks the startup code under QEMU's `virt` machine: the probe program, the faults of a store to the guard page, of a store to code, of a call into data, and of floating point without its enable, the entry levels, and the device tree. [`verified.sh`](baremetal/verified.sh) runs the cases of `tests/native/verified.sh` under QEMU and checks each call's stack against its bound.  [`m7.sh`](baremetal/m7.sh), [`req.sh`](baremetal/req.sh), and [`usart3.sh`](baremetal/usart3.sh) run the Cortex-M7 startup code, controller programs, and programs with device requests on QEMU's `mps2-an500` and on the NUCLEO-F767ZI.  The drivers need CompCert 3.18 for their target, whose driver, run-time library, and `clightgen` the variables `CCOMP`, `CCOMP_STDLIB`, and `CLIGHTGEN` name, and `qemu-system-aarch64` or `qemu-system-arm`.  `ACCEL=kvm` runs `run.sh`, `programs.sh`, `inputs.sh`, and `ctl.sh` under KVM on an AArch64 host.  `run.sh` also needs `nm` for AArch64 objects and `dtc`, which `NM` and `DTC` name, `req.sh` and `usart3.sh` need `uv` and for the gateway the minute series `SERIES`, and `usart3.sh` needs the board and `st-flash`, or Renode 1.17.0 for `emulate`.  [The test plan](../docs/native-bare-metal.md#test-plan) describes each test, and [the Rocq check](../rocq/README.md) checks the separate proof composition. |
| The AArch64 back end without C | [`tests/baremetal/a64-images.sh`](baremetal/a64-images.sh) writes the back end's programs as arm64 Images, has the kernel check each Image's file and theorems, and runs each under QEMU's `virt` machine, and [`a64-uart.sh`](baremetal/a64-uart.sh) does the same for Images that read their input from the UART. [`a64-encode.sh`](baremetal/a64-encode.sh) compares the encoder with the GNU assembler, [`a64-cosim.sh`](baremetal/a64-cosim.sh) co-simulates the model with QEMU, and [`a64-fpvectors.sh`](baremetal/a64-fpvectors.sh) and [`a64-fpexhaust.sh`](baremetal/a64-fpexhaust.sh) compare the floating-point forms with QEMU and the processor on vectors at the corner cases of IEEE 754 and, for the single-precision forms, on every 32-bit word or a sample of them.  `a64-images.sh`, `a64-uart.sh`, `a64-rcv.sh`, and the floating-point tests check QEMU's loading of each Image with [`a64-loadcheck.sh`](baremetal/a64-loadcheck.sh). | The Cortex-M7 back end | [`tests/baremetal/m7-encode.sh`](baremetal/m7-encode.sh) compares the encoder with the GNU Arm assembler, [`m7-cosim.sh`](baremetal/m7-cosim.sh) co-simulates the model with QEMU's Cortex-M7, and [`m7-image.sh`](baremetal/m7-image.sh) has the kernel check the code images and their step theorems. ## Builds, inputs, and outputs

Run commands from the repository root.  Lean and Lake commands use `tools/leanrun`, and the
repository test drivers call that runner themselves.
[The repository instructions](../AGENTS.md#lean-process-limits) and [the manual's section on
memory-heavy numerical proofs](../docs/verified-manual.md#memory-heavy-numerical-proofs) give the
required memory settings and build order.  The full numerical suite can take hours.

The [verified module registry](verified/modules.txt) identifies the source module, module
constant, and emitted name.  [The numerical registry](verified/numerics.txt) names the
emitted module, its byte-theorem module, and its file-theorem module.  The file checks run after
emission because elaboration reads the generated file.  The file theorems state that the file's
bytes equal the expected encoding and decode to the module.  [Shared test support](TestSupport)
holds case generators, result formatting, and numerical reference calculations.

Default output directories are under `build/`.  The native execution drivers recreate
`build/native/run/` and `build/native/verified/`.  The verified driver adds to `build/verified/`
without clearing it, records its passing checks in `build/verified-checks/`, and its byte check
writes `build/byte-check/verified/`.  A fast build writes the package's modules to
`.lake/build-fast/`, as [the manual's section on fast builds](../docs/verified-manual.md#fast-builds)
explains.  `tests/verified/run.sh --check-bytes DIR` reads reference modules from `DIR`, writes
fresh emissions to `build/byte-check/verified/`, and fails at the first module whose bytes differ,
and it leaves `build/verified/` unchanged.

The native tests require CompCert 3.18's `ccomp` and `clightgen` from one tree configured for the
target, which `CCOMP` and `CLIGHTGEN` name when they are not on the search path, and
`CCOMP_STDLIB` names the run-time library of a tree that is not installed.  The bare-metal drivers
need `qemu-system-aarch64` or `qemu-system-arm`, and the Wasmtime, WebGPU, and CUDA tests use the
hosts that [the host tools](../tools/README.md#execution-hosts) build in `build/tools/`.  The
Python scripts carry PEP 723 metadata and run with `uv run`, which installs the pinned
dependencies that a script names.  Each script's header states its checks, its options, and the
tools that it needs.

[The full check](../docs/verified-manual.md#the-full-check) runs, after the build and
`tests/verified/AllAxioms.lean`, `tests/verified/run.sh` with `tests/drone/run.sh` and
`tests/modules/chunks.py`, `tests/native/verified.sh` with and without `--aligned`, `aligned.sh`,
`run.sh`, `bytes.sh`, `clight.sh`, and `clight-rocq.sh`, `tests/wasi/run.sh` and `sys-run.sh`, the
drivers of the random-residue histogram, the random choice, and the manifest checker with the
runners that the host supports, `tests/linux/sys-run.sh`, `a64-elf.sh`, `a64-wasi.sh`,
`a64-wasi-clocks.sh`, `a64-wasi-preopen.sh`, and `a64-wasi-files.sh` on an AArch64 Linux host,
`tests/baremetal/run.sh`, `programs.sh`, `inputs.sh`, `ctl.sh`, `verified.sh`, `a64-images.sh`,
and `a64-uart.sh` under TCG, `tests/isla/theorems.sh` and `m7-theorems.sh`, `tests/wgsl/run.sh`,
`tests/gpt32/native.sh` on its default devices, `tests/talos/run.sh`, the hash functions' vector
checks, `tests/regex/run.sh`, `tests/orderbook/run.sh`, `tests/conjunction/run.sh`,
`tests/sgp4/run.sh`, the knowledge base's `VKB/Check.lean`, `rocq/check.sh`,
`clightn/check.sh --mutations`, and the documentation and layout checks, with the drivers that
those drivers call.  It leaves out `tests/native/subset.sh`, whose result is the count of modules
without a translation that `tests/native/verified.sh` reports, `tests/native/bench.sh`, which
measures time, the decoder test, which needs the WebAssembly testsuite converted by
`wasm-tools`, and the bare-metal runs under KVM.  It also leaves out
`tests/baremetal/a64-rcv.sh`, which needs the RCV corpus and a memory limit of 48G, the
regeneration of the Isla traces by `tests/isla/traces.sh`, `linux-traces.sh`, and
`m7-traces.sh`, which needs the patched Isla, the IR of the Sail model, and Z3, and the
Cortex-M7 drivers of the board, of Renode, and of QEMU's mps2-an500 machine,
`tests/baremetal/m7-board.sh`, `usart3.sh`, `m7.sh`, `req.sh`, `m7-qemu.sh`, and `m7-cosim.sh`.
The other drivers of the table run only when a person runs them.

## Documentation tests

```sh
tools/check-doc-links.mjs
node tools/check-doc-links.test.mjs
```

The checker reads Git's tracked and unignored untracked file inventory, so the checker covers new
documentation before staging.  Ignored build outputs cannot satisfy a missing repository link.  The
tests use temporary documents to check parsing, path membership, anchors, and traversal, including
an isolated group of documents that link to one another.
