RCV Recount

This page recounts a ranked-choice contest from a canonical ballot file on this computer, under Oakland City Charter §1105 with the Oakland module or under 21-A M.R.S. §723-A and 29-250 C.M.R. ch. 535 with the Maine module. The browser reads the file with the File API and sends nothing to the server. The page calls the export tabulate of the chosen module, which the verified compiler produced from Demos/Rcv/TabulateProgram.lean or Demos/Rcv/Maine/TabulateProgram.lean, and shows the report that the module returns. tests/rcv/convert.py writes the canonical file of an Oakland contest from D. Otis's CSV cast vote record, and tests/rcv/maine/convert.py that of a Maine contest from the Secretary of State's spreadsheets.

The page's bound for a file of L bytes is the module's bound in the table above,

The page's JavaScript, tabulate.js and app.js, lies outside the
theorems and is trusted to establish the premises and to read the result.  For each file it
creates a fresh instance of the chosen module, whose store the generated
compiled.initial and Verified.Ready.initial prove ready in Talos's
semantics.  It checks that the sum of the memory's size, 48 bytes, the file's block, and the bound
is at most the cap of 65,535 pages, since top lies inside the memory and
alloc raises it by at most 48 bytes and the block.  Before the call it grows the memory
by the 48 bytes, the block, and the bound, so that neither alloc nor
tabulate grows it, and it refuses the file when the check fails or the browser refuses
the memory.  It then calls alloc with the file's length, writes the file's bytes into
the block, passes the root and the length to tabulate, and copies the bytes at the
returned root and length.  The browser's WebAssembly engine is trusted to agree with Talos's
semantics, and its File API to give the file's bytes.  The text above decodes the report as UTF-8,
and the download holds its bytes unchanged.
