# Checked dynamic array traversal input

Use `FixedArrayTraversalInput.dynamicProgram_spec` when the goal begins at the standard dynamic `Array UInt64` element-address calculation and load.  The theorem accepts annotation-selected array, index, and item locals, together with the represented input and an in-bounds logical index.  It proves the generated modulo-address bound and memory read once, then reaches an arbitrary continuation with the loaded element stored in the item local.

Use `FixedArrayTraversalInput.continuingProgram_spec` at the beginning of a continuing array-loop step.  This form executes the unsigned `index ≥ effectiveStop` guard and its false `br_if 1` path before applying the dynamic loader theorem.  Use `continuingProgram_exit_spec` when the index and effective-stop getters are equal: it proves the true guard edge through `Break 1` while keeping the caller's result suffix folded.  Rewrite the nested interval with the generated `<region>_continuing_eq`, whose checked local arguments identify the exact `continuingProgram arrayLocal indexLocal stopLocal itemLocal` instance.

When the recipe supplies `<region>_continuing_spec`, prefer that generated theorem in the continuing branch.  Its frame definition fixes the compiler-selected array, index, stop, and item locals, and its checked item-validity proof removes the structural premises of `continuingProgram_spec`.  The artifact proof supplies only the encoded-index equality, continuing inequality, represented input, logical index bound, and dependent continuation.

Keep the caller's semantic loop frame in the invariant and let the generated theorem infer its local-value parameters from the current goal.  Rewrite only the program prefix to `<region>_continuing_program`, apply `<region>_continuing_spec`, and name a local value only if inference leaves a specific ambiguity.  Rebuilding the invariant around the generated 21-value frame repeats the complete local vector in later evaluator and invariant goals, defeating the adapter's compact application boundary.

After applying `continuingProgram_spec`, use `Frame.internal_getElem?_of_get` or `internal_getElem_of_get` to derive the internal-list facts requested by a dependent continuation from the invariant's `Wasm.Locals.get` equations.  Supply the parameter count, internal-index bound, and combined getter instead of unfolding `Locals.get` and applying `List.getElem?_eq_getElem` at each live local.  Keep `UInt64.ofNat_add` and the `toUInt32` addition rules in the proof kit's simplifier orientation, because adding reverse equations for either form creates simplifier cycles.

Supply the dependent premises of `continuingProgram_spec` by name when its continuation mentions the loaded frame.  In particular, name `hValues`, the three local getters, `hIndexValue`, `hContinue`, `hItem`, `hInput`, and `hIndex`, then leave `hNext` as the sole residual goal.  Positional tactic bullets can shift when Lean infers `hItem` or a getter from the target, producing diagnostics against later premises rather than the intended one.

`FixedArrayTraversalInput.program_spec` covers the older constant-index loader used by unrolled search nodes, and `FixedArrayEqNode` composes that theorem with equality branches.  The dynamic theorems assume the emitted one-word stride and forward address formula, so a reverse traversal or wider source slot needs a distinct checked program.  Keep the fold, map, filter, or search invariant in its semantic entry and use this entry only for the guard, load, and item-local transition.
