# Running GPT2/128 with the checked WGSL projection

The 128-position checkpoint now runs through the parent's Lean hidden
computation, the verified Wasm dispatch bridge, the checked WGSL vocabulary
projection, and the verified Wasm bias addition. The WebGPU backend is the
existing server-side CPU runtime.

A separate [native/browser artifact demo](gpt128-demo.md) now runs the transformer
in generated Wasm. Its complete Wasm proof remains unfinished; the user
authorized this execution demonstration with that limitation.

This is the small model with 128 **byte-token positions**, width four, two
attention heads, one block, and 2,984 parameters. It accepts any nonempty prefix
of at most 128 bytes and produces 256 next-byte logits. The parameter layout
places the 4×256 head matrix at word 1,680 and its biases at word 2,704.

From the configured repository root:

```sh
source tools/macos-env.sh # configured ARM Mac only
tools/artifact-proof.js wgsl-gpt128-run data/tiny-gpt2-128-v1/checkpoint.json --text "To be, or not to be"
tools/artifact-proof.js wgsl-gpt128-run data/tiny-gpt2-128-v1/checkpoint.json --bound 0.5 --tokens 84 111 32 98
tools/artifact-proof.js wgsl-gpt128-corpus build/wgsl/my-gpt128-corpus
```

The corpus destination must be fresh. Text is encoded as UTF-8; the limit is
128 bytes, not 128 Unicode characters. The default weight bound is ten.
The parent `F64Clip.prepare` rejects nonfinite parameters and clips finite
weights to the caller's bound in [0,10]. The shipped checkpoint's maximum
parameter magnitude is about 2.312, so the default does not change it.

Each invocation reports its evidence directory. The JSON report contains all
output words, the eight highest logits and their byte tokens, runtime identity,
checkpoint/parameter hashes, and the execution and verification boundaries.
The model is small; these results demonstrate execution and correspondence,
not strong language-model quality. Token sampling is not implemented by this
command.

## What is proved and what executes

| Stage | Execution | Formal statement |
|---|---|---|
| Hidden row | `TinyGpt2Seq.hidden` evaluated directly in Lean | The parent source is the computation; no hidden-Wasm execution claim |
| Vocabulary projection | Parsed WGSL through the proved Wasm bridge | Exact binary32 result under the declared profile and transfer/runtime premises |
| Bias addition | Existing finish Wasm | Exact binary64 result, decoding, validation, termination, and memory preservation |

[`TinyGpt2Seq.Mixed`](../../proofs/talos/lean/Project/TinyGpt2Seq/Mixed.lean)
names the mixed-precision Lean function separately from the parent's all-binary64
inference function. It reuses the same sequence hidden computation, then uses
four separate binary32 multiply/add updates from positive zero, promotion, and
binary64 bias addition. Its checked entry retains the parent's input validation
and parameter preparation policy. `checked_word` connects accepted checked
inference to each output word.

[`GptSequence.completes`](../../proofs/talos/lean/Project/WGSL/GptSequence.lean)
proves the bridge, shader and finish behavior given that hidden row. The theorem
is generic in runtime parameters and token arrays; the executable entry enforces
the model's 1–128-byte domain. The independent package checker binds the theorem
to the actual shader source, profile, manifest and Wasm bytes. All public proof
audits accept only the standard logical axioms. No real-valued error allowance
is needed for exact equality with the mixed function.

The declared profile fixes nearest/even binary32 rounding, preserved subnormals,
IEEE zero signs, source order, and separate multiply/add. Native runtime
conformance and data transfer remain assumptions. The harness uploads the
binary32 words computed by Lean and separately checks native binary32-to-binary64
promotion before invoking the finish artifact.

The complete parent GPT2/128 hidden-Wasm execution proof is unfinished. This
path does not execute that Wasm. Receipts explicitly record
`hiddenWasmExecuted: false` and `completePipelineArtifactProof: false`.
Native Lean evaluation is an execution boundary; the projection theorem is not
a proof of the entire native Lean runtime. All Wasm artifacts actually used by
this path have the existing checked artifact theorems.

## Focused validation

Seven cases cover lengths 1, 4, 64 and 128; full-length zero and 255 contexts;
and a run with bound 0.5 that exercises clipping. All 1,792 raw binary32 head
words and 1,792 final binary64 logits match the Lean mixed function. The four
invalid token-domain cases are rejected by the driver. The checker requires
every expected reference field, so missing raw-head evidence cannot silently
skip that comparison.

Reports also compare the mixed output with the parent's binary64 head on the
same computed hidden row. That difference is an observed comparison for the
given input, not a proved uniform bound. The mixed result is not claimed to be
bit-identical to all-binary64 GPT2/128 inference.

The parent updates merged for this work are 2f4e024a (sequence sum/maximum
execution) and bd6f58dc (sequence map execution and shared allocation lemmas).
They advance the full-Wasm proof separately from this runnable WGSL path.

The [retained evidence](../../test/wgsl/gpt128) also includes a readable
128-byte prompt ending “outrageous fortune.” All 256 head and final result words
match Lean; its highest-scoring next byte is space. Across the corpus and this
demonstration, 2,048 head words and 2,048 final logits match exactly.
