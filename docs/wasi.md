# Verified WASI Manual

`verified_compile_wasi` compiles Lean actions to core WebAssembly with WASI Preview 1 imports for stdin reads, stdout and stderr writes, and exit.  The generated proofs relate execution of the exported functions to the original Lean actions, including their ordered I/O effects, returned values, and terminal outcomes.  [The verified compiler manual](verified-manual.md) describes the pure dialect used inside actions.  [The WASI design](verified-wasi-design.md) records the API and proof decisions.  The interface follows the pinned [Preview 1 declarations](https://github.com/WebAssembly/WASI/blob/fae981bae14809d91f9bc2d63852d461f331d161/preview1/witx/wasi_snapshot_preview1.witx), [type definitions](https://github.com/WebAssembly/WASI/blob/fae981bae14809d91f9bc2d63852d461f331d161/preview1/witx/typenames.witx), and [application ABI](https://github.com/WebAssembly/WASI/blob/fae981bae14809d91f9bc2d63852d461f331d161/application-abi.md).

## Writing actions

### Operations and results

`import LeanExe.Wasi` provides the compiler-independent API and native interpreter.  `import Verified.Wasi` also provides `verified_compile_wasi`.  The API is in `LeanExe.Wasi` and uses `LeanExe.Bytes` for packed bytes.

| Operation | Type | Behavior |
|---|---|---|
| `readSome capacity` | `UInt64 → Action ReadResult` | Calls `fd_read` once when `capacity < 2^32`, after any required allocation succeeds. |
| `readAll limit` | `UInt64 → Action ReadResult` | Calls `fd_read` with capacity 4,096 until a read returns an errno or no bytes, or until more than `limit` bytes are held, after allocating one buffer of `limit + 4096` bytes. |
| `writeStdoutSome bytes` | `Bytes → Action WriteResult` | Calls `fd_write` once for stdout. |
| `writeStderrSome bytes` | `Bytes → Action WriteResult` | Calls `fd_write` once for stderr. |
| `exit code` | `UInt64 → Action α` | Requests terminal exit with `code mod 2^32`. |
| `loop count init test step` | `UInt64 → σ → (UInt64 → σ → Bool) → (UInt64 → σ → Action σ) → Action σ` | Runs a bounded sequence of effectful steps. |

These call counts describe the compiled guest's WASI import invocations.  A host may use several operating-system calls for one import.  [The native interpreter](#native-interpreter) executes the same action API through its own host adapter.

[The result definitions](../LeanExe/Wasi/Action.lean) give `ReadResult` the fields `errno : UInt64` and `bytes : Bytes`, and `WriteResult` the fields `errno : UInt64` and `count : UInt64`.  Zero errno means success.  A successful read may return fewer bytes than requested, and a successful write may report any count from zero through the supplied length.  The operations perform no retries.  Stream hosts report EOF through empty success.  A zero-capacity read still invokes the host once, so its empty result supplies no EOF evidence.  The abstract host relation has no separate EOF state.

A read capacity of at least `2^32` returns errno 61 and empty bytes before allocation or host invocation.  A nonzero read errno returns empty bytes, and a nonzero write errno returns count zero.  The host model records committed prefixes on error or trap, so these public results do not prove zero device progress.  Returned errnos are bounded by the Preview 1 errno range, 0 through 76.

`readAll limit` reads the whole standard input into one byte string for a program that needs all of its input before it computes.  [Its definition](../LeanExe/Wasi/ReadAll.lean) is a `loop` of `limit + 2` passes, each a `readSome 4096` whose bytes the loop appends to the bytes held, so `Exec`, `Prefix`, and the native interpreter give it the meaning of those reads.  A read that returns an errno ends the loop with that errno and the bytes read before it, a read that returns no bytes ends it with errno 0, and a read that brings the bytes above `limit` ends it with errno 0 and those bytes, so the result exceeds `limit` only when the input does, and then by less than 4,096 bytes.  Each pass that continues adds a byte, so the passes always suffice.  A limit of `2^32 - 4096` or more returns errno 61 and empty bytes before any allocation or read.  The compiled code allocates one buffer of `limit + 4096` bytes and gives each read the buffer's unused tail as its iovec, so the host writes each reply in place and no byte is copied.  Its allocation charge is `Bytes.allocationCost (limit + 4096)`, which depends on the limit alone, and every read has capacity 4,096.

Actions use ordinary Lean `do` notation:

```lean
import Verified.Wasi

namespace StdioExample
open LeanExe LeanExe.Wasi

def copySome (capacity : UInt64) : Action UInt64 := do
  let input ← readSome capacity
  if input.errno != 0 then
    pure input.errno
  else
    let output ← writeStdoutSome input.bytes
    pure output.errno

def main : Action UInt64 := copySome 4096

verified_compile_wasi callable := [copySome, main]
verified_compile_wasi command (main := main) := [copySome, main]
end StdioExample
```

[The stdio example](../Verified/Examples/WasiStdio.lean) makes at most one read and one write.  It returns the write's errno even when the host reports a short successful write.  A complete stream copy requires an explicit loop and handling of short transfers.

`Action` describes effects and their continuations.  `let action := readSome n` binds a description.  Each `let result ← action` executes it once, so sequencing the same description twice makes two reads.  Reflection constructs typed code and its correspondence proof without executing guest I/O.  Native execution constructs and interprets continuations as the action runs.

### Packed bytes

| Expression | Meaning |
|---|---|
| `Bytes.empty` | Empty bytes. |
| `bytes.size` | Length as `UInt64`. |
| `bytes.get index` | Byte as `UInt64`, or zero outside the buffer. |
| `Bytes.build count element` | `count` bytes, with the low eight bits of `element index` at each index. |
| `bytes![0, 65, 255]` | Packed literal.  Each numeral must lie between 0 and 255. |

[The byte dialect](../LeanExe/Dialect/Bytes.lean) wraps a native `ByteArray`.  Compiled byte values occupy two `i64` words: the payload address and logical length.  The representation requires a length below `2^32`.  A compiled builder requesting at least `2^32` bytes takes a guest resource trap.  `Bytes.build` evaluates its pure callback in index order, with a `UInt64` index.

Nonempty literals have deduplicated raw data in the module's static pool, after its constant word arrays.  Each literal evaluation makes an owned copy, including evaluations inside pure helpers, builders, branches, and loops.  Empty literals and empty builders return canonical empty values without allocation.  These byte operations are also part of the pure verified compiler.

Ownership follows the pure compiler's rules.  Writes borrow their buffer.  Reads return owned bytes.  Passing bytes to an owned parameter or returning owned bytes transfers ownership, while returning borrowed bytes makes a copy.  Cleanup releases an unused owned allocation after its last use.  An empty argument may have a nonzero allocated root.  Cleanup tests the root, and borrowed representations protect the allocation's header and capacity even when its logical length is zero.  [The byte representation](../LeanExe/Pipeline/Bytes.lean) states these memory requirements.

### Control and helper functions

An action may return `Unit` or a value accepted by the pure dialect.  Structures use the same `Flat` representation as pure functions.  Pure expressions, `let` bindings, action bindings, conditionals, and calls to listed helpers compose inside actions.  An unlisted `@[inline]` helper unfolds at its use.  A dependent conditional is accepted when its branches do not use the proof of the condition.

`LeanExe.Wasi.loop count init test step` starts with index zero and state `init`.  At each index below `count`, it evaluates the pure `test index state`.  False returns the current state.  True executes `step index state`, takes its returned state, and increments the index.  Reaching `count` returns the state without another test.  Count zero skips both callbacks.  Exit or host trap in a step terminates the whole action.  Outer values captured by callbacks remain borrowed across iterations.

Effectful helper calls are acyclic.  Recursive effectful definitions are rejected.  Pure helpers retain the verified compiler's recursion and tail-loop rules.  General `IO` and `BaseIO` operations, arbitrary monadic recursion, and action values stored in runtime containers are outside the reflected dialect.

### Processes without an iteration bound

`Process σ` contains an initial state and `step : σ → Action (ProcessStep σ)`.  A step returns a `running` flag, a `UInt64` status, and its next state.  False ends the process with that status.  True continues with the returned state.  Exit or host trap terminates the process.  `process.runFrom host state` and `process.runStdio` interpret these steps natively.

The [typed process entry](../Verified/Wasi/ProcessCode.lean) composes separately compiled begin and step functions into a `_start` loop.  Begin returns the initial control flag, status, and owned state.  Step borrows the current state and returns its replacement.  After begin and after each completed step, the loop compacts the state: it copies the state above the heap's top and moves the copy down to the heap's base, the heap top when `_start` began, so between steps the heap holds the literal pool and one state.  The process theorems take `entry.state.compactable = true`, which holds for states built from scalars, arrays, byte strings, and pairs of them and fails for trees, and an initial heap with an empty free list.  A normally stopped process passes its status to `proc_exit`.  Begin and step take no hidden constant tables, so a program whose effectful functions use constant arrays cannot form a process entry.  [Running sum](../Demos/RunningSum/README.md) uses this API to read through EOF, retain partial lines, and finish short writes.

[Process refinement](../Verified/Wasi/ProcessCorrect.lean) classifies every target run that completes without exhausting Talos fuel.  The result preserves completed native steps, terminal outcomes, and pending action prefixes after guest resource failure.  [The total-process theorem](../Verified/Wasi/ProcessTotalCorrect.lean) proves eventual accepted exit when an application supplies a well-founded progress relation, bounded helper proofs, and final-exit acceptance, together with cost conditions on single steps.  A begin charge and a step charge bound the typed resource prefixes of begin and of the step from each represented running state.  The heap must have free memory above its base for each charge together with the copies of the state before and after it.  Because the loop compacts the state, these conditions concern one step at a time.  The theorem requires begin and every step to return normally, so a process that may exit or take a host trap inside a step stops only through its running flag under this theorem.

[Running sum's integer theorem](../Demos/RunningSum/Correct.lean) proves canonical decimal output for the cumulative sum at each line before the first line that is not a decimal integer, and eventual accepted exit with status 0 when every line is one and 28 otherwise.  Its [stream-host assumptions](../Demos/StreamFold/StreamHost.lean) require successful I/O, input-prefix consumption, EOF, committed output prefixes, and a decreasing proof-only counter for zero-byte writes.  Independent [input bounds](../Demos/RunningSum/Model.lean) constrain each line's length and the digit count of each prefix sum of valid lines.  Limits on the bytes of each line and the digits of each total, `InputLimits L D`, and one inequality between the memory cap and `220 · (L + D) + 1,010,000` bytes above the literal pool replace the cost conditions, which the application proves from the generated bounds of its pure functions.  A corollary fixes both limits at 9,000,000.  `ExitAccepted` supplies the final-exit premise.  The [application guide](../Demos/RunningSum/README.md) states the exact scope.

[The floating-point running sum](../Demos/RunningSumFp/README.md) uses the same stream protocol with a binary64 total starting at positive zero.  Its [arithmetic proof](../Demos/RunningSumFp/ArithmeticProof.lean) uses the existing general float parser, IEEE-754 addition, and shortest scientific printer.  [Its compiled theorem](../Demos/RunningSumFp/Correct.lean) requires fewer than `2^32` bytes per line.  It proves the printed sequential totals of the lines before the first line that denotes no number, and accepted exit with status 0 or 28, under host progress and final-exit acceptance.  A limit on the bytes of each line up to and including the first line that denotes no number, `InputLimits L`, and one inequality between the memory cap and `80 · L + 64,031,000` bytes above the heap's base replace the cost conditions, which the application proves from the generated bounds of the parser, the printer, and its effect bodies.  A corollary fixes the limit at 50,000,000.  Both applications use [the shared stream proofs](../Demos/StreamFold/README.md).

[The order book's process](../Demos/OrderBook/Process.lean) runs [the order book](../Demos/OrderBook/README.md) over stdin and stdout with StreamFold's host assumptions and its own framing.  It reads little-endian 64-bit words, passes the whole seven-word records of the carry and each 4,096-byte read to one call of the program's `run`, and writes the event words in the same form.  [Its compiled theorem](../Demos/OrderBook/ProcessCompiledCorrect.lean) proves that `_start` writes exactly the little-endian bytes of the specification's event words on the whole words of the input and exits with status 0 when the input is a whole number of words and 28 otherwise, under host progress, final-exit acceptance, and the requirements' bound of fewer than 2^64 − 1 records.  Its states have constant size bounds, so the memory condition is one closed inequality that the proof decides, 3,456,119,748 bytes above the literal pool for two copies of a state and a step's charge, and the theorem has no memory premise.  The charge of a read step holds for every reply, so it bounds `run` on any batch of 74 records from any book of the program's array sizes, by [the closed form of its bound](../Demos/OrderBook/Bound.lean) and a count of events over the program itself.  The state's 13 fields make the elaborator's conversion of a call's arguments in the effect bodies exponential in their depth, so [its charges](../Demos/OrderBook/ProcessCharges.lean) evaluate the destructured environment with a simproc and read the pure program's flags from a lemma that the kernel decides.

### Flat Preview 1 calls

`LeanExe.Wasi` provides typed functions for the functions of `wasi_snapshot_preview1` except `proc_exit`, which the stream functions serve, and `sock_recv` and `sock_send`, which have no description: the flat functions, whose parameters are words, strings, buffers, result words, records, and reported regions, and the nested ones, `fd_read`, `fd_write`, `fd_pread`, `fd_pwrite`, and `poll_oneoff`, which pass arrays of records in memory (section "Nested calls").  Each function has a typed function of its own, except `args_get` and `environ_get`, which `args` and `environ` call after their reporters, `path_open` and `fd_close`, which only `withOpen` calls (section "Handles"), and `fd_renumber`, which no program calls.  The typed functions share one action, `Action.sys call args next`.  A call is a description in [the call table](../LeanExe/Wasi/CallTable.lean): its import name, the core form of each parameter, and the call whose reply gives the sizes of the regions it writes.  `tools/wasi-calls.py` generates the call table, [the typed functions](../LeanExe/Wasi/SysCalls.lean), [their reflection equations](../Verified/Wasi/ReflectSysCalls.lean), and the frame test `tests/wasi/sys/frame-all.wat` from the witx of WebAssembly/WASI commit `fae981bae14809d91f9bc2d63852d461f331d161`, kept in `tests/wasi/witx/`.  Its check fails when a committed file differs from its output, and [an independent lowering](../tests/wasi/witx-lowering.py) compares the parameter forms, record layouts, and reporters of the call table with its own reading of the witx.

A typed function takes each descriptor as a `Handle`, each word, enum, and flags argument as `UInt64`, each string as `Bytes`, and the capacity of an output buffer as `UInt64`.  It returns the errno for a function without results, `WordResult` for one result word, `ArgsSizes` for the two result words of `environ_sizes_get`, `BytesResult` for an output buffer, and `BytesCountResult` for an output buffer and the count of bytes that the call wrote into it (`fd_readdir` and `path_readlink`).  `BytesCountResult` holds the whole buffer, of which the call wrote the first `count` bytes.  A function that writes a record returns `FdstatResult`, `FilestatResult`, or `PrestatResult`: the errno and each field of the record as a `UInt64`, named after the witx field.  `Action.run` and the compiled code reject an argument before the call, without a host request, by the first rule that applies in parameter order:

| Parameter | Rejected argument | Errno |
|---|---|---|
| 32-bit word or descriptor | `2^32` or more | 61 (`overflow`) |
| Enum of `n` values | `n` or more | 28 (`inval`) |
| 32-bit flags | `2^32` or more, or a bit outside the type's flags | 61, or 28 |
| 64-bit flags | A bit outside the type's flags | 28 |
| String | A length of `2^32` or more | 61 |
| Output buffer | A capacity of `2^32` or more | 61 |

Wasmtime 44 traps on an enum or flags value outside its type before the function runs, and the rejection keeps such values from reaching it.  `args` and `environ` call a reporter and then the reported call, and they are written by hand, as are `clockTimeGet`, `randomGet`, and `argsSizesGet`.

| Function | Type | Behavior |
|---|---|---|
| `clockTimeGet id precision` | `UInt64 → UInt64 → Action ClockResult` | Calls `clock_time_get`. |
| `randomGet length` | `UInt64 → Action RandomResult` | Calls `random_get` into a fresh buffer of `length` bytes. |
| `argsSizesGet` | `Action ArgsSizes` | Calls `args_sizes_get`. |
| `args` | `Action ArgsResult` | Calls `args_sizes_get` and then `args_get` into one buffer.  An errno of the first call ends the operation with that errno, and sizes whose buffer would reach `2^32` bytes give errno 61. |
| `environ` | `Action ArgsResult` | Calls `environ_sizes_get` and then `environ_get`, by the rules of `args`. |

The native interpreter serves `clock_time_get`, `random_get`, `args_sizes_get`, and `args_get` through `NativeHost.withSys`, from the system clock, the system's random bytes, and the given arguments, and it traps on the other calls.  The Wasmtime host passes arguments with `--arg` and environment variables with `--env NAME=VALUE`, and it preopens one directory as `.` with `--dir PATH`.  The native interpreter requires a call's outputs to have the sizes that its description and arguments give, and a reported region the size that the last successful reply of its reporter in the same run gives, and it raises an `IO.Error` otherwise.  In the verified compiler, a module imports the three stream functions and then the calls that its program uses, so every defined function moves by the number of calls; each layout definition and theorem has a form over the list of imported calls, and the forms at the empty list are the definitions and theorems of the stream-only layout.

`Command.sys call form args inputs` compiles a call with the word variables `args` and the byte variables `inputs`, which the host reads.  The command borrows each input and releases an owned input that is not live after it.  The flat form serves a call with at most one output buffer and at most two result words, the record form a call whose last parameter is a record, the reported form `args_get` and `environ_get`, the iovec forms the reads and writes of the section "Nested calls", and the poll form `poll_oneoff`.  The record form allocates a block of the record's size plus its alignment less one, passes the block's address rounded up to the alignment, loads each field into a result word when the errno is 0, and releases the block.  `command_sys_spec_with` and `cost_command_sys_spec_with` prove its code against the host contract `sysContract`, whose frame is the request's output regions.

`verified_compile_wasi` reflects each typed function, `args`, and `environ` to one `Command.sys` command, whose result is the `Flat` form of the result structure: `(errno, value)` for `WordResult`, `(errno, bytes)` for `BytesResult`, `(errno, count, bytes)` for `BytesCountResult`, the errno and the fields in order for a record, and `(errno, count, size, bytes)` for `ArgsResult`.  An argument that is not a variable is bound first, and an `Action.sys` term written directly is rejected, so a program reaches `args_get` only through `args`.  A program with `sys` commands compiles with `compileCalls p.sysCalls`, and its generated theorems are the general forms at `p.sysCalls`; a program without them keeps the module and the theorems of the stream-only layout.  [The flat call example](../Verified/Examples/WasiSys.lean) writes its arguments, their count and size, readings of the realtime and monotonic clocks, and 16 random bytes.  [The input example](../Verified/Examples/WasiSysInputs.lean) creates and removes a directory in the preopened directory, [the record example](../Verified/Examples/WasiSysRecords.lean) writes the fields of the records of the preopened directory and of a file that it opens there with `withOpen`, and [the environment example](../Verified/Examples/WasiSysEnviron.lean) writes the count, size, and bytes that `environ` returns, and [the nested example](../Verified/Examples/WasiSysNested.lean) writes a file with `fdWrite` and `fdPwrite` in a bracket, reads it back with `fdPread` and `fdRead`, and polls the clock and the file.

### Handles

A descriptor is a `Handle`, a structure with one field, the descriptor as a word.  A program reaches two kinds of handles: `Handle.preopened`, descriptor 3, the directory that the Wasmtime host preopens with `--dir`, and the handle that `withOpen dir dirflags path oflags rightsBase rightsInheriting fdflags onError body` binds.  `withOpen` calls `path_open` for `path` under `dir`, and its result has type `α × UInt64`.  On a nonzero errno it runs `onError errno` and returns the result of `onError` with 0.  Otherwise it runs `body` with the new handle, and when the body returns it calls `fd_close` on the handle and returns the body's result with the errno of `fd_close`.  `verified_compile_wasi` requires a source type for `α`, so it refuses a body that returns `Unit`.  A body that exits or traps ends the process with the descriptor open, and Wasmtime closes it at exit.  `path_open`, `fd_close`, and `fd_renumber` have no typed function, and the check below refuses every handle argument other than a bracket's handle and 3, so descriptors 0, 1, and 2 stay reachable only through the stream functions as long as no bracket receives one of them, which the host assumption `FreshOpens` below excludes.  The descriptions mark each descriptor parameter as `.handle`, which is lowered and rejected as a 32-bit word.

`verified_compile_wasi` reflects `withOpen` as a fixed shape of the existing commands, which the docstring of `withOpen` gives: the `path_open` call, a test of its errno, on failure the error continuation followed by its result paired with 0, and on success the body followed by the `fd_close` call and the body's result paired with the close's errno.  `Command.HandleCheck` ([the handle check](../Verified/Wasi/HandleCheck.lean)) refuses a call that is not one of the generated descriptions of `Call.table`, a `path_open`, `fd_close`, or `fd_renumber` call outside this shape, an argument of a `.handle` position that is not a marked variable, and a call of an effect helper whose argument for a `Handle` parameter is not a marked variable.  The marked variables are the handles that brackets bind, the variables bound to the literal 3, and the `Handle` parameters of the helper being checked.  Since every call must be a generated description, the check reads each call's `.handle` positions from the witx, whatever source produced the command.  For each program, `verified_compile_wasi` decides the check in the kernel (`p.handlesChecked`) and states `p.handles`, or `p.f.handles` for each export of a program without `main`.  A callable export takes and returns no `Handle`.

`p.handles` states `Action.BracketRuns` of `main` ([the bracket discipline](../LeanExe/Wasi/Bracket.lean)): every `Exec` run and every `Prefix` run of `main` satisfies `WellBracketed [] trace stack`, with `stack = []` when the run returns normally.  `WellBracketed` reads the trace with a stack of descriptor numbers, the open brackets with the innermost first.  Every event's call is a description of `Call.table`.  A `path_open` event that returns errno 0 pushes the number it returns, an `fd_close` event pops the top, which must be its argument, no `fd_renumber` event occurs, and every other call takes 3 or a number on the stack at each `.handle` position.  Every use of a handle therefore lies between its open and its close.  A trace has no event at a bracket's return, so `withOpen_closes` ([the handle theorems](../Verified/Wasi/Handles.lean)) states the events and the result of each run of `withOpen` that returns normally.  When `Call.reject` rejects the arguments of `path_open`, the open makes no event, the trace is that of a run of `onError` on the rejection's errno, well bracketed from the stack back to the same stack, and the returned errno is 0.  Otherwise the trace starts with the open event.  When the open returns errno 0 and descriptor `d`, the rest of the trace is that of a run of the body on `d`, well bracketed from `d` on top of the stack back to the same stack, followed by the bracket's close, an `fd_close` event of `d`, and the returned errno is that event's.  `WellBracketed` reads numbers, so the theorem leaves open another close of `d` among the body's events: the close of a nested bracket whose open received `d` again, which `FreshOpens` below excludes, or a close of `d` in the body followed by an open that the host numbers `d`, which the check refuses.  When the open returns another errno, the rest is the trace of a run of `onError` on that errno, well bracketed from the stack back to the same stack, the bracket adds no close, and the returned errno is 0.  In each case the first component of the result is the result of that run of the body or of `onError`.  Its premises are what `Command.handles_exec` gives for the body and the error continuation of a checked bracket.  [The handle theorems](../Verified/Wasi/Handles.lean) `Command.handles_exec` and `Command.handles_prefix` give the discipline for every command that passes the check.

`Action.BracketRuns.exec_descriptors` reads the stack as the open descriptors of the trace.  Descriptors 0 to 3 are open before the first event, a `path_open` event that returns errno 0 opens its number, and an `fd_close` event closes its argument, whatever it returns.  For a host that never returns from `path_open` a number that is open (`FreshOpens`), as Wasmtime 44 asserts of every new descriptor, every `.handle` argument names an open descriptor other than 0, 1, and 2, every `fd_close` closes a descriptor that a bracket opened, and a normal return leaves open exactly descriptors 0 to 3.  Descriptor 3 is the preopened directory when the host is given `--dir`.  Without it, 3 is open only by this definition.  `WellBracketed` reads descriptor numbers, so a use of a closed bracket's handle inside a later bracket that receives the same number would be well bracketed.  The check excludes such a use, since a handle's variable is in scope only inside its bracket, and `Command.handles_exec` holds for every host, among them hosts that never reuse a number, under which such a use breaks the discipline.

### Nested calls

`fd_read`, `fd_pread`, `fd_write`, and `fd_pwrite` take an array of iovecs, each a buffer's address and length.  Wasmtime 44 reads into and writes from only the first non-empty element of the array, so the descriptions use arrays of one element (`Param.iovec`): the code writes the element into scratch bytes `[0, 8)` and passes its address and the length 1.  For a read, the element points to a fresh buffer of the requested capacity, a shown output; for a write, it points to the input bytes.  `poll_oneoff` takes an array of subscriptions, 48 bytes each, and an array of events, 32 bytes each.  Its descriptions (`Param.subscriptions`, one for each shape that a typed function uses) give each record's fields: a constant, such as the union's tag or the userdata, a word argument, or a handle argument, which the handle check treats as a `.handle` position.  The code allocates a block, aligns it to 8, zeroes the subscriptions, writes the fields, places the events after the subscriptions, and passes the number of records as the count.  A word field is rejected before the call only when it does not fit its width, since Wasmtime answers invalid contents of a subscription with errno 28.

| Function | Type | Behavior |
|---|---|---|
| `fdRead h capacity`, `fdPread h capacity offset` | `… → Action BytesResult` | Calls `fd_read` or `fd_pread` into a fresh buffer of `capacity` bytes.  The bytes are the prefix of the count that the call returns, clamped to the capacity. |
| `fdWrite h bytes`, `fdPwrite h bytes offset` | `… → Action WordResult` | Calls `fd_write` or `fd_pwrite` with `bytes`.  The value is the count written, which may be less than the length.  On a handle opened to append, Wasmtime 44 ignores the offset of `fd_pwrite` and writes at the end. |
| `pollClock clock timeout precision flags` | `… → Action PollResult` | Calls `poll_oneoff` with one clock subscription of userdata 1. |
| `pollRead h clock timeout`, `pollWrite h clock timeout` | `Handle → UInt64 → UInt64 → Action PollResult` | Calls `poll_oneoff` with a read or write subscription on `h` (userdata 1) and a clock subscription (userdata 2). |

`PollResult` holds the errno, the count of events, and the first event's userdata, error, type, `nbytes`, and flags.  Wasmtime writes the events of the ready subscriptions in subscription order, so the first event's userdata tells which subscription fired.  A read subscription on a file at its end, or on an empty file, is reported with `nbytes` 1 and the flag `fd_readwrite_hangup`, and a clock of timeout 0 fires before a file's readiness, so a poll with such a clock returns only the clock's event.  Wasmtime 44 charges each call a hostcall fuel of `2^27` bytes and answers a buffer of more than `2^27 − 8` bytes with errno 48, which limits the stream functions as well.  A module that calls `fdRead` or `fdWrite` imports `fd_read` or `fd_write` a second time, after the stream functions, with the contract of its description; Wasm admits a function imported twice, and the two contracts govern different import indices.

## Compilation and generated declarations

### Callable and command modules

The two command forms are:

```lean
verified_compile_wasi p := [pureHelper, actionHelper, action]
verified_compile_wasi p (main := main) := [pureHelper, actionHelper, main]
```

The compiler collects pure definitions first, preserving their relative order, then reflects effectful definitions in their relative order.  A pure helper's other listed pure callees must precede it among the pure definitions.  An effectful helper's listed effectful callees must precede it among the effectful definitions.  Pure helpers are available to every effectful definition.  The selected command `main` must appear among the effectful definitions and have type `Action UInt64` with no visible parameters.  Captured constant arrays become hidden borrowed table arguments.  The frontend rejects duplicate definitions, generated-name collisions within each of the pure and effectful groups, and callable names reserved by the runtime exports.  [The checked public examples](../Verified/Wasi/ReflectCommandCases.lean) include hidden tables, literals, byte ownership, records, computed call arguments, and both export forms.

Callable modules export each listed effectful definition under the last component of its Lean name.  They also export `alloc` and `release`, allocation counters `allocCount` and `freeCount`, linear memory `memory`, and the empty table `__indirect_function_table`.  Pure helpers compile internally.  Command modules export `_start : () → ()`, `memory`, and the empty table.  `_start` invokes the selected main, then passes a normally returned status to `proc_exit`.  An explicit exit in main or a helper terminates before that final exit.

The module imports three functions from `wasi_snapshot_preview1`, followed by the flat calls of `p.sysCalls` when its program uses them:

| Import | WebAssembly signature | Descriptor |
|---|---|---|
| `fd_read` | `(i32, i32, i32, i32) → i32` | 0: stdin. |
| `fd_write` | `(i32, i32, i32, i32) → i32` | 1: stdout, or 2: stderr. |
| `proc_exit` | `(i32) → ()` | None. |

[The ABI definitions](../Verified/Wasi/ABI.lean) reserve scratch bytes `[0,16)` for one iovec and transfer count.  The read wrapper checks capacity before narrowing it to 32 bits.  Heap and byte-representation premises prove that pointer and write-length narrowing preserves their values.  The module relocates pure calls by the number of imports and pure types by three positions, uses the shared allocator and release functions at the first two defined indices, which are 3 and 4 without flat calls, and passes a hidden depth through internal calls.  Public wrappers initialize depth to zero.  Effectful calls increment it, and guarded pure calls use the same depth.  Guarded calls enforce the depth limit of 1,000.

Pure functions that take the call depth retain the 32-position frame limit.  Acyclic effectful helpers may use larger frames when `p.stackFits` accepts the estimated whole-call-chain stack use.  [The stack check](../Verified/Wasi/Stack.lean) includes the existing 272,000-byte guarded-call allowance, pure-module frames, the three WASI wrapper frames, effectful helpers' excess over 32 positions, and exported entry frames, within 512 KiB.  It uses the existing estimate of eight bytes per position and sixteen bytes per frame.  The check does not formalize a real engine's native stack layout.  Engine stack behavior remains part of host validation and execution tests.

A callable host configures stdio before invoking an export and may invoke another export after normal return.  Exit and trap terminate the instance's lifecycle.  Command hosts invoke `_start` once.  The modules provide no `_initialize` hook, which the pinned application ABI permits to be absent.

## Execution proofs and their premises

### Results and traces

The exported-entry theorems quantify an initial store, host implementation, and native arguments.  They provide a fuel bound such that every modeled execution with at least that much fuel has one of the following classifications:

| Outcome | Proved relation |
|---|---|
| Normal return | Source execution returns the corresponding native value.  The machine words represent that value with owned result memory.  The allocator invariant and the caller's retained heap regions outside scratch are preserved. |
| Accepted exit or host trap | Source execution has the same terminal outcome, committed final world, and ordered I/O trace.  Accepted exit also has the designated exit marker and exact narrowed status. |
| Guest resource trap, when permitted | Source prefix has the same committed world and trace, with a residual action describing the remaining work. |

[The native result statement](../Verified/Wasi/NativeResult.lean) relates wrapper execution to native Lean actions.  [The command entry theorem](../Verified/Wasi/NativeCommand.lean) includes main's final exit.  Host relations may permit several replies.  Each sufficiently fueled target execution has a matching source execution or permitted source prefix with the same committed effects.

The target host state contains the abstract world and an append-only joint event journal.  Events record reads, requested writes and their committed counts, accepted exits, and rejected exit requests.  The final journal equals the initial journal followed by the source trace.  This preserves ordering even when stdout and stderr refer to the same host destination.  The world is proof and host state, separate from the source program's arguments.

### Resources, host assumptions, and total execution

| Premise | Requirement |
|---|---|
| Host implementation | Talos host satisfies `hostSpec host` for the three imports, including reply bounds, trace updates, terminal exit behavior, and guest-memory preservation.  Such a host exists when `host` answers every request, and only when it answers every request that the ABI expresses, as [the totality module](../Verified/Wasi/HostTotal.lean) proves.  A module with flat calls requires `hostSpecWith host p.sysCalls`, which adds `sysContract host call` for each call, and [the totality module for calls](../Verified/Wasi/HostTotalWith.lean) proves the same two facts for it. |
| Heap and arguments | `Heap.At`, correctly represented argument words, and separation of consumed blocks from retained and borrowed memory. |
| Static input | Literal pool's bytes and region exist and are disjoint from consumed blocks.  Hidden table arguments represent their declared constants. |
| Scratch separation | Every live region read through an argument is disjoint from `[0,16)`, including the full allocation of an allocated-empty byte buffer. |
| Memory cap | At most 65,535 pages. |
| No guest resource failure | With `aborts = false`, `Heap.Within` holds for a budget and `Resource.CallPrefixBound` bounds every typed source resource prefix by that budget with its size and depth checks satisfied. |
| No reached host trap | Generated action `.total` theorems require `host.NoTrapsAlong` the native action in its initial world.  Process theorems use application-specific host-progress and final-exit premises. |

The budget is a proof-level natural number.  It accounts for allocation and copying in pure fragments, read-buffer capacity, flat call buffers, helper calls, and loop iterations along host-permitted paths.  The rule of a `sys` command bounds its charge on the runs and prefixes that the host permits.  A flat call charges its output buffer whatever the trace, a record call the block of its record's size plus its alignment less one, and a reported call the block that its reporter's reply asks for, so `reported_rule_observed` in [the rule premises](../Verified/Wasi/SysRule.lean) derives the rule's premises from a bound on the sizes that the host's reporter replies give.  Executable lengths, loop counts, byte values, and statuses remain `UInt64`.  `p.f.callee`, `p.program`, and the source resource relations provide concrete terms for a resource proof.  The frontend exposes this typed prefix condition.  It does not synthesize a bound solely from the original input for every I/O program.

Each running sum's `RunCharges` states its charges and free-memory conditions on native states and stream positions, independently of compiled stores and locals.  The integer program's `RunCharges` takes an invariant, and its termination theorem uses `LimitInv L D`: the state has a future under `limitSpec L D`, a run of the remaining input that meets the limits `L` and `D`, and its buffers are within their bounds.  The integer charges follow from the generated bounds of the pure functions: a step that consumes input pushes at most 4,096 bytes onto the pending line and completes at most one line.  `InputBounds` gives the kernel's size condition at each line, and `InputLimits` bounds the same sizes by `L` and `D` for the memory premise.  The binary64 program's `RunCharges` takes the invariant `LimitInv L` in the same way, and its charges follow from the generated bounds of the parser, the printer, and the effect bodies.  The printer's search for the shortest decimal stops within 27 steps of its start for every finite nonzero binary64 word (`PrintFloatSteps.search_le`), so it tests at most 28 exponents.  Each tested exponent takes two quotients and the choice of the digits at most six more, at most 953,376 bytes each, so the rendering of a total costs at most 59,112,378 bytes.  A parse costs at most `8 · L + 4,404,576` bytes for a line of `L` bytes.  The mathematical `Nat`/`Int` values and progress ranks are proof-only.

[The retained-buffer example](../Verified/Examples/WasiRetain.lean) performs up to two one-byte reads, writes the previous buffer at each iteration, and returns the last buffer.  [Its budget proof](../Verified/Examples/WasiRetainBudget.lean) bounds every host-reply path and resource prefix by 112 bytes: each read charges a 48-byte header and eight-byte minimum capacity.  [The total-execution application](../Verified/Examples/WasiRetainTotal.lean) proves that this budget fits the modeled initial store, supplies the generated representation and separation premises, and applies `compiled.retain.total` under a satisfying host and `NoTrapsAlong`.  [The mixed-depth example](../Verified/Examples/WasiDepth.lean) combines effectful helpers, a hidden constant table, and guarded pure recursion.  Its resource-prefix condition must cover the combined effectful and pure call depth below 1,000.

`NoTrapsAlong` quantifies only operations reachable through source prefixes.  Returned nonzero errnos remain ordinary results.  The premise excludes read and write traps and rejected exit requests along those paths.  Thus callable `.total` allows a native return or accepted exit, while command `.total` proves accepted exit.  A host that rejects some statuses can satisfy the premise for a program whose reached exits use accepted statuses.  [The reached-host condition](../LeanExe/Wasi/NoTrapPrefix.lean), [typed prefix bound](../Verified/Wasi/ResourcePrefix.lean), and [command total theorem](../Verified/Wasi/CommandTotal.lean) give the exact statements.

With `aborts = true`, `.implements` and `.start` permit guest allocation or depth failure after earlier I/O.  Their prefix classification retains those effects.  Normal-return ownership and heap-preservation postconditions apply to a returned store.  Terminal exit and trap require the host to discard the instance.

The host's memory rules preserve globals, memory limits and page count, and bytes outside scratch and a read's destination.  Read and write preserve the exit marker.  Accepted exit records its status and uses the designated exit trap.  Rejected exit preserves the previous marker and records its failure.  The guest wrapper follows `proc_exit` with `unreachable`, while the host API requires the import to terminate.  In [the host assumptions](../Verified/Wasi/HostSpec.lean), an accepted exit sets the exit marker and records its status, and a host trap or a rejected exit leaves the marker unchanged.  A host trap may have any message, including the exit trap's message, so the journal and the exit marker distinguish the outcomes and the trap message alone does not.

`hostSpec host` constrains every invocation of each import from every store, so a satisfying Talos host must answer every request that reaches it.  [The totality module](../Verified/Wasi/HostTotal.lean) gives a sufficient condition and a necessary one, and they differ.  `Host.Total host` requires a permitted reply to every read and write and an accepted or rejected outcome for every exit, and `Host.Total.satisfiable` builds a host environment that satisfies `hostSpec host` for any module with the three imports, from an oracle that chooses those replies.  `Host.Answers.of_satisfies` proves the converse for every request that the one-iovec ABI expresses with its payload at address 16: reads of capacity at most `2^32 - 16`, writes of at most `2^32 - 16` bytes, and every 32-bit exit status.  A theorem that assumes a satisfying host is therefore vacuous for a host relation that leaves such a request without a reply.  The sufficient condition also requires replies to requests that no execution makes, such as reads of capacity `2^32` or more, and the necessary one omits writes that the ABI can express at other addresses.  [The scripted host](../Verified/Wasi/ScriptHostContracts.lean) is the oracle of a queue world.

`hostSpecWith host calls` adds, for each call, `sysContract host call`, whose premise `SysRequest` admits a request that fits the call's parameters (`argsFit`: one argument of the parameter's kind for each parameter that takes one, within its core type), that the call does not reject, whose inputs lie in memory, and whose output regions lie in memory at multiples of their alignments, end below `2^32`, and lie apart from one another and from the inputs.  Inputs may overlap, since `path_rename` and `path_link` may name one path twice.  Wasmtime 44 traps on an output buffer or a reported region that ends at `2^32` in a memory of 65,536 pages, which the bound excludes.  `Host.TotalFor host calls` adds to `Host.Total` a permitted reply to every such request of each call, and `Host.TotalFor.satisfiableWith` builds a host environment that satisfies `hostSpecWith host calls` for any module that imports the calls after the three stream functions.  Its import for a call ([the flat call host](../Verified/Wasi/OracleSys.lean)) decodes the request from the core arguments and the inputs in memory, takes an oracle's reply, and writes each shown output into its region.  `Host.Answers.of_satisfiesWith` proves the converse, `Host.AnswersFor`, for each such request whose inputs and output regions end below `2^32` when laid out one after another from address 16, with result words, records, and reported regions at multiples of their alignments (`layoutEnd`), for a call whose reported regions have positive alignments.

### Initial store and external execution

[The trusted-base document](trusted-base.md#wasi-wasi-preview-1-modules) lists the trusted parts of the WASI theorems, with the check and the source of each.  `p.initial` proves properties of the store constructed from `p.module.initialStore`, with a supplied host world.  It initializes the allocator, constant arrays, and raw static bytes and proves the declared memory cap.  The exported-entry theorems apply to that store after their argument, host, separation, and resource premises have been established.  They can also apply after a prior normal call when its postconditions establish the next call's premises.

The proofs use Lean's kernel, the project's definitions of source actions and memory representations, Talos's execution semantics, and the binary decoder.  Every WASI theorem also assumes that these definitions model Preview 1: `Host`, `Exec`, `exitStatus`, and `Transfer.validErrno` in [the semantics](../LeanExe/Wasi/Semantics.lean) and [actions](../LeanExe/Wasi/Action.lean), `observedHost` in [the observed host](../Verified/Wasi/Observed.lean), `ReadRequest`, `WriteRequest`, `GuestFrame`, and the three import specifications of `hostSpec`, and `TerminalMessage` in [the command specification](../Verified/Wasi/CommandSpec.lean).  The theorems of a module with flat calls also assume `argsFit`, `SysRequest`, `sysContract`, and `hostSpecWith` in [the host assumptions](../Verified/Wasi/HostSpec.lean), `Call.reject` in [the parameter forms](../LeanExe/Wasi/Calls.lean), and the descriptions of [the call table](../LeanExe/Wasi/CallTable.lean).  Their axiom audit permits `propext`, `Classical.choice`, and `Quot.sound`.  Host installation in a real engine, operating-system I/O, the native stream adapter, emitted file contents, and Wasmtime's agreement with the modeled semantics require external validation.  Talos permits memory growth up to the declared cap, while `memory.grow` may fail earlier in an engine.  Fuel bounds describe modeled guest execution.  External reads may block.  [The shared proof scope](design.md#scope-of-the-theorem) describes the engine and file-emission limits.

## Native and WebAssembly execution

### Native interpreter

`action.run host : IO (Outcome α)` executes an action through a `NativeHost`.  `action.runStdio` uses Lean's current stdin, stdout, and stderr.  Its result is `.returned value`, `.exited code`, or `.trapped message`.  Exit returns a terminal outcome to the Lean caller without terminating the Lean process.

`NativeHost.ofStreams` reports errno zero for successful stream reads and full successful count after a write and flush.  It accepts every narrowed exit status.  Stream operations may use several operating-system calls.  An `IO.Error` propagates to the Lean caller, including when a failed stream operation has already changed the outside world.  Explicit `Transfer.trapped` replies instead produce an `Outcome.trapped`.  Invalid host reply lengths or errnos raise an `IO.Error`.  [The native interpreter](../LeanExe/Wasi/Interpreter.lean) defines this adapter policy.

The [running-sum native executable](../Demos/RunningSum/Native.lean) uses a [POSIX fd 0 reader](../Demos/RunningSum/read.c) for short reads on pipes.  The pinned Lean stream reader uses `fread`, which can wait for the requested capacity or EOF.  The descriptor adapter returns after one successful `read`, retries interrupted calls, and propagates other OS errors through Lean's error decoder.  Writes retain the stream adapter's flush policy.  No theorem relates the native interpreter to `Exec`, and its agreement with the semantics depends on inspection and on the native tests.  `Process.runFrom` returns the status of a stopped process to its caller without a host exit, while the compiled `_start` passes that status to `proc_exit`, so the two differ for statuses that Wasmtime rejects.

### Wasmtime host

The [Wasmtime host setup](verified-manual.md#the-wasmtime-host) builds `build/tools/leanexe-wasmtime-host` against pinned Wasmtime 44.0.0.  It uses Wasmtime's standard Preview 1 implementation.  From the repository root, the stdio example builds and emits both module forms:

```sh
mkdir -p build/wasi
tools/leanrun --timeout 10m lake build Verified.Examples.WasiStdio
tools/leanrun --timeout 5m lake env lean --run tools/Emit.lean \
  Verified.Examples.WasiStdio StdioExample.command.module build/wasi/stdio-command.wasm
tools/leanrun --timeout 5m lake env lean --run tools/Emit.lean \
  Verified.Examples.WasiStdio StdioExample.callable.module build/wasi/stdio-callable.wasm
wasm-tools validate build/wasi/stdio-command.wasm
wasm-tools validate build/wasi/stdio-callable.wasm
```

The command form runs `main` and exits with its returned errno:

```sh
build/tools/leanexe-wasmtime-host --stdin-file input.bin \
  --stdout-file output.bin --stderr-file errors.bin run build/wasi/stdio-command.wasm
```

`run` enables WASI and invokes `_start`.  Without stream-file options it inherits stdio.  For a callable module with a `copySome : UInt64 → Action UInt64` export:

```sh
build/tools/leanexe-wasmtime-host --wasi --stdin-file input.bin \
  --stdout-file output.bin --stderr-file errors.bin --control-file control.txt \
  call build/wasi/stdio-callable.wasm copySome i64 i64:4096
```

Control output contains return values, allocation counts in `call-stats` mode, and the outcome records that [the verified compiler manual](verified-manual.md#the-wasmtime-host) lists.  Guest stream files contain guest bytes.  Callable WASI modes require `--control-file` or a separate `--stdout-file`.  Script and session modes also require `--stdin-file` so guest input does not consume host instructions.  Host diagnostics use host stderr.

Exit always passes the low 32 bits of the source status.  [Wasmtime 44 accepts statuses below 126](https://github.com/bytecodealliance/wasmtime/blob/v44.0.0/crates/wasi/src/p1.rs#L2614-L2625) and rejects larger narrowed statuses as engine errors.  For example, `2^32 + 7` requests accepted status 7, and `2^32 + 126` requests rejected status 126.  An accepted exit produces a `wasi-exit STATUS` record when control records are enabled, and the host process uses the low eight bits as its status.  Rejection produces an error diagnostic and process status 1.  Both outcomes preserve previously written guest output.  This differs from the native stream adapter's policy of accepting every narrowed status.

### The Linux shim's specification

[The shim's environment](../Verified/Shim/Satisfies.lean) `linuxEnv F L I replies calls` implements the three stream imports and the flat calls of `shimCalls` with requests of [the Linux call layer](a64-bare-metal.md#the-linux-call-layer), with no instruction set.  Its parameters are the open flags `F` that differ between architectures (`arm64Flags`), the layout `L` of the guest's byte 0 and the shim's scratch, the launch `I` with the process's arguments, its environment, and whether descriptor 3 is a directory that the launcher grants, and the replies `replies`, which give the reply to the call made after that many layer events.  `fd_read` makes one `read` of descriptor 0 into the guest's buffer, at `L.base` plus the guest's pointer, and `fd_write` one `write` of descriptor 1 or 2, through the layer's rule `Linux.step`.  `clock_time_get` of clock 0 or 1 makes one `clock_gettime` into the scratch's timespec and stores the time in nanoseconds, and clocks 2 and 3 answer errno 8 without a call.  `random_get` makes `getrandom` calls until the buffer is full, each asking for the bytes that remain.  `args_sizes_get`, `args_get`, `environ_sizes_get`, and `environ_get` make no call: they answer from `I`, with errno 61 from the sizes functions and a trap from the strings functions when a count or a size reaches `2^32`.  `path_open` makes the checks of `openCheck` in Wasmtime 44's order and then `openat2` with the path and an `open_how` record in the scratch and the resolution `RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS`, again after `EAGAIN` up to four calls in all.  `fd_close` makes one `close`, `fd_read` and `fd_write` on a handle make one `read` or `write` of the request's descriptor with the buffer that the iovec element at the request's pointer names, and `fd_prestat_get` and `fd_prestat_dir_name` make no call.  A result in the range that Linux gives for a request is a count, a descriptor, or a time, a negated error number gives the WASI errno of `errnoOf`, which follows Wasmtime 44's table with `EXDEV` as `perm`, and any other result traps with `shimTrap`.  The shim also traps for a stream request that fails a premise of `ReadRequest` or `WriteRequest`, a flat request with a region outside memory, a clock above 3, and an iovec count other than 1, and it answers a flat request whose pointers are misaligned or whose regions overlap, which `SysRequest` also excludes.  `proc_exit` makes no request of the layer: it accepts a status below 126 and rejects a status of 126 or more with `exitRejected`.

The shim holds open the descriptor numbers of `openNumbers I events`, which it reads from the world's layer events at each call: 3 when `I` grants it and each number below `descriptorLimit`, 1,024, that an `openat2` returned, each until a `close` of the number.  An `openat2` that returns 1,024 or more traps with `shimTrap`: 1,024 is Linux's default soft `RLIMIT_NOFILE`, below which Linux numbers every descriptor of a process that keeps it, and the shim does not change the limit.  `path_open`, `fd_close`, and the handle forms of `fd_read` and `fd_write` refuse every other number with errno 8 (`badf`) and no call, as Wasmtime 44 answers for a number outside its table.  A module then reaches no descriptor that the process inherited, other than the standard streams and a granted 3, when `openat2` returns only numbers that are not open, as Linux does, and no theorem of the shim assumes that property of the replies.  `fd_prestat_get` and `fd_prestat_dir_name` answer for descriptor 3 as the directory `.` while `preopened I events` holds, from the grant until a `close` of 3, and `fd_prestat_dir_name` answers errno 54 (`notdir`) for 0 to 2 and the other numbers held open.  `Image` takes the layer events before each call and reads the same numbers from them, so the host's relation fixes which requests the shim refuses.

[The shim's host](../Verified/Shim/Host.lean) `linuxHost F L I replies` relates a WASI request to a reply exactly when the layer events that it appends form an `Image` of the WASI event, hold their replies, and meet `WritesWithin L (2^32)`.  `Image` fixes each event's call and arguments, the inputs and the bytes before the call where the shim determines them, and derives the WASI reply from the events' results, and it leaves free an address in linear memory and an output region's bytes before a call, which depend on the store.  The sizes of the regions of `args_get` and `environ_get` come from `I`, and the world records the outputs of every successful flat call by name, from which a call that names another reporter takes its sizes, as `Host.sys_reports` requires.  `linuxEnv_satisfies` proves that the environment satisfies `hostSpecWith (linuxHost F L I replies) calls` for every module with at most the stream imports and `calls`, when `shimCalls` holds every call of `calls`, and [`shim_footprint`](../Verified/Shim/Footprint.lean) composes it with `compiled_native_start_run_with`: every run of `_start` with enough fuel traps with a world whose layer events extend the initial world's events by `Images` of a WASI trace of the command's action, which ran to an accepted exit, a rejected exit, a trap of the shim, or a guest trap after a prefix.  No statement assumes a property of the replies other than the frame of the layer's rule.  `linuxHost` admits no reply to a write of `2^32` bytes or more or to a flat call outside `shimCalls`, so a lemma proved by induction on `Exec` under it says nothing of an action that makes such a request.  `shim_footprint` excludes both: a compiled module passes a length below `2^32`, and its premise `supported` excludes the other calls.

`Images.readData` and `Images.writeData` of [the trace lemmas](../Verified/Shim/Trace.lean) give the bytes that the layer's reads and writes of a descriptor moved as the bytes that the trace's events read from or wrote to it, the stream functions' and the handle forms' alike.  [The descriptor corollary](../Verified/Shim/Descriptors.lean) `footprint_namesHeld` states, for every command and every reply sequence, that the layer events of every run that the footprint describes name only standard streams and the numbers that the shim holds open: the descriptor of each `read` and `write` is 0, 1, or 2 or a number of `openNumbers I` after the events before it, and the descriptor of each `close` and the directory of each `openat2` is such a number.  [The readAll example](../Verified/Examples/WasiReadAllShim.lean), [the flat call and environment examples](../Verified/Examples/WasiSysShim.lean), and [the file example](../Verified/Examples/WasiFilesShim.lean) instantiate the footprint, with a guest trap admitted after any prefix and each module's declared memory cap, and the file example also the descriptor corollary.

`WritesWithin L size` bounds each output region by the `size` bytes from `L.base` or makes it the scratch's timespec, and the host and `shim_footprint` state it for `2^32` bytes, the guest's address space.  In an AArch64 executable whose data segment ends below `2^32` and holds the stack and the scratch above linear memory, that window contains them, so the bound excludes no write into the data segment above the guest's byte 0.  `HostEnv.Satisfies` requires each contract at every store, and `linuxHost` sees a world and a request but no store, so a host that bound the writes by a native cap would have to answer a request whose buffer lies beyond the cap at a store whose memory exceeds it, with an event that names an address the environment did not use.  A binding whose relation keeps the store within a native cap at each call obtains that bound from `readEvent_writesWithin` and `randomEvent_writesWithin`, which bound the output region of a `read` or `getrandom` event by any size that holds its buffer, such as the memory's size at the call.  The requests of `clock_gettime` and `openat2` name only the scratch, which lies outside the Talos store: `step_clock` and `step_openat2` give their events for every memory that holds the cleared timespec, the path with its terminating zero, and the `open_how` record.  No binding to a machine exists yet, so no executable runs these definitions, and the theorems state nothing of a process.

The shim follows the repository's Wasmtime host in its errnos and in the order of its checks, except for a file handle as the directory of `path_open`, and it differs in the replies of the table below, each of which the WASI contracts admit.  A test that compares a native run with a run of the same module under the host expects these differences.  The table omits differences that no WASI reply shows, such as the bytes that Wasmtime's helper thread reads from standard input ahead of the guest.  It also omits requests outside the contracts' premises, which a compiled module does not make: Wasmtime answers errno 28 (`inval`) for an enum or flags value out of range and traps for a misaligned pointer, while the shim traps for a clock above 3, ignores flag bits outside the masks, and answers a misaligned flat request.

| Case | Wasmtime host | Shim |
|---|---|---|
| A closed standard descriptor | End of input for a read and a full count for a write, from Rust's `handle_ebadf` | Errno 8 (`badf`) |
| Reads after the first error on standard input | End of input: the stream is closed | Each read's own result |
| A zero-length `fd_read` of standard input | Errno 27 (`intr`) when input is pending, by a reading of the code | A count of 0 |
| A `write` that returns 0 | Errno 29 (`io`) from `write_all` | A count of 0 |
| `fd_read` of standard input | At most 1,024 bytes, one read of the helper thread | Linux's count, up to the capacity |
| `fd_write` to standard output | The whole count or an error, in pieces of 4,096 bytes | Linux's count, which may be short |
| A buffer or path of more than `2^27 − 8` bytes, the hostcall fuel | Errno 48 (`nomem`) | The call for a buffer and the checks of `openCheck` for a path |
| A realtime clock before 1970 | A panic of the host function | Errno 61 (`overflow`) |
| The monotonic clock's origin | The creation of the WASI context | Linux's boot |
| Random bytes | A user-space generator seeded once | `getrandom` for each call |
| Arguments and environment | `--arg` and `--env` values, each UTF-8 | The launch's byte strings |
| The preopened directory | `--dir PATH`, none without it | Descriptor 3 when the launcher grants it |
| A descriptor number that neither a granted 3 nor an `openat2` gave, inherited ones among them | Errno 8 (`badf`), except that `fd_close` of 0 to 2 closes the stream, `fd_read` of 0 reads standard input, and `fd_write` of 1 or 2 writes the stream | Errno 8 (`badf`) for every such number |
| `path_open` under a file handle | Errno 54 (`notdir`), after the UTF-8 check and before the others | The checks of `openCheck`, then `openat2`, which tests an empty or absolute path before the descriptor: errno 58, 28, 37, 44, or 63 |
| `path_open` with `directory` of a symlink not followed | Errno 32 (`loop`) | Errno 54 (`notdir`), from `O_DIRECTORY` |
| A FIFO opened with `directory` | The open blocks until a writer opens the FIFO, then errno 54 | Errno 54 at once |
| `path_open` after four `EAGAIN` results, after `EPERM`, or after `ENOSYS` as before Linux 5.6 | cap-std's own resolution | Errno 29 (`io`) after `EAGAIN` or `ENOSYS` and 63 (`perm`) after `EPERM` |
| Descriptor numbers | Wasmtime's table | Linux's lowest free number |
| `path_open` under a raised `RLIMIT_NOFILE` while every number below 1,024 is open | The open succeeds | A trap of the shim, since `openat2` returns 1,024 or more |
| `append` and `nonblock` | Kept in user space, with every file nonblocking | `O_APPEND` and `O_NONBLOCK` as asked |
| `fd_read` of a directory, descriptor 3 among them | Errno 8 (`badf`) | Errno 31 (`isdir`) from `EISDIR` |
| `fd_close` whose `close` reports a failed flush | 0: dropping the descriptor discards `close`'s result | The errno of `EIO`, `EINTR`, `ENOSPC`, or `EDQUOT` |
| An iovec count other than 1 | The first non-empty element, or a count of 0 without one | A trap of the shim |

## Tests

```sh
tests/wasi/run.sh --foundations-only
tests/wasi/run.sh
```

[The flat call example's driver](../tests/wasi/sys-example-run.sh) audits the axioms of the marshalling theorems, the reflection equations, the host totality theorems, and the example's generated theorems.  It checks [a witness host](../tests/wasi/SysWitness.lean) that meets `Host.TotalFor`, `Host.NoTraps`, and the premise of `reported_rule_observed`, and that has an environment satisfying `hostSpecWith` for the example's module.  `total_of_bound` in [the example's total theorem](../Verified/Examples/WasiSysTotal.lean) discharges the heap and resource premises of the example's `total` for every host whose `args_sizes_get` replies ask for blocks of at most 252,640,960 bytes, and the witness file applies it to the witness host.  The driver runs native cases with the native host's calls, with replies that carry an errno, and with `args` at its size test, and it runs the module in the Wasmtime host with no arguments, one argument four times, four arguments of which one is empty, and two arguments of which one has 4,096 bytes.  Each run must report the realtime clock within a day of the system clock and the monotonic clock below `10^17` ns, and the four runs with one argument must give at least two values at each random position.  The driver also audits the axioms of the input and record examples, runs the record functions natively against scripted replies, and runs both modules in the Wasmtime host with a fresh preopened directory, which each must leave empty.  The record example must report the file types of the directory and of its file, the file's append flag and its size of `2^32 + 5`, and the same filestat through the descriptor and through the path.  The driver audits the axioms of the environment example and runs it with two environment variables and with none, and each run must write the count, the size, and the variables that the host was given.  It runs the nested calls natively against scripted replies, among them a count above the capacity, which the prefix clamps, audits the axioms of the nested example, `handles` among them, and runs its module, which must write exactly the bytes it read, the fields of both polls, and leave the directory empty.  It runs the `main` of the record example and of the nested example natively against a host whose `fd_close` returns errno 8.  Each must return 8, or 5 when a call in the bracket's body also returns errno 5, and neither may call `path_unlink_file`.  [The flat call driver](../tests/wasi/sys-run.sh) checks the generated files against the generator's output and the call table against the independent lowering, and it checks that both checks reject altered files.  It runs the frame test of the argument calls with several argument lists, and the frame test of every function with a description, with a fresh preopened directory, two arguments, and one environment variable, whose bytes and pointers the test checks after `args_get` and `environ_get`.  Its steps for the nested calls write a file of 64 bytes with `fd_write` and `fd_pwrite`, read 16-byte buffers back with `fd_read` and `fd_pread`, and poll a clock with timeout 0 and the file for reading and writing, with the read buffers, the result words, and the events as the declared regions.  The iovec element and the subscriptions are among the bytes that must keep their values.  Before each call, the second module fills the first 65,536 bytes of its memory, where every region lies, with a guard byte, and after the call it checks the errno that Wasmtime 44 gives, that every byte outside the call's declared regions keeps its value, and values that the call writes, such as a file size of `2^32 + 5` and the type of the preopened directory, reading each record field at the offset and with the width of the call's description.  Each result word and record lies at a multiple of its alignment that is not a multiple of twice it, so that Wasmtime traps when a description gives it a smaller alignment.  The driver also runs frame tests that the generator writes with seeded faults (a record one byte short, an 8-byte result word declared with 4 bytes, an output buffer one byte short, an output buffer one byte late, a record at half its alignment, the strings of `environ_get` one byte short, a read buffer one byte short, an iovec at half its alignment, an event record 7 bytes short and one byte late, and a wrong expected count of `fd_pread`), each of which must fail with the status of its check.  The status names the step and the kind of check: the step's number for the errno, the number of steps plus it for a byte outside the regions, and for the step's values twice the number of steps plus the step's position among the steps with value checks.  Every status lies below 126, which Wasmtime 44's `proc_exit` refuses, and the generator refuses a list of steps that needs more.  Its rejection sweep passes each enum parameter its last value and the next one and each flags parameter each single bit, [the sweep check](../tests/wasi/SysSweep.lean) computes with `Call.reject` which of these values each call rejects, and Wasmtime must trap on each rejected value and return an errno for the others.

[The readAll example](../Verified/Examples/WasiReadAll.lean) copies its standard input to its standard output through `readAll 1000000` and returns 1 when the input exceeds the limit.  [Its driver](../tests/wasi/readall-run.sh) audits the axioms of `readAll`'s proofs and the example's generated theorems, runs native cases against scripted replies, and runs the module in the Wasmtime host on inputs from files and from pipes of 0, 1, 4,095, 4,096, 4,097, 65,536, 1,000,000, 1,000,001, and 3,000,000 bytes, with a read error and a write error.

[The WASI driver](../tests/wasi/run.sh) builds the universal proofs and audits their axioms.  The foundations-only mode also runs native interpreter, wrapper-code, and exit-model tests.  The native interpreter tests run `withOpen` against scripted hosts, among them one whose `fd_close` returns errno 8, and check the errno that it returns.  [The handle check tests](../tests/wasi/HandleCheck.lean) check in the kernel that `Command.HandleCheck` refuses a close or an open outside a bracket, an unmarked directory, a handle argument bound to another word, a helper call with an unmarked handle argument, and a bracket that does not return the body's result with the close's errno.  They check that it accepts single and nested brackets, a bracket whose body returns bytes, and the preopened directory, and that `verified_compile_wasi` refuses a body that returns `Unit`.  The full mode adds emitted-module validation and execution tests for packed bytes, literals, ownership and allocation counts, reflected callable and command modules, and the standard Wasmtime host.  [The public reflection driver](../tests/wasi/reflection-run.sh) tests generated modules against binary stream fixtures and separate control records.  [The host tests](../tests/wasi/host.sh) cover stream routing, accepted and rejected exits, low-32-bit conversion, and terminal lifecycle behavior.

[The running-sum driver](../tests/running-sum/run.sh) checks the unbounded process loop, native and Wasm decimal streams, split lines, short and zero-byte writes, committed effects before failures, and interactive output before EOF.  [The floating-point driver](../tests/running-sumfp/run.sh) adds rounding, cancellation, subnormals, overflow, signed zero, infinities, NaNs, and the general parser grammar, through native, Talos, Wasmtime, and interactive stream tests.  On an 8-CPU host with about 12 GiB of memory, the full WASI and floating-point drivers use `LEANRUN_MEMORY_HIGH=10G`, with the [approved CPU and worker settings](../AGENTS.md#lean-process-limits).  The initial combined parser/printer WASI compilation had a captured memory peak of 4.84 GiB.
