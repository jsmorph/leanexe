# Review of the specification

Two fresh agents reviewed [the specification](Spec.lean) and [the case inputs](../../../tests/TestSupport/Modules/BinarySearch.lean) against [the request](request.txt), from the files alone.

The first review found no disagreement for any sorted array that memory can hold.  It found three points that the specification's comment did not state: that indices start at 0, that the specification fixes the result and not the method, and that the count fits in a word only for arrays of fewer than `2^64` elements.  The comment now states all three.  It also named classes that no input covered: an array of two elements, arrays of more than 34 elements, long runs of equal elements in a long array, and words on either side of `2^63`.  The inputs now include arrays of 2 elements, of `2^63 - 1` and `2^63`, and five arrays of 200 to 1,000 elements, three with long runs of equal words.

The second review found no disagreement.  It confirmed that restricting the theorem to sorted arrays follows the request, which states the order as a property of the input, and that the comment records the index base, the bound on the size, and the scope of the specification.  Its remaining notes are recorded here without new inputs.  No array has 8, 9, 15, 17, 32, or 33 elements, sizes at which a search whose steps are powers of two changes its first step.  On the long arrays the keys reach only the answers 0, the length, and those next to every 37th element.  The specification does not certify that the program follows the steps of Algorithm B, which only the program text shows.
