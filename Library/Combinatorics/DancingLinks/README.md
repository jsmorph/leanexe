# DancingLinks: Algorithm X of TAOCP §7.2.2.1

## Request and specification

[The request](request.txt) asks for the number of exact covers of the items `1..N` by a list of options, computed with Knuth's dancing links, and for a check of the input.  The input is a word array `[N, items of option 1, 0, items of option 2, 0, …]`.  [The specification](Spec.lean) reads `N` as `x.getD 0 0` and the options as the maximal runs of nonzero words after it, so consecutive, leading, and trailing zeros add no option, a last run without a zero after it is an option, and two equal runs are two options.  `countSpec x` is the number of sets of option indices that contain exactly one option holding each item of `1..N`, modulo `2^64`, and `validSpec x` is 1 exactly when `N ≤ 998`, every item lies in `1..N`, and no option repeats an item.  The bound on `N` comes from [the compiler's limit of 1,000 nested calls](../../../docs/verified-manual.md#calls-and-recursion), since the search takes one call for each level.  The request fixes the count only on valid inputs, and the module's theorem for `count` assumes validity, which `valid` checks.  [The review](review.md) records the specification's independent reviews and the classes of input that the cases leave out.

## The program

[The program](Program.lean) performs Algorithm X of §7.2.2.1 with the recursive `search(k)` of Knuth's paper "Dancing Links" in place of TAOCP's explicit list of choices `x_0, …, x_l`.  `build` performs step X1, and `count` calls `search` with the depth bound `N`.  A call of `search` performs step X2, returning 1 when no item is active, and otherwise step X3 in `choose`, which takes the active item with the fewest remaining options, Knuth's minimum-remaining-values heuristic, and the leftmost on ties, as DLX1 does when it does not randomize.  It then covers the item, step X4, and for each option in the item's list covers the option's other items with `coverOthers`, step X5, counts the covers of the rest by a recursive call, and uncovers those items with `uncoverOthers` in `next`, step X6.  At the end it uncovers the item, step X7, and returns to the level above, which takes the place of step X8.  `coverItem`, Knuth's `cover(i)`, hides the options of the item's list from the top down with `hideColumn` and `hide` and then unlinks the item, and `uncoverItem`, Knuth's `uncover(i)`, relinks it and unhides the options from the bottom up with `unhideColumn` and `unhide`, in the reverse order.

The program holds Knuth's two tables in one array, so that the frame of the recursive `search` fits the compiler's limit, which the next section states.  Node `p` holds `TOP`, `ULINK`, and `DLINK` in words `3p` to `3p + 2`: node 0 belongs to no list, the headers `1..N` keep the length `LEN` of their list in `TOP`, each option's nodes follow a spacer, and the spacer `Z` follows the last option.  A spacer has `TOP = 0`, a `ULINK` to the first node of the option before it, and a `DLINK` to the last node of the option after it.  Knuth's spacers hold `TOP` values 0, -1, -2, and so on, which DLX1 tests only for their sign.  The item links `LLINK` and `RLINK` follow the nodes at `b = 3(Z + 1)`, with item 0 as the header of the list of active items.  The proof states the lists pointwise: a column with header `c` and present nodes `Q` is the cyclic list of `c` and `Q` in increasing order, so each node's `DLINK` is `nxt c Q` of it, the least present node above it or the header, and its `ULINK` is `prv c Q` of it, and the list of active items has the same form with item 0 as its header.  The invariant of the search, `Inv t L B`, holds the static words, the list of active items `B`, and, for each active item, its column of the nodes of the options that lie inside `B`.  At each pass of the loop of `search` over the column of the chosen item `i`, the array is the one that covering `i` produced, and the count so far is the sum of the covers over the nodes already visited.

A call of `search` with an active item makes one recursive call for each option in the chosen item's list, so the calls form the search tree of Algorithm X, and each exact cover corresponds to exactly one call that finds no active item and returns 1.  The recursion goes at most `N` levels below the first call, since each level covers at least the chosen item, and it goes `N` levels down when a cover's options each hold one item.  `choose` reads each active item once.  Covering item `i` writes three words, `DLINK(u)`, `ULINK(d)`, and `LEN`, for each node of each option in the list of `i` other than the option's node in that list, and two item links, and uncovering writes the same words in the reverse order.

## The module counts the exact covers

`verified_compile compiled := [hide, unhide, hideColumn, unhideColumn, unlinkItem, relinkItem, coverItem, uncoverItem, coverOthers, uncoverOthers, choose, next, search, nodeCount, build, count, valid]` in [the verified compilation](Compiled.lean) compiles the program into a module whose exports `count` and `valid` are functions 20 and 18.  Function 20 is the entry of `count`, which starts its code at call depth 0.  The compiler limits the frame of a function whose code takes the call depth to 32 positions, and a tuple that holds two arrays takes a position for each of its nested pairs.  One array, one `if` for both early returns of `search`, and the helper `next` for the end of each pass of its loop keep the frame of `search` within that limit.  The generated bound of `search` is 0, so the search copies no array, and the bound of `count` is the one block of the array that `build` allocates.  `valid` reads `N` first and returns 0 for `N > 998` before it allocates its mark array of `N + 1` words.  The call theorems compose the generated `trapFree` theorems with `count_eq` and `valid_eq`.

Removing a node changes only the successor of its predecessor and the predecessor of its successor, which are the writes of `hide`, and the node's own links keep their values, so restoring it right after returns the array.  `rstAll_delAll` extends this to a list of removals undone in the reverse order, the order in which `unhide` walks an option and `uncover` walks a column.  `cover_inv` shows that covering `i` leaves the invariant of `B` without `i`, since hiding the options through `i` removes exactly the nodes of the options that no longer lie inside the active items.

`search_eq` is an induction on the depth bound.  The search's loop visits the present nodes of the chosen column in increasing order, each pass covers the other items of one option, the induction gives the count of the remaining items, and the uncovers restore the array, so the sum over the column is `coversOf_rec` at the chosen item.  The sum does not depend on which active item the search chooses, so `choose_mem` states only that the choice is active.  The search's depth condition, the generated `fits`, depends on the depth bound alone, so `search_fits` proves it for every array by induction, without the invariant.  `build_inv` follows step X1 with the reader of `Read.lean`: after each prefix of the words, the array holds the columns of the nodes made so far, the spacers up to the current option, and zeros in every later word, and the reader's options are the specification's.  The axiom reports of `count_call` and `valid_callSpec` name only `propext`, `Classical.choice`, and `Quot.sound`.

## Building, running, and testing

```sh
tools/leanrun --timeout 60m lake build Library.Combinatorics.DancingLinks.Compiled
tests/verified/run.sh --cases dancingLinks
tests/native/verified.sh --module dancingLinks
```

The commands build the verified compilation and its theorems and run the module's cases, with the setup of [the repository README](../../../README.md#commands).  The inputs of `count` in [the case inputs](../../../tests/TestSupport/Modules/DancingLinks.lean) include the empty array and inputs with no items, leading, consecutive, and trailing zeros, an option without a zero after it, equal options, an item in no option, options in no cover, and an option whose items are not in increasing order.  They also include Knuth's example, the Bell numbers `B(1)` to `B(6)` and `B(10)` from all subsets of the items, two copies of each one-item option for 10 and 17 items, 65 items with an option that holds the items 1 and 65, domino tilings, the empty 4 × 4 Sudoku, Langford pairs of orders 3, 4, 5, and 7, and 998 items with one option each, which uses the deepest recursion the depth limit allows.  The inputs of `valid` add the item counts 998, 999, and `2^64 - 1`, repeated items in first, middle, and last options, the items 1 and 65 in one option, items above `N`, the same item in two options, and items with `N = 0`.  [The verified library cases](../../../tests/TestSupport/LibraryCases.lean) print each input with its expected value, from `countRef`, which `countRef_eq` equates with the specification, and from `validSpec`.  [The verified driver](../../../tests/verified/run.sh) runs the cases in Wasmtime, checks each call's allocations, and checks the file theorems, and [the native driver](../../../tests/native/verified.sh) runs them on the module's translation to C, compiled with CompCert.
