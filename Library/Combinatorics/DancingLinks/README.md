# DancingLinks: Algorithm X of TAOCP §7.2.2.1

## Request, specification, and program

[The request](request.txt) asks for the number of exact covers of the items `1..N` by a list of options, computed with Knuth's dancing links, and for a check of the input.  The input is a word array `[N, items of option 1, 0, items of option 2, 0, …]`.  [The specification](Spec.lean) reads `N` as `x.getD 0 0` and the options as the maximal runs of nonzero words after it, so consecutive, leading, and trailing zeros add no option, a last run without a zero after it is an option, and two equal runs are two options.  `countSpec x` is the number of sets of option indices that contain exactly one option holding each item of `1..N`, modulo `2^64`, and `validSpec x` is 1 exactly when `N ≤ 998`, every item lies in `1..N`, and no option repeats an item.  The bound on `N` comes from the compiler's limit of 1,000 nested calls, since the search takes one call for each level.  The request fixes the count only on valid inputs, and the module's theorem for `count` assumes validity, which `valid` checks.

[The program](Program.lean) keeps Knuth's two tables in one array.  Node `p` holds `TOP`, `ULINK`, and `DLINK` in words `3p` to `3p + 2`: the headers `1..N` keep the length of their list in `TOP`, each option's nodes follow a spacer, a spacer follows the last option, and a spacer has `TOP = 0` with links to the first node of the option before it and the last node of the option after it.  The item links `LLINK` and `RLINK` follow the nodes at `b = 3(Z + 1)`, with item 0 as the header of the list of active items.  `build` performs step X1 word by word, and `count` calls `search` with the depth bound `N`.  `search` is the recursive `search(k)` of Knuth's paper "Dancing Links", where TAOCP writes steps X1 to X8 with an explicit stack: when no item is active it returns 1, and otherwise it chooses the active item with the fewest remaining options, the leftmost on ties as DLX1 does, covers it, and for each option in its list covers the option's other items, counts the rest, and uncovers them.  `coverItem` hides the options of the item's column and then unlinks the item, and `uncoverItem` relinks it and then unhides the options from the bottom up, the reverse order, as TAOCP's `cover` and `uncover` do.  The program marks spacers with 0, where Knuth numbers them with nonpositive values that his program DLX1 reads only to print an option.

The first version of the program kept the nodes and the items in two arrays, and the compiler rejected its `search`, because a function whose code takes the call depth may use at most 32 positions, and a tuple that holds two arrays takes a position for each nested pair.  One array, one `if` for both early returns of `search`, and the helper `next` for the end of each pass of its loop bring the frame within 32 positions.  The generated bound of `search` is 0, so the search copies no array, and the bound of `count` is the one block of the array that `build` allocates.  `valid` reads `N` first and returns 0 for `N > 998` before it allocates its mark array of `N + 1` words.

## The module counts the exact covers

`verified_compile compiled := [hide, unhide, hideColumn, unhideColumn, unlinkItem, relinkItem, coverItem, uncoverItem, coverOthers, uncoverOthers, choose, next, search, nodeCount, build, count, valid]` in [the verified compilation](Compiled.lean) compiles the program into a module whose exports `count` and `valid` are functions 20 and 18.  Function 20 is the wrapper that starts `count`'s code at call depth 0.  The call theorems compose the generated `trapFree` theorems with `count_eq` and `valid_eq`.

| Theorem | File | Statement |
|---|---|---|
| `coversOf_rec`, `coverCount_eq` | [The count](Count.lean) | For any item `i` of `B`, the covers of `B` are the sum, over the options inside `B` that hold `i`, of the covers of `B` without that option's items, and on a valid input the specification's count is the count of all items. |
| `refCount_eq`, `countRef_eq` | [The count](Count.lean) | The recursion on lists that the cases use equals `coverCount` and `countSpec` on valid inputs. |
| `nxt_erase_prv`, `prv_erase_nxt`, `repeatWhile_inv` | [The links](Links.lean) | Removing a node from a cyclic list joins its predecessor to its successor, and a loop's invariant with a decreasing measure holds at its end. |
| `del_col`, `rst_del` | [The removals](Delete.lean) | Removing a present node keeps the column of the others, and restoring it right after returns the array. |
| `rstAll_delAll` | [The layout and columns](Table.lean) | Removing distinct present nodes in order and restoring them in the reverse order returns the array. |
| `walkFwd`, `walkBwd`, `hide_eq`, `unhide_eq` | [The walks](Walk.lean) | The walk around an option forward from `p + 1` and back from `p - 1`, and Knuth's `hide` and `unhide`. |

| `coverOthers_eq`, `uncoverOthers_eq`, `choose_mem` | [The option loops](Others.lean) | Steps X5 and X6 for one option, and step X3 returns an active item. |
| `search_eq` | [The search](Search.lean) | On an array with the invariant of `B` and a depth bound of at least `\|B\|`, `search` returns the number of exact covers of `B` modulo `2^64` and the same array. |
| `finish_read`, `nodeCount_eq`, `layout_good` | [The reader](Read.lean), [the layout](Layout.lean), [the build's parts](BuildInit.lean) | Reading the words one at a time gives the specification's options, `nodeCount` counts their nodes and spacers, and a valid input's layout meets the search's conditions. |

The proof states the lists pointwise.  A column with header `c` and present nodes `Q` is the cyclic list of `c` and `Q` in increasing order, so each node's `DLINK` is `nxt c Q` of it, the least present node above it or the header, and its `ULINK` is `prv c Q` of it, and the list of active items is the same structure with item 0 as its header.  Removing a node changes only the successor of its predecessor and the predecessor of its successor, which are the writes of `hide`, and the node's own links keep their values, so restoring it right after returns the array.  `rstAll_delAll` extends this to a list of removals undone in the reverse order, the order in which `unhide` walks an option and `uncover` walks a column.  The invariant `Inv t L B` of the search holds the static words, the list of active items `B`, and, for each active item, its column of the nodes of the options that lie inside `B`.  `cover_inv` shows that covering `i` leaves the invariant of `B` without `i`, since hiding the options through `i` removes exactly the nodes of the options that no longer lie inside the active items.

`search_eq` is an induction on the depth bound.  The search's loop visits the present nodes of the chosen column in increasing order, each pass covers the other items of one option, the induction gives the count of the remaining items, and the uncovers restore the array, so the sum over the column is `coversOf_rec` at the chosen item.  The sum does not depend on which active item the search chooses, so `choose_mem` states only that the choice is active.  The search's depth condition, the generated `fits`, depends on the depth bound alone, so `search_fits` proves it for every array by induction, without the invariant.  `build_inv` follows step X1 with the reader of `Read.lean`: after each prefix of the words, the array holds the columns of the nodes made so far, the spacers up to the current option, and zeros in every later word, and the reader's options are the specification's.  The axiom reports of `count_call` and `valid_callSpec` name only `propext`, `Classical.choice`, and `Quot.sound`.

## Building, running, and testing

```sh
tools/leanrun --timeout 60m lake build Library.Combinatorics.DancingLinks.Compiled
tests/verified/run.sh --cases dancingLinks
tests/native/verified.sh --module dancingLinks
```

The commands build the verified compilation and its theorems and run the module's cases, with the setup of [the repository README](../../../README.md#commands).  The inputs of `count` in [the case inputs](../../../tests/TestSupport/Modules/DancingLinks.lean) include the empty array and inputs with no items, empty, consecutive, and trailing runs, equal options, an item in no option, and options in no cover.  They also include Knuth's example, the Bell numbers from all subsets of up to 10 items, two copies of each one-item option for 10 and 17 items, domino tilings, the empty 4 × 4 Sudoku, Langford pairs of orders 3, 4, 5, and 7, and 998 items with one option each, which uses the deepest recursion the depth limit allows.  The inputs of `valid` add item counts above 998, repeated items in first, middle, and last options, and items above `N`.  [The verified library cases](../../../tests/TestSupport/LibraryCases.lean) print each input with its expected value, from `countRef`, which `countRef_eq` equates with the specification, and from `validSpec`.  [The review](review.md) records the specification's independent reviews and the classes of input that the cases leave out.  [The verified driver](../../../tests/verified/run.sh) runs the cases in Wasmtime, checks each call's allocations, and checks the file theorems, and [the native driver](../../../tests/native/verified.sh) runs them on the module's translation to C, compiled with CompCert.
