# Review of the specification

Two fresh agents reviewed [the specification](Spec.lean) and [the case inputs](../../../tests/TestSupport/Modules/Heapsort.lean) against [the request](request.txt), from the files alone.

The first review found no input on which `expected` differs from the request.  It found that the comment's claim of one nondecreasing list held only if "collection" counts repetitions, and that the comment did not mention arrays of 0 and 1 elements, which Knuth's Algorithm H excludes, or the meaning of "no storage beyond the array."  The comment now states all three: the same words with the same repetitions, arrays of 0 and 1 elements as their own result, and no allocation, which a separate theorem states.  It named three classes without inputs: a long ascending array, a long array of one repeated word, and a long array of only 0 and `2^64 - 1`.  The inputs now include an array of 300 elements of each kind.  It also found three inaccuracies in the inputs' docstring, now corrected.

The second review found no disagreement.  It found two more faults in the docstring, an omitted input and a misdescribed boundary array, both now corrected, and it asked whether the call stack counts as storage, which the comment now answers: the sift compiles to a loop.  It recorded one class that no input can reach: overflow of `2i + 1` near the top of the index range, which appears only in arrays far too large to build and which the main theorem covers.  Both reviews noted that the theorem certifies the result and not the method, so an in-place insertion sort would satisfy the same theorems, and only the program text shows Algorithm H.
