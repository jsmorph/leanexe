# Review of the specification

Two fresh agents reviewed [the specification](Spec.lean) and [the case inputs](../../../tests/TestSupport/Modules/RadixSort.lean) against [the request](request.txt), from the files alone, each with an independent Python model of the program at 64-bit words.  Both found that `expected` states the request's result on every input, and their models returned Python's `sorted` on every case input and on 1,525 and 114 further arrays, among them 70,000 words below 256 and arrays near `2^63` and `2^64`.  The first checked on positions that each pass is a stable sort by its byte and that the counts after steps D4 and D6 are those of Algorithm D, and it found that the program follows steps D1 to D6 with positions from 0, using Knuth's text through a third-party transcription of §5.2.  The second checked the claims of the proof on random arrays: the counts of `countDigits_spec`, the placement at `pos s src j`, the distinct positions, and the order modulo `2^(8k)` after `k` passes.

Both found that the theorems read the allocation requirement as a rise of `top` of at most `blockCost n + blockCost 256`, which permits allocations from free blocks and a single block of the same cost, and that no theorem states that the call releases the second array and the counts or that the result occupies the input's block.  The specification's comment now states this reading and names the theorems that give it, the comment of the program now says that the result's block depends on the compiler's ownership rules, and the compilation's comment states the bound as a sum of costs where it had named the blocks.  Both found that the docstrings of `low_step` and `pass_spec` described their use in the proof, where `low_step` concerns two words and `pass_spec` states a relation between the words of the input in order, and that the docstring of `countDigits` left out its 256 counts.  These docstrings now state what the code and the theorems give.

Both found two sentences of the case inputs that said more than the arrays do: every pass moves every word, so a one-byte array makes one pass the only one that changes the order, not the only one that moves words, and the arrays of bytes 0 and 255 are not tied to one byte each.  The sentences now describe the arrays.  Both ran wrong programs on the case inputs and found that the cases detect every one of them that returns a wrong result, while variants that return the sorted array on every input, such as an unstable first pass, four passes on 16-bit digits, or a stable counting sort other than Knuth's, pass every case and every statement but the bound, which the 16-bit variant breaks.

The first found that a wrong mask on a middle byte and an exchange of two middle passes were detected only by one or a few arrays, and the cases now add, for each byte, 300 words whose higher bytes are fixed and whose lower bytes are arbitrary, so that every pass up to that byte decides the order.  The second found that no count exceeded 10,000 in one pass, and the cases now add 17,000 words with the same lowest byte.  An argument of the host program holds at most 128 KiB, which excludes arrays of more than about 6,000 full-width words.
