# MultiPrecision: Algorithms A, S, M, and D of TAOCP §4.3.1

## Request, specification, and program

[The request](request.txt) asks for addition, subtraction, multiplication, and division of nonnegative integers held as arrays of digits in base `b = 2^32`, least significant first, one digit to a word.  [The specification](Spec.lean) states each result through `value u`, the sum of `u[i] * b^i`, and `digits n x`, the `n` least significant digits of `x`.  The lengths of the results follow Knuth's algorithms: a sum has `k + 1` digits and a difference `k`, where `k` is the larger length of the arguments, and a product has `m + n` digits, where `m` and `n` are the lengths.  A division returns the `m` digits of the quotient followed by the `n` digits of the remainder.  A difference `u - v` with `u < v` is `u - v + b^k`, the result of Algorithm S without its final borrow, and division by 0 gives the quotient 0 and the remainder `u`, as Lean's `Nat` division does, cut or padded to `n` digits.  `Digits u` states that every word of `u` is below `b`, and the results on other arrays carry no meaning.

[The program](Program.lean) follows Knuth's steps.  `add` runs Algorithm A over the `k` positions with a carry of 0 or 1 and appends the final carry.  `sub` runs Algorithm S, which adds `b` to each digit before it subtracts the digit of `v` and the borrow, so that no word wraps, and takes the new borrow as 1 when the sum stays below `b`.  `mul` runs Algorithm M: for each digit `v[j]`, an inner loop adds `u * v[j]` to the product's digits from position `j` on, and the last carry becomes digit `j + m`.  Knuth's step M2, which skips a zero digit of `v`, is a shortcut whose omission leaves the product unchanged, and the program omits it.  A read past the end of an argument gives 0, so the loops of `add` and `sub` run over both arguments to the larger length.  Each loop's state holds the carry or the borrow before the array that the step changes, so that the step reads the array before it writes it.

`divide` counts the significant digits `t` of the divisor with `significant`.  A divisor of value 0 gives zeros followed by the low digits of `u`, and a divisor of one significant digit uses `shortDiv`, which divides from the most significant digit down and appends the remainder.  `longDiv` runs Algorithm D for `t ≥ 2`.  Step D1 multiplies both arguments by `d = 2^(32 - L)`, where `L` is the bit length of the divisor's top digit, so that the top digit of the normalized divisor is at least `b / 2`.  The program computes the products with the Uscale module's `mulSmall` and the bit length with its `wordBits`.  Each step of the main loop takes the quotient digit at position `j = m - t, …, 0`.  Step D3, in `trial`, divides the top two digits of the partial remainder by the top digit of the divisor and decreases the trial digit while `tooBig` holds, at most twice.  Step D4 subtracts the trial digit times the divisor from the `t + 1` digits from `j`, and step D6 adds the divisor back and decreases the digit when the difference is negative.  Step D8 divides the low `t` digits of the final partial remainder by `d` with `shortDiv`.  Knuth's loop runs `j` down from `m - t` to 0, and the program's loop counts `e` up and takes `j = m - t - e`.

## The module computes the results

`verified_compile compiled := [width, add, sub, mul, significant, mulSmall, wordBits, shortDiv, tooBig, trial, longDiv, divide]` in [the verified compilation](Compiled.lean) compiles the program into a module whose exports `add`, `sub`, `mul`, and `divide` are functions 3, 4, 5, and 13.  The call theorems compose the generated `trapFree` theorems with `add_eq`, `sub_eq`, `mul_eq`, and `divide_eq`.  The generated bounds of `add` and `sub` count only the growth of the result, the bound of `mul` is one block of `m + n` words, and the bound of `divide` counts the normalized arguments, the quotient's block, the short division, and the result, so no function copies an array.

`prefixValue u q` is the value of the first `q` digits of `u`, and `segValue w j n` the value of the `n` digits from position `j`.  The loop of Algorithm A keeps `prefixValue w j + c * b^j = prefixValue u j + prefixValue v j`, where `w` holds the digits written so far and `c` is the carry, and the loop of Algorithm S keeps `prefixValue w j + prefixValue v j = prefixValue u j + c * b^j` with the borrow `c`.  The inner loop of Algorithm M keeps `prefixValue w' (i + j) + c * b^(i + j) = prefixValue w (i + j) + prefixValue u i * v[j] * b^j`, and the outer loop keeps `prefixValue w (j + m) = value u * prefixValue v j` with the digits from `j + m` on still 0.  Each step's equation follows from the identity of its digit, `t % b + b * (t / b) = t`, by `linear_combination` over the integers.

`DivInv U V m J` states the invariant of Algorithm D's main loop for the normalized arguments `U = value u * d` and `V = value v * d` when the positions from `J` on are done.  The quotient digits so far have the value `U / (V * b^J) * b^J`, and the partial remainder is `U % (V * b^J)`, so the `t + 1` digits from position `J - 1` hold a number `X` below `b * V` whose quotient by `V` is the next digit.  The trial-digit theorems place the digit of step D3 in `{X / V, X / V + 1}`.  A borrow out of step D4 shows that the digit is one too large, and step D6 then leaves `X % V` in the window.  At position 0 the quotient digits are `U / V = value u / value v`, and the partial remainder is `(value u % value v) * d`, which step D8 divides by `d`.  The bounds on the lengths keep every index and every size below `2^64`, and the call theorems obtain the bound on each array from its presence in memory.  The limb routines of [the Uscale module](../Arithmetic/Uscale/README.md) use the same representation, which they state with `val` and `Limbs`.  The axiom reports of the four call theorems name only `propext`, `Classical.choice`, and `Quot.sound`.

## Building, running, and testing

```sh
tools/leanrun --timeout 60m lake build Library.Numerics.MultiPrecision.Compiled
tests/verified/run.sh --cases multiPrecision
tests/native/verified.sh --module multiPrecision
```

The commands build the verified compilation and its theorems and run the module's cases, with the setup of [the repository README](../../../README.md#commands).  The cases come from [the case inputs](../../../tests/TestSupport/Modules/MultiPrecision.lean).  The pairs of `mpInputs` run through addition, subtraction, and multiplication: empty and zero numbers, carries and borrows through runs of digits, differences whose first argument is the smaller, products of the largest digits, every pair of lengths from 1 to 8 digits, and numbers of up to 150 digits.  The pairs of `divInputs` run through division: zero divisors, divisors of one significant digit, dividends shorter than the divisor, pairs that make step D6 add the divisor back or step D3 decrease the trial digit twice, divisors with and without a shift, and arbitrary pairs of up to 100 digits.  [The review](review.md) records the specification's independent reviews and the classes of input that the cases leave out.  [The verified library cases](../../../tests/TestSupport/LibraryCases.lean) print each pair with its results.  [The verified driver](../../../tests/verified/run.sh) runs the cases in Wasmtime and checks the file theorems, and [the native driver](../../../tests/native/verified.sh) runs them on the module's translation to C, compiled with CompCert.
