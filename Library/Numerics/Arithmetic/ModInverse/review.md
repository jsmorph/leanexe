# Review of the specification

Two fresh agents reviewed [the specification](Spec.lean) and [the case inputs](../../../../tests/TestSupport/Modules/ModInverse.lean) against [the request](request.txt), from the files alone.

The first review found no input on which `expected` differs from the request.  It confirmed that the guard `2 ≤ m` is required, since `(1 : ZMod 0)⁻¹ = 1` would otherwise make `(1, 0)` return 1, and that returning 0 for `m = 1` follows from the request's own definition.  It found two missing classes: `(1, 0)`, the only pair with `m = 0` and `gcd a m = 1`, which a program that tests only the greatest common divisor would get wrong, and the consecutive Fibonacci numbers `F₉₂` and `F₉₃`, on which the algorithm takes its largest number of steps.  The inputs now include both, the Fibonacci pair in both orders.  It also found three inaccuracies in the inputs' docstring, now corrected, and the comment now states that the congruence is one of integers and that the specification fixes the result and not the method.

The second review found no disagreement.  It found that one sentence of the comment attached the fact that 0 is never an inverse modulo `m ≥ 2` to the non-coprime case alone and left out `m = 1`, where 0 is the inverse; the comment now states both.  It named the docstring's omissions, the small moduli and two repeated pairs for `m = 2^64 - 1`, which the docstring now states.  Its remaining notes are recorded here without new inputs: the only even modulus above 12 is `2^63`, a power of 2; few coprime pairs have `a > m ≥ 2^63` with a nontrivial residue; and no modulus lies between 97 and `10^9 + 7` or between about `2^39` and `2^61`.  Algorithm X does not branch on parity or on the size of the modulus, so these gaps would affect only a different method.
