# The gamma function

[The implementation](Program.lean) ports CORE-MATH's `cr_tgamma` [1, 2], using [the software fused multiply-add](../../Arithmetic/Fma/README.md).  `TgammaWithin.tgamma_within` proves one representable step from nearest-even rounding of `Real.Gamma` at every finite input except zero and the negative integers.  The proof discharges the approximation and path hypotheses of `TgammaFinal.tgamma_within_one`.  [The byte theorem](TgammaBytes.lean) carries the bound to the compiled module, and [the file theorems](TgammaFile.lean) identify `build/verified/tgamma.wasm`.

## Specification

`tgamma` computes `Γ` of the value of its argument.  [Mathlib's `Real.Gamma`](https://github.com/leanprover-community/mathlib4/blob/85e3a25e006c35636f0e53b0e9296caca2685bc0/Mathlib/Analysis/SpecialFunctions/Gamma/Basic.lean) is Euler's integral (DLMF 5.2.1) [4] for positive arguments, extended to the other reals by the recurrence `Γ (s + 1) = s Γ (s)`, and it takes the value 0 at zero and the negative integers by convention (`Real.Gamma_neg_nat_eq_zero`) [5].  The poles are therefore outside the domain of the accuracy statement, and their results are exceptional values.  The domain of the bound is every finite double other than zero and the negative integers.

The decided statement for such an `x` is `F64SignedRounding.WithinSteps 1 (Real.Gamma (value x.toBits)) (Tgamma.tgamma x).toBits`, with `WithinSteps` from [the signed rounding reference](../../../../LeanExe/ProofKit/F64SignedRounding.lean) as for the other functions: the word is not a NaN, and its position on the ordered line of doubles lies within one step of the position of the signed nearest-even reference.  The reference is `±∞` beyond the overflow threshold `2^1024 - 2^970` of IEEE 754-2019 clause 4.3.1 [6], which `Γ` crosses at about 171.62, and `±0` at or below half the smallest subnormal, which holds for every non-integer `x ≤ -184`.  The bound is the decision of 2026-10-10 recorded in [the journal](../../../../devnotes.md#2026-10-10-decisions-after-the-review-of-gamma-bessel-and-worst-inputs) and in [the plan](../../../../transcendentals.md#decisions), and the review of the same day recommended the special values in the table.

| Input | Result of the port | Source of the rule |
|---|---|---|
| `+0`, `-0` | `+∞`, `-∞` | C99 F.9.5.4 [7]; POSIX [8] |
| a negative integer | the canonical NaN | C99 F.9.5.4; POSIX on IEC 60559 systems |
| `-∞` | the canonical NaN | C99 F.9.5.4; POSIX |
| `+∞` | `+∞` | C99 F.9.5.4; POSIX |
| NaN | the canonical NaN | C99 F.9 paragraph 11; the deterministic profile of WebAssembly [9] |
| `x ≥ 0x1.573fae561f648p+7` | `+∞`, as `0x1.fp1023 + 0x1.fp1023` | overflow, POSIX |
| non-integer `x ≤ -184` | `±0` with the sign of `Γ x`, as `2^-1022 · (±2^-1022)` | underflow, POSIX |
| `x = 2^-1024` | `+∞`, as `0x1.fffffffffffffp+1023 + 0x1p+970` | overflow: `Γ x` exceeds the threshold |

IEEE 754-2019 lists no gamma function among its recommended operations [6], so C99's Annex F and POSIX fix the special values.  The port's NaN results are the canonical NaN, as every NaN result of the dialect is.  CORE-MATH sets `errno` when built with `CORE_MATH_SUPPORT_ERRNO` and raises the floating-point exceptions of these paths, and the port does neither.

## Algorithm

CORE-MATH's method evaluates `Γ` in double-double arithmetic, a pair `h + l` of doubles, with an explicit error bound `eps` for each path.  The project's paper describes the method: a fast path computes an approximation `y` with an error bound `ε`, a rounding test checks whether `[y - ε, y + ε]` crosses a rounding boundary, and otherwise an accurate path returns the correctly rounded value [3].  In `cr_tgamma`, when `h + (l + eps)` and `h + (l - eps)` round to the same double, the fast path returns that double, and otherwise `as_tgamma_accurate` evaluates `Γ` to about 100 bits, with a table of 57 hard cases for the inputs whose rounding test that path fails.  The structure below comes from the source [1].

| Range | Fast path |
|---|---|
| `\|x\| < 2^-112` | `1/x`, the leading term of `Γ x = 1/x - γ + ⋯`, and the correction for an exact `1/x` changes only the inexact flag and the directed roundings |
| `2^-112 ≤ \|x\| < 1/4` | `1/x` plus a polynomial of degree 20 in `x`, whose constant term is `-γ` |
| `-3 ≤ x ≤ 4`, not an integer | a polynomial of degree 17 in `d = x - (i + 3.5)` that approximates `Γ` on `[3, 4]`, divided by the product `x (x + 1) ⋯ (x + m - 1)` of the shifts that carry `x` there, the recurrence of DLMF 5.5.1 [4] |
| positive integers | `(x - 1)!` as a product in double-double, rounded once |
| `4 < x < 0x1.573fae561f648p+7` | `exp (lgamma x)`, with `lgamma` from Stirling's series (DLMF 5.11.1) by `as_lgamma_asym` and the exponential by `as_expd`, both in double-double |
| `-184 < x < -3`, not an integer | the reflection `Γ x = π/(sin (π x) Γ (1 - x))` (DLMF 5.5.3), with `Γ (1 - x)` from Stirling's series and `sin (π x)` from `as_sinpid`.  Below -170 the code tests whether the result is subnormal and then rounds it at the subnormal position. |

The accurate path `as_tgamma_accurate` uses polynomials in triple or double-double arithmetic, a series of 28 double-double terms below `1/4` and polynomials on nine ranges above it, and rounds once.  The fast path's error bounds, such as `1e-21` relative on `[-3, 4]` and `2e-21 + 1.84e-22 x` relative above 4, are constants of the source, and no Lean proof establishes them.  The decided one-step bound needs a proof that every path's error stays below one and a half spacings of the result, at least `1.5 · 2^-53 ≈ 1.7e-16` relative, about five orders of magnitude weaker than the bound `1e-21` that the rounding test on `[-3, 4]` assumes.

## Implementation

The source is `src/binary64/tgamma/tgamma.c` of CORE-MATH [1], `Copyright (c) 2024 Alexei Sibidanov`, under the MIT license [2].  The module docstring of [the implementation](Program.lean) quotes the copyright and permission notice of `tgamma.c` verbatim, as the license requires in all copies or substantial portions.  The port follows the C code operation for operation in the Verified dialect, the subset of Lean that [the Verified compiler](../../../../Verified/README.md) translates to WebAssembly.  The `verified_compile` command lists 40 functions: the 14 of `Fma` and 26 of this module, among them the double-double operations `fastTwoSum`, `twoSum`, `fastSum`, `sumDD`, `mulDD`, `mulDD3`, `mulDDD`, and `polyDDD`, the helpers `asLogd`, `asExpd`, `asSinpid`, and `asLgammaAsym` for the logarithm, the exponential, `sin (π x)`, and Stirling's series, `database`, `accurate`, `tgammaWith`, and `tgamma`.

| C code | Port | Reason |
|---|---|---|
| a second result through a pointer | a pair result | The dialect has no pointers. |
| global `static const` tables | eight `Array UInt64` tables passed by `tgamma` to `tgammaWith` | The tables become borrowed arrays of the module. |
| integers `i`, `jm`, `ip`, `k` that count or select | integer-valued doubles | The dialect's words are unsigned 64-bit integers. |
| `int` exponents `e`, `eoff` and the index of `as_expd` | two's complement words, with `sar` for the arithmetic shift | The same reason. |
| `__builtin_fma` | `Fma.fma`, at all 15 calls | WebAssembly has no scalar fused multiply-add, and in the deterministic profile its relaxed SIMD multiply-add returns the unfused result [9]. |
| `roundeven_finite`, `floor` | adding and subtracting `2^52`, and `floorF` from it | The dialect has no operation that rounds to an integer. |

| `errno`, `raise_underflow`, `feraiseexcept` | omitted, with the expressions evaluated for their flags kept | WebAssembly has no floating-point status flags. |
| `verified_compile` | present | The command checks the encoding one function at a time, and the module's build needs about 1.9 GB, within the runner's default 4 GB, as the Proof section describes. |

## Theorems

`TgammaWithin.tgamma_within` states `WithinSteps 1` against `Real.Gamma` for every finite `x` other than 0 and the negative integers, and its axiom report lists only `propext`, `Classical.choice`, and `Quot.sound`.  The module defines `compiled` with `verified_compile`.  [The byte theorem](TgammaBytes.lean), `TgammaBytes.tgamma_bytes_accuracy`, has the form of `ExpTheorem.exp_bytes_accuracy` with the eight tables borrowed: the bytes decode to the module, whose function 41 is the export `tgamma`, and a call from a ready store returns `(Tgamma.tgamma x).toBits` without a trap, leaves a ready store, and lies within one step of `Γ x` for finite `x` other than 0 and the negative integers.  [The file theorem](TgammaFile.lean), which `tests/verified/run.sh` checks against the `tgamma.wasm` it writes, takes the module from `tgamma_bytes_accuracy`, so its axiom report covers the byte theorem, and the run also checks [the accuracy](../../../../tests/TestSupport/Numerics/TgammaAccuracy.lean) natively.  `FmaSpecTheorem.fma_nearest` states that [the software fused multiply-add](../../Arithmetic/Fma/README.md) returns a nearest double to `a · b + c`, which is the hypothesis `FmaSpec.FmaNearest` of every path of the proof.  The Proof section lists the mathematical facts toward the accuracy theorem.

`TgammaSpecial` proves the exceptional results at `±0`, `±∞`, and NaN, for `tgammaWith` with any tables and hence for `Tgamma.tgamma`.  `tgamma_pos_zero` and `tgamma_neg_zero` give `+∞` and `-∞` at `+0` and `-0`, `tgamma_pos_inf` gives `+∞` at `+∞`, and `tgamma_neg_inf` and `tgamma_nan` give the canonical NaN at `-∞` and at every NaN.  Their axiom report lists only `propext`, `Classical.choice`, and `Quot.sound`.  `TgammaSmallPath.smallPath_within` proves the fast path from `2^-112` to `1/4` in magnitude within one step of `Γ`, from the hypotheses `FmaSpec.FmaNearest` and `TgammaApprox.SmallFact` and the hypothesis that the accurate path is within one step at the same input, which covers the case where the rounding test sends the input there.  `TgammaMainPath.mainPath_within` proves the path on `(-3, 4)` within one step for every finite non-integer `x` with `-3 < x < 4` and `|x| ≥ 1/4`, from `FmaSpec.FmaNearest`, `TgammaApprox.MainFact`, and the accurate path at the same input.

Four more paths are within one step without the accurate path: `TgammaTiny.tinyPath_within` covers every nonzero finite `x` below `2^-112` in magnitude, `TgammaInt.intPath_within` the integers from 1 to 171, `TgammaEdge.overflowPath_within` every argument from `0x1.573fae561f648p+7` on, where the result is `+∞`, and `TgammaEdge.underflowPath_within` the non-integers at or below -184, where the result is a zero.  `TgammaEdge.intPath_neg` gives the canonical NaN at the negative integers.  With `TgammaSpecial`, these theorems cover every row of [the Specification's table](#specification): the last three rows within one step of `Γ`, without a statement of the word.  `TgammaAsym6.asLgammaAsym_spec` puts `asLgammaAsym` within `2^-60` of `log Γ`, the first stage of the paths above 4 and below -3, from `FmaSpec.FmaNearest`, `TgammaApprox.StirlingFact`, and `TgammaAsym1.LogdSpec`, which `TgammaLogd.asLogd_spec` implies.  `TgammaLarge.largePath_within` proves the path from 4 to `0x1.573fae561f648p+7` within one step, and `TgammaReflPath.reflPath_within` the path from -184 to -3, each from the accurate path at the same input and the hypotheses below.

`TgammaLarge.largePath_within` takes `FmaSpec.FmaNearest`, `TgammaApprox.StirlingFact`, `TgammaApprox.ExpFact`, `TgammaAsym1.LogdSpec`, the accurate path at the same input, and `TgammaLarge.GammaBelowT0`, the bound `Γ ≤ 2^1024 (1 - 2^-50)` at the double below the threshold, which `GammaBelowT0.gamma_below_t0` proves.  `TgammaReflPath.reflPath_within` takes `FmaSpec.FmaNearest`, `TgammaAsym1.LogdSpec`, `StirlingFact`, `ExpFact`, the accurate path at the same input, and two hypotheses that other tracks prove: `TgammaRefl4.SinpidSpec`, the specification of `asSinpid` at the doubles `n/2^53` of `(0, 1)` with a relative error of `2^-58` and a low part below `2^-50` of the high part (track `expm1`), and `TgammaRefl4.SubnormalGap`, which `GammaSubnormal.subnormal_gap` proves.  `SinpidSpec` takes the grid `n/2^53` of `TgammaSinpid.asSinpid_spec`, which holds the fractional part `k/2^51` of every double below -2 (`TgammaRefl4.fract_grid`), and `TgammaSpecs.sinpidSpec` and `TgammaSpecs.logdSpec` derive `SinpidSpec` and `LogdSpec` from `asSinpid_spec` and `TgammaLogd.asLogd_spec` with `FmaSpecTheorem.fma_nearest`, `SinFact`, and `LogFact`.  `TgammaFinal.tgamma_within_one` proves `Tgamma.tgamma` within one step of `Γ x` for every finite `x` other than 0 and the negative integers, with `FmaSpec.FmaNearest` discharged by `FmaSpecTheorem.fma_nearest`, from `SmallFact`, `MainFact`, `StirlingFact`, and `ExpFact`, the hypotheses `LogdSpec`, `SinpidSpec`, `GammaBelowT0`, and `SubnormalGap` above, and `TgammaFinal.AccurateWithin`, the accurate path within one step at the inputs where the fast paths call it.  `TgammaFinal.tgamma_neg_int` gives the canonical NaN at the negative integers.  `TgammaAccSmallPath.accurate_small_within` proves the accurate path within one step below `1/4`, `TgammaAccPath.accurate_range_within` from `1/4` on under `DbWithin`, the database's values within one step, and `TgammaAccDb.db_within` proves `DbWithin`.  `TgammaAccPath.accurate_within` joins them into `AccurateWithin`, and `TgammaWithin.tgamma_within` discharges every hypothesis of `tgamma_within_one`.

## Proof

`FmaSpecTheorem.fma_nearest` supplies exact fused multiply-add.  Mathlib supplies `Real.Gamma`, the recurrence `Real.Gamma_add_one`, and Euler's reflection formula `Real.Gamma_mul_Gamma_one_sub` [5], and ProofKit supplies the real-argument Stirling remainder bounds of DLMF 5.11(ii) [4].  The error analysis covers each fast path, the accurate path, and the 57 hard cases against one and a half spacings, including subnormal results below -170 and the overflow and underflow boundaries.  The byte and file theorems carry the result to the compiled module and its emitted file.

[The review of 2026-10-10](../../../../devnotes.md#2026-10-10-review-of-the-options-for-stages-7-and-8) proposed the shared FMA proof, and [the decision of 2026-10-12](../../../../devnotes.md#2026-10-12-integration-of-expm1-tanh-erf-log1p-atan-atan2-asin-and-acos-first-push) set the one-step bound.  The shared gamma foundations are the six modules `GammaBasic`, `GammaStirling`, `RatExpLog`, `GammaThresholds`, `TaylorModel`, and `GammaModels` in `LeanExe/ProofKit`.  Their 42 axiom reports list only `propext`, `Classical.choice`, and `Quot.sound`, and [the journal](../../../../devnotes.md#2026-10-11-foundations-for-core-maths-tgamma-and-lgamma-track-erf-debtop1) lists the facts with the C source lines that use them.  The table gives the results that `tgamma`'s proof uses.

Stirling's remainder comes from Mathlib's limit `Real.BohrMollerup.tendsto_log_gamma` and Stirling's formula for `n!`: the remainder `R` satisfies `R y - R (y + 1) = ρ y` with an elementary `ρ`, the kernel bounds `ρ` by a proved polynomial inequality in `1/y`, and the bound telescopes.  Each fact about a CORE-MATH polynomial then becomes a kernel check of Taylor models on pieces of its interval.  The one-step bound needs about `2 ^ -60` relative error per approximation, so each fact is proved to that precision, which is weaker than the `1e-21` of CORE-MATH's rounding test.

[The approximation statements](TgammaApprox.lean) state eight facts, built from the exact values of the table words: `SmallFact` and `MainFact` for the fast path's polynomials below `1/4` and on `[3, 4]`, `AccSmallFact` and `AccRangeFact` for the accurate path's polynomial below `1/4` and its nine ranges against `Real.Gamma`, `StirlingFact` for the two Stirling fits of `as_lgamma_asym` against `log Γ`, and `LogFact`, `ExpFact`, and `SinFact` for the kernels, tables, and constants of the logarithm, the exponential, and `sin (π x)`.  In the first version of the statements, each tolerance left a factor of at least 8 over the largest error that a 90-digit evaluation found at dense sample points, while the analysis needs only a total relative error well below `2^-53` before the final rounding.  `MainFact` covers `|d| ≤ 1/2 + 2^-50`, because the code rounds `x - 7/2` before it chooses the nearest integer, so that `d` exceeds `1/2` by up to `2^-51`, at `x = 1 - 2^-53` for example.  `ExpFact` states the kernel of `asExpd` for `|X| ≤ 5/8` in place of `|X| ≤ 513/1024`, with the same tolerance `2^-74`: `asLogd` returns a low part up to `2^-22` without renormalizing it, the product in `asLgammaAsym` turns that into a low part up to about `2^-14.5`, and the first product of `asExpd` carries it into the kernel's argument, up to about `0.566`.  A 60-digit sampling of the kernel at 4001 points of each interval gives a largest error of `2^-76.89` on `[-5/8, 5/8]`, a factor above 7 below the tolerance.  The journal records that the 57 hard cases need no separate statement, since `AccRangeFact` and an exact evaluation at those arguments bound `Γ` there.

The floating-point proof, assigned to track `arc`, takes as hypotheses the eight approximation statements that `Library/Numerics/Float64/Tgamma/TgammaApprox.lean` defines, with the widened `MainFact` (`SmallFact`, `MainFact`, `AccSmallFact`, `AccRangeFact`, `StirlingFact`, `LogFact`, `ExpFact`, and `SinFact`).  `TgammaFacts.allFacts` proves them.  `TgammaFactsBase` reads the coefficient lists from the port's tables with the same definitions as `TgammaApprox`, so each theorem below has the type of the corresponding statement up to unfolding.  The models use Mathlib's 20-digit bounds on `π` where `π` enters only through `ln (2π)/2`, and `GammaPi` gives `π` within `2 ^ -128` from `TrigPi` for the kernels and tables of the sine. With its `verified_compile` call, the module's build first ran 25 minutes of CPU time at the runner's limits of 4.2 GB of memory and 1 GB of swap before `tools/leanrun` stopped it.  Probes that chain `let (h, l) := mulDD …` bindings showed the objects of the generated program growing from 5,093 at 10 bindings to 15,413 at 20, and a probe of 40 bindings exhausted the memory ([the journal](../../../../devnotes.md#2026-10-11-a-software-fused-multiply-add-core-maths-gamma-functions-and-fdlibms-bessel-functions)).  The first change shares the expression of the context, which `Ctx.ctx` in `Verified/Reflect/Command.lean` had rebuilt at each of its 23 uses, and the second computes the live variables of each subexpression as data, which `Expr.code` in `Verified/Compile.lean` had kept as a chain of closures.  The kernel's check that the module encodes then still needed about 5 GB, which the runner's option `--memory-high` allows, and a further change fixes the proofs of matches on a call's result, which had made the kernel evaluate that call ([the journal](../../../../devnotes.md#2026-10-13-the-kernels-evaluation-in-a-match-on-a-call-and-the-four-large-modules-coordinator)).  The module then compiled in about 121 s at 5.6 GB.  The check of one function at a time, which the user decided on 2026-10-12, removes the dependence on the module's size: the command checks the encoding one function at a time, with the bytes of each part from a native evaluation of the encoder, which brings the module's build from 5.5 GB to 1.9 GB of anonymous memory ([the journal](../../../../devnotes.md#2026-10-14-the-kernel-check-per-function-implementation-track-ports-minideb1)).

## Tests

[The accuracy check](../../../../tests/TestSupport/Numerics/TgammaAccuracy.lean) compares `Tgamma.tgamma` natively with the double nearest to `Γ x` from [the gamma reference](../../../../tests/TestSupport/Numerics/GammaReference.lean), and it fails at the first result more than one step away.  Its 74,373 arguments are 30,001 evenly spaced values from -185 to 172 and 20,001 from -4 to 5, 20,000 hashed values over the exponents from `2^-1074` to `2^7` with both signs, the integers from -200 to 172, the five doubles at and around each integer from -190 to 172 and each half-integer from -189.5 to 172.5, the doubles around the thresholds `2^-112`, `1/4`, 3, 4, `0x1.573fae561f648p+7`, and -184 and their negations, the 57 hard cases and their neighbors, the ten inputs of `WorstCases.tgamma`, and 13 special values.  The ten worst-case inputs give the largest known `tgamma` errors in Tables 4 to 11 of Gladman, Innocente, Mather, Ozaki, and Zimmermann's report [10], whose Table 3 lists 0.500 units for GNU libc 2.44 and 1.03e3 for FreeBSD 15.1.  The fast paths rarely reach the accurate path, so the check also calls `Tgamma.accurate` directly at every eighth argument from -184 to 171 above `2^-112` in magnitude, other than the integers, and at the 57 hard cases, 7,002 arguments.

The reference computes `lgamma y` for `y > 0` as `lgamma (y + N) - ln (y (y + 1) ⋯ (y + N - 1))` with `y + N ≥ 300`, Stirling's series with 60 terms and a remainder below `2^-650`, and one logarithm of the exact product, and for `x < 0` the reflection with `Reference.sinCosTurns`.  `Γ` is the exponential of `lgamma` with the sign of `sin (π x)`.  The Bernoulli numbers come in exact fractions from the algorithm that the module attributes to Akiyama and Tanigawa, and a Python model of the reference at 600 bits gave the same doubles as compiled CORE-MATH at 3,500 arguments.  The truncation errors are stated in docstrings and are not proved.

In a run of `tests/verified/run.sh`, all 74,373 results equal the reference, so the largest measured distance is 0 steps against the decided bound of 1, and the 7,002 results of the accurate path also equal the reference.  An earlier run gave the same results.  The runs use the module built without its `verified_compile` call, so they test the Lean function that the compiler will translate, and no compiled WebAssembly.

## Limits

`TgammaBytes.tgamma_bytes_accuracy` has the limits of the compiled functions, as for [the exponential](../Exp/README.md#limits): Talos and the decoder are trusted, the file theorem trusts `binary_file%`, the theorem covers the canonical NaN argument only, and a host that calls another export of the module or writes its tables between calls to `tgamma` needs a theorem that the action preserves `Ready`.  The port depends on `Fma.fma` at every path, which `FmaTheorem.fma_toBits` proves equal to IEEE 754's fusedMultiplyAdd for every operand triple, and `tests/verified/run.sh` also runs its native check, `FmaAccuracy.lean`, at 763,816 triples.

The proved bound permits one representable step from nearest-even rounding.  A correct-rounding theorem would require proving that every chosen result, including the hard-case table entries, equals nearest-even rounding.  The port drops `errno` and the floating-point exceptions, which C99 and POSIX specify for poles, overflow, and underflow.
