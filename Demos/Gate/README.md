# Gate: chi-square gating and certified track association

The demo serves the association of observations with tracks in the maintenance of a catalog of space objects.  [The module `chisquare`](Program.lean) encloses the chi-square distribution function and its tail at a point and encloses the quantile at a probability, from which a tracker sets the threshold of a validation gate and learns the probability that a true association falls outside it.  [The module `gate`](GateProgram.lean) evaluates the gate: it shows an innovation covariance positive definite, encloses the squared Mahalanobis distance of an innovation, and compares it with the threshold.  [The module `assignment`](Assignment.lean) checks that an assignment of observations to tracks, which an unproved solver proposes with a dual certificate, has the least total cost of every admissible assignment.  Every theorem concerns the accepted results only: an interval that a program returns contains the exact value of the model for the real values of the inputs, and an assignment that the check accepts is optimal for the integer costs that it reads.

[The requirements](requirements.md) state the models, the interface, the method, and the tests, and [the review](review.md) records the decisions and the findings of their independent review.  `verified_compile` compiles the module `chisquare` into 50,638 bytes, `gate` into 8,596 bytes, and `assignment` into 3,138 bytes.  In Wasmtime they agree with native Lean, bit for bit, on 1,461, 325, and 389 generated calls.  The oracle tests compare the programs with mpmath at 50 digits, with exact rational arithmetic, and with assignment solvers that compute no dual values.

## The models

The chi-square distribution with `k` degrees of freedom is Mathlib's Gamma distribution with shape `k/2` and rate `1/2`, `Model.chiSquare k = gammaMeasure (k/2) (1/2)`, since Mathlib has no chi-square distribution.  `Model.cdf k x` is Mathlib's distribution function of that measure, and `Model.tail k x` the measure of `(x, ∞)`, so `Model.tail k x = 1 - Model.cdf k x`.  For `x ≥ 0` and `y = x/2`, with `T(a, y) = exp(-y) y^a / Γ(a + 1)`,

`Model.tail k x = E_k(y) + Σ over j < ⌊k/2⌋ of T(a₀ + j, y)`,

where `a₀ = 0` and `E_k = 0` for even `k`, and `a₀ = 1/2` and `E_k(y) = erfc(√y)` for odd `k` (Abramowitz and Stegun 26.4.4 and 26.4.5).  [The model](Model.lean) proves the closed form from Mathlib's integral of the Gamma density: the fundamental theorem of calculus gives `Model.cdf 2 x = 1 - exp(-y)`, `Model.cdf 1 x = erf(√y)`, and the recurrence `Model.cdf (k + 2) x = Model.cdf k x - T(k/2, y)` for every `k ≥ 1`.  `erf` and `erfc` are those of `LeanExe.ProofKit.RealErf`, defined by the integral of DLMF 7.2.1.  The quantile at `p` is the unique `x` with `Model.cdf k x = p`, which exists and is unique for `0 < p < 1` because the distribution function is continuous, strictly increasing on `[0, ∞)`, and 0 at 0.

The squared Mahalanobis distance of an innovation `ν` under a covariance `S` is `Model.mahalanobis S ν = ν ⬝ᵥ (S⁻¹ *ᵥ ν)`, with Mathlib's matrix inverse.  The gate with threshold `γ` holds the innovations with `Model.mahalanobis S ν ≤ γ`.  When `ν` is normal with mean 0 and covariance `S` in `d` dimensions, the distance has the chi-square distribution with `d` degrees of freedom, so the probability that a true association falls outside the gate is `Model.tail d γ`.  That statement, `Model.gaussian_tail` of [the requirements](requirements.md#the-gate), is not proved, so the theorems state the gate's probability as `Model.tail d γ` and the Gaussian model's link to it is a premise of the reader.

An instance of the assignment has `n` rows, `n` columns, and an integer cost for each pair, or a mark that forbids the pair.  An admissible assignment is a permutation of the columns that uses no forbidden pair, and its cost is the sum of its pairs' costs.  A dual certificate `u`, `v` with `u i + v j ≤ c i j` for every allowed pair bounds the cost of every admissible assignment below by `Σ u + Σ v`, which is weak duality, so an admissible assignment whose pairs satisfy `u i + v (π i) = c i (π i)` has the least cost.  A tracker reduces the association of `m` tracks and `n` observations, with the costs of a missed detection and of a new track, to such a square instance with dummy rows and columns.

## Interface

```text
module chisquare
  cdf       k : UInt64, x : Float                  ->  status, lo, hi
  tail      k : UInt64, x : Float                  ->  status, lo, hi
  quantile  k : UInt64, p : Float, h : UInt64      ->  status, lo, hi

module gate
  gate      nu s : Array Float, g : Float          ->  status, lo, hi, verdict

module assignment
  check     c : Array Int64, perm : Array UInt64, u v : Array Int64  ->  status, row, col
```

`k` lies from 1 to 1,000, `x` is finite, `p` lies strictly between 0 and 1, and `h`, the number of halvings of each bisection, lies from 0 to 64.  `cdf` and `tail` return status 0 for every such input and status 1 otherwise.  `quantile` returns status 0 with an interval that contains the quantile, status 1 for an input outside the ranges, and status 2 when the enclosure at the bracket's upper end does not reach `p`, which no tested `p` up to `1 - 2⁻⁵³` gives.

`gate` takes the innovation `nu` of `d` values, `d` from 1 to 64, the covariance `s` of `d·d` values in row-major order, and the threshold `g ≥ 0`.  Status 1 marks an input outside these ranges, a value that is not finite, or an asymmetric `s`, and status 2 a covariance that the elimination does not show positive definite or an interval operation that rejects.  With status 0, `[lo, hi]` contains the squared Mahalanobis distance, and the verdict is 1 when `hi ≤ γ`, so the innovation lies inside the gate, 2 when `γ < lo`, so it lies outside, and 0 otherwise.

`check` reads the `n × n` costs `c` in row-major order, in which `2⁶³ - 1` forbids a pair, the assignment `perm`, which gives row `i` the column `perm[i]`, and the certificate `u`, `v`.  [The requirements' table](requirements.md#the-module-assignment) gives its statuses: 0 for an accepted assignment, 1 for a size outside `1 ≤ n ≤ 16,384`, 2 for a dual value outside `(-2⁶², 2⁶²)`, 3 for an assignment that is not a permutation through allowed pairs, 4 for a violated dual inequality, and 5 for a pair of the assignment that is not tight, with the row and column of the first failure.

`quantile 2 0.99 64` returns status 0 with `lo = 9.210340371976145` and `hi = 9.210340371976196`, around the quantile `9.2103403719761810` at the binary64 value of 0.99, and `quantile 1000 0.99 64` returns `[1106.968994352212, 1106.9689943522224]` around `1106.9689943522173`.  `tail 1000 1024` returns `[0.29208617287404115, 0.2920861728741849]` around `0.29208617287412165`.  `gate [3, 4] [1, 0, 0, 1] 25` returns status 0 with `[24.999999999999982, 25.000000000000025]` and verdict 0, since the distance 25 lies on the gate's boundary.  In Wasmtime on one core of an AArch64 host, a call of `quantile` at `k = 1000` with 64 halvings takes 0.05 seconds and a call of `gate` at `d = 64` takes 0.05 seconds, each with the module's compilation.

## Method

`tail` evaluates the closed form in [interval arithmetic](../../Library/Numerics/Interval/README.md), with the library's `exp` and `erfc`, each within one step of the nearest-even rounding of the real function and widened by two steps.  A loop of `⌊k/2⌋` steps adds each term to the sum and computes the next term from the ratio `T(a + 1, y) = T(a, y) · x / (2a + 2)`, with the integer divisor `2j + 2` or `2j + 3`.  Each term is clamped to `[0, 1]`, where `Model.term_le_one` places the real terms, so no finite `x` overflows.  The interval of `y = x/2` and that of `y/π` are clamped to `[0, x]`, since outward rounding moves the lower end of a product that rounds to 0 below 0, where a square root rejects.  Above `x = 1450`, near the end of the normal range of `exp(-x/2)`, `tail` returns `[0, upper end at 1450]`, which contains the tail because the tail decreases.  `cdf` is one less the tail.

`quantile` brackets the quantile by `[0, B]` with `B = k + 2√(40k) + 80`, where Laurent and Massart's inequality puts the tail below `exp(-40)`, and narrows the bracket by two bisections, as the radius program of [the conjunction demo](../Conjunction/README.md#radius-at-a-probability-ce-and-le) does.  Each halving takes the midpoint of the bit patterns of the two ends, so 63 halvings reach adjacent doubles from any bracket.  The first bisection keeps a lower end whose distribution function an enclosure shows below `p`, and the second an upper end whose distribution function an enclosure shows at least `p`.

`gate` checks the input, then eliminates the covariance and the innovation symmetrically in interval arithmetic.  Step `k` requires a pivot interval above 0, adds `r_k²/p_k` to the sum, and subtracts the multiples of row `k` from the later rows, with the new matrix and right-hand side built as new arrays.  The real counterpart of the elimination gives `ν' S⁻¹ ν = Σ r_k²/p_k`, and positive pivots show `S` positive definite: `Model.posDef_of_pivots` writes the quadratic form as `Σ p_m (y_m + Σ l_jm y_j)²`, and the last nonzero entry of a nonzero `y` makes one term positive.  The probability outside the gate depends only on `d` and `γ`, so a tracker computes `tail d γ` once for a gate while `gate` runs for each pair of a track and an observation.

`check` makes three passes and allocates nothing: the ranges of `u` and `v`, then for each row its column's range, its pair's mark, and its pair's tightness, then for every pair `t = i·n + j` the distinct columns of rows `i < j` and the dual inequality.  Every sum `u[i] + v[j]` of values in range is exact in `Int64` and below the mark, so the check needs no exception for a forbidden pair.

The proof of the tail follows the program: each interval contains its real quantity, the loop of `terms` keeps a partial sum of the closed form and its next term, and `Model.tail_closed` equates the closed form with the tail.  The proof of the gate keeps, after step `k`, every accepted entry of the interval matrix around the entry of `Model.elimA`, every entry of the right-hand side around `Model.elimR`, and the sum around `Model.quad`, with every pivot so far positive.  The proof of the check turns each pass into a statement about every index it covers, by induction on the loop, and the range of `u` and `v` makes the sums of `Int64` values the sums of their integers.

## Tests

`tests/verified/run.sh --cases chisquare`, `--cases gate`, and `--cases assignment` write the modules, validate them, compare them with native Lean on the generated cases, run the axiom audits, and check the file theorems.  The module cases of `assignment` omit the instance of size 100, whose costs exceed the length of one argument of the host's command line.

[`tests/gate/distribution.sh`](../../tests/gate/distribution.sh) compares `cdf`, `tail`, and `quantile` with mpmath's regularized incomplete gamma functions at 50 digits, on every `k` from 1 to 12 and `k` of 15, 30, 64, 100, 999, and 1,000, at points from −1 through the subnormal range and the quantiles of common gates to `1e300`, and on quantiles at probabilities from `1e-300` to `1 - 2⁻⁵³`.  All 1,209 checks pass: every input in range gives status 0 with an interval that contains the reference, and every width meets the bound of [the requirements](requirements.md#the-distribution-function-and-the-tail), with `u = 2⁻⁵³`: the tail's relative width from 0 to 1,450 is at most `8 (k + x + 10) u`, the distribution function's absolute width at most `4 (k + 10) u`, and the quantile's relative width at `p ≥ 1e-6` at most `2 (k + 10) u / min(p, 1 - p)`.  The largest width is 0.68 times its bound.

[`tests/gate/gate.sh`](../../tests/gate/gate.sh) compares `gate` with a reference that decides positive definiteness from the pivots of the elimination in exact rational arithmetic and computes the distance with mpmath at 50 digits.  Its 325 cases hold covariances of dimensions 1 to 6, 10, 32, and 64 with condition numbers from 1 to `1e12`, correlations of `1 - 1e-12`, matrices with a negative or a zero eigenvalue, every cause of status 1, overflows, and thresholds at the ends of an earlier interval.  All pass: every accepted interval contains the reference, every verdict follows its rule, no matrix that is not positive definite is accepted, and every positive definite matrix in the acceptance region of the requirements is accepted.  At `d = 64` the covariances with a condition number of `1e12` give status 2, and those up to `1e6` give status 0.

[`tests/gate/assignment.sh`](../../tests/gate/assignment.sh) runs the unproved solver of [the test support](../../tests/TestSupport/Gate/AssignmentCases.lean), the Hungarian method with potentials, on random instances of sizes 1 to 9, 16, 64, and 100 with costs up to `2⁴⁰` in magnitude and forbidden pairs, mutates its certificates, and checks each result against a model of the check written from the table of statuses and against the least cost from enumeration for `n ≤ 9`, dynamic programming over subsets for `n = 16`, and successive shortest augmenting paths with the Bellman–Ford method above.  All 399 checks pass: every certificate of the solver is accepted when an admissible assignment exists and gives status 3 otherwise, every accepted assignment has the least cost, and every invalid mutation is rejected with the status, row, and column of the model.

## Limits of the theorems

The theorems concern the stated models.  Whether an innovation is normal with mean 0 and covariance `S`, the realism of `S`, the choice of `γ` and of `p`, and the choice and the integer scaling of the costs are the caller's, and so are the solver and every converter.  The link between the multivariate Gaussian and `Model.tail` is not proved.  No theorem bounds a width: a wide interval is sound, its verdict is then 0, and a status other than 0 carries no statement.

The widths have the limits that the tests measure.  The distribution function, computed as one less the tail, loses relative accuracy where it is small, so a quantile at `p` below about `k · 2⁻⁵³` has an upper end where the distribution function reaches that level, and a gate's level `α = 1 - p` below `2⁻⁵³` cannot be expressed.  Above `x = 1450` the tail's interval is `[0, upper end at 1450]`, where the tail is at most `3.7e-19` for every `k ≤ 1000`.  Interval elimination widens its intervals at each step, so the gate shows fewer covariances positive definite as `d` grows: every covariance up to a condition number of `1e12` for `d ≤ 9`, and up to `1e4` at `d = 64`, by the review's sweep.
