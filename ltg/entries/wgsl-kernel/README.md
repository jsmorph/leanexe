# WGSL kernels from IR builds

Use this entry for a WGSL kernel.  `Project.WGSL.Module.print` prints a kernel in a restricted format, one space or newline between tokens, every number as eight hexadecimal digits, and every binary expression in parentheses, and `Module.parse_print` proves that `Module.parse` reads the text back as the kernel when its indices fit in eight digits; for a concrete kernel, `Module.parse_print_of_wfb` with `decide` gives the same.  `Module.invoke` runs one invocation on the read-only buffers and returns its stores to the read-write buffer, which it may not read; `Module.dispatch` applies the stores of invocations `0` to `count - 1` in order; and `Module.RaceFree` states that distinct invocations store to distinct words, which makes the order irrelevant under WGSL's memory model.

A kernel comes from the compiled body `seq (arraySize s src) (build dst limit index (get s) element)` of a function such as `LeanExe.build x.size.toUInt64 fun i => ...`.  A `Spec` names the parameters' kinds, the index and size locals, and the element, and `Spec.module` builds the kernel: one buffer per parameter, the index pair, the parameters' variables, a return when the index is not below the count, the element's translation (`trExpr`, one `let` per IR node), and the stores of the element's halves.  `Spec.dispatch_eq` proves the kernel from one fact, that `element.denote` gives `f k` for each `k` below the count.

The same fact proves the Wasm function: `Expr.eval_denote` turns it into `Stmt.build_spec`'s element hypothesis under `Agrees`, the locals and the arrays' `UInt64Array.At` below the scratch base.  `Project.Binary32.axpyArrayElement_denote` is such a fact, one `simp` call with `getElem!_map_toBits32` and `F32Bits`; `Project.Binary32.axpyArray32_implements` uses it through `Stmt.arraySize_spec` and `Stmt.build_spec`, and `Project.WGSL.axpyArrayKernel_dispatch` through `Spec.dispatch_eq`.

In proofs about one invocation, prove one lemma per statement and keep buffer contents behind hypotheses so that `simp` never unfolds `arrayWords`.  When a hypothesis states the value of a subexpression, `generalize` that subexpression before `simp`.  State `UInt32` facts through `toNat` (`UInt32.toNat_add`, `toNat_mul`, `toNat_sub`, `toNat_div`, `toNat_ofNat'`) and close them with `omega`, since `simp` rewrites `UInt32.ofNat (2 + 2 * n)` into `2 + 2 * UInt32.ofNat n`; generalize the halves of a `u64` before `simp` for the same reason.
