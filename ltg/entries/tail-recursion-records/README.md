# Tail recursion over represented arguments

Use this entry when a hint has rule `tail-recursion-loop` and a parameter has a recursive type, such as `sumAcc (acc : UInt64) : Words → UInt64`.  The compiler's template is the one for words: `while done = 0 do step`, with `result` and `done` in the first two variables, one temporary per parameter after them, and the fields that a `node match` loads in further variables.  `Func.tailIn_implements` proves `Implements` from `TailStepIn`, which states one run of `step` from parameter values `vs` that represent the arguments as borrowed in a fixed store.  The run either continues with values that represent new arguments with the same result and a smaller measure, or keeps the parameters and stores the result.

Unlike `Func.tail_implements`, the rule needs no injectivity of the arguments' values: its loop rule `Stmt.while_ghost` carries the measure as a ghost index in the invariant, `measure + 1` while running and 0 when done.  For a recursive argument, take `sizeOf` of the value as the measure; `simp` proves that a field is smaller.  The continuing branch must show that the next parameter values represent the next arguments: for a child field, the `NodeBorrowed` fact of the child from the record's `SlotsBorrowed` is that representation.  `Project.Words.sumAcc_step` is the worked example, 89 lines with every intermediate state named.  Arguments must be passed as a pair, `sumAccTuple (x : UInt64 × Words)`, as for `gcd`.
