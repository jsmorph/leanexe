# Calls between compiled functions

Use this entry when a hint has rule `call` or `call result`.  `leanexe_compile p := [f, g, …]` compiles the listed definitions into one module, with the runtime's `alloc`, `retain`, and `release` at indices 0, 1, and 2 and the listed function `i` at index `3 + i`.  A definition may call any other listed function.  The call graph is acyclic because a Lean definition refers only to earlier declarations and the compiler gives a recursive definition no callees.  The compiler translates a call to `Stmt.call index args results`, which evaluates the arguments, calls the function, and stores its results in fresh locals, the first result in the first local.

`Stmt.callImplements_spec` proves the call from the callee's `Implements` theorem at the same module, so the caller's proof does not repeat the callee's.  The caller supplies the evaluated argument words and a proof that they represent the callee's input as borrowed, together with the allocator invariant and room for the callee's need.  The rule returns values that represent the callee's result as owned, the arguments still borrowed, and every array borrowed or owned before the call kept with the same contents, which is the frame clause of `Implements`.  `compile_funcs` gives the function at index `3 + i` for the `hFunc` premise.

Give the callee's input explicitly with `(x := …)`, because the unifier cannot recover the scalar part of a tuple from `Scalar.values`.  The caller's `need` must cover the callee's.  State that inequality as a separate fact, proved with both need definitions unfolded, so that `omega` can use it for the room premise.  `Project.Clob.addBid_implements` is the worked example: a conditional whose branches call `addToLevel` or `insertLevel` and copy the two results into the result locals.
