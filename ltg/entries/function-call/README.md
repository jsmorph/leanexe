# Calls between compiled functions

Use this entry when a hint has rule `call` or `call result`.  `leanexe_compile p := [f, g, …]` compiles the listed definitions into one module, with the runtime's `alloc` and `release` at indices 0 and 1 and the listed function `i` at index `2 + i`.  A definition may call any other listed function.  The call graph is acyclic because a Lean definition refers only to earlier declarations and the compiler gives a recursive definition no callees.  The compiler translates a call to `Stmt.call index args results`, which evaluates the arguments, calls the function, and stores its results in the locals `results`, the first result in the first local.  A call that gives a function's result, directly or in a branch, stores into the result locals, and any other call stores into fresh locals.

`Stmt.callImplements_spec` proves the call from the callee's `Implements` theorem at the same module, so the caller's proof does not repeat the callee's.  The caller supplies the evaluated argument words and a proof that they represent the callee's input as borrowed, together with the allocator invariant, `Separate` for the blocks the callee consumes, and the memory cap.  The rule returns values that represent the callee's result as owned, the region clause of `Implements` as `Heap.Keeps` (every region of the caller's heap apart from the consumed blocks kept and apart from the result; see the `region-frame` entry), and the memory's maximum size unchanged.  A second call takes its allocator invariant and memory cap from the first call's postcondition.  `compile_funcs` gives the function at index `2 + i` for the `hFunc` premise.

Give the callee's input explicitly with `(x := …)`, because the unifier cannot recover the scalar part of a tuple from `Scalar.values`.  `Project.Clob.bid_spec` is the worked example of two calls in sequence: `findLevel` computes a position, and a branch calls another function.  `Project.Clob.pairCall_spec` proves once a call whose two arrays become the caller's result, for any result locals and any caller arguments, and `addBid_implements`, `cancelBid_implements`, and `applyCommand_implements` apply it.

Call arguments are typed expressions, so a call can pass floats.  A function of scalars whose body keeps the store can also be proved with `Func.implementsPure`, which concludes `ImplementsPure`: for every store, the call returns `f x` and leaves the store unchanged.  `ImplementsPure.implements` derives `Implements` from it.  `Stmt.callPure_spec` proves such a call where the store must not change, which is how a loop body or an element of `LeanExe.build` may call a function.  The compiler allows calls there only when every argument and result is a scalar, and it places the call's statement inside the loop body or element, before the expression that uses the result.  `Project.Gpt.softmax_implements` is the worked example: it calls `exp` in its sum loop and in each element.

A call may pass a value of a recursive type.  At a borrowed position it is a variable, and when the caller owns it, the caller lends it for the call: `NodeOwned.borrowed` gives the callee's `NodeBorrowed` premise, `NodeOwned.slotRegions_apart` gives `Separate` from the disjointness of the caller's owned trees, and `Heap.Keeps.node` gives the tree back owned after the call.  At an owned position it is an owned variable that occurs once among the call's tree arguments, or a call whose result the outer call consumes, and a value that such a call moves occurs in no other argument, so no call both lends and consumes a tree.  `Project.Trees.insertTwo_implements` applies `Stmt.callImplements_spec` with `insert_implements` twice and composes the two frames with `Heap.Keeps.trans`.  `Project.Trees.sizeSum_implements` calls `size` and then `sum` on the same borrowed tree: `Heap.Keeps.nodeBorrowed` gives the tree back from the first call's frame, with the positivity premise `EncodeSlotted.slotRegions_pos`, and `Func.implements_heap` closes the proof.  An owned tree comes back with `Heap.Keeps.node` (see the `region-frame` entry).  `Project.Trees.dropSmall_implements` lends its owned tree to `size`, whose premise is then `Separate.nil`, and `Heap.Keeps.rebuilt` joins `size`'s frame to each branch's `Heap.Rebuilt`.  `Project.Trees.addLeft_implements` lends the left child and consumes the right child in one call to `addRoot`: `NodeOwned.slotRegions_apart` gives `Separate`, the call's postcondition is a `Heap.Rebuilt` of the right child, and `Heap.Rebuilt.rightChild` stores the result into slot 2.

A result may be a pair whose components are trees.  The pair instance of `Represent` makes an owned pair two owned components whose blocks lie apart.  `Project.Trees.pickPair_implements` returns two consumed trees in either order: `Separate` places their blocks apart, and `Project.Trees.treePair_owned` builds the owned pair.
