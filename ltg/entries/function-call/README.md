# Calls between compiled functions

Use this entry when a hint has rule `call` or `call result`.  `leanexe_compile p := [f, g, …]` compiles the listed definitions into one module, with the runtime's `alloc`, `retain`, and `release` at indices 0, 1, and 2 and the listed function `i` at index `3 + i`.  A definition may call any other listed function.  The call graph is acyclic because a Lean definition refers only to earlier declarations and the compiler gives a recursive definition no callees.  The compiler translates a call to `Stmt.call index args results`, which evaluates the arguments, calls the function, and stores its results in the locals `results`, the first result in the first local.  A call that gives a function's result, directly or in a branch, stores into the result locals, and any other call stores into fresh locals.

`Stmt.callImplements_spec` proves the call from the callee's `Implements` theorem at the same module, so the caller's proof does not repeat the callee's.  The caller supplies the evaluated argument words and a proof that they represent the callee's input as borrowed, together with the allocator invariant and room for the callee's need.  The rule returns values that represent the callee's result as owned, the arguments still borrowed, every array borrowed or owned before the call kept with the same contents, which is the frame clause of `Implements`, and the memory's maximum size unchanged.  A second call needs room in the store the first call leaves: `Heap.Room.after` gives it from the caller's room, the first call's bound on `top`, and the unchanged maximum size.  `compile_funcs` gives the function at index `3 + i` for the `hFunc` premise.

Give the callee's input explicitly with `(x := …)`, because the unifier cannot recover the scalar part of a tuple from `Scalar.values`.  The caller's `need` must cover the callee's.  State that inequality as a separate fact, proved with both need definitions unfolded, so that `omega` can use it for the room premise.  `Project.Clob.bid_spec` is the worked example of two calls in sequence: `findLevel` computes a position, and a branch calls another function.  `Project.Clob.pairCall_spec` proves once a call whose two arrays become the caller's result, for any result locals and any caller arguments, and `addBid_implements`, `cancelBid_implements`, and `applyCommand_implements` apply it.

Call arguments are typed expressions, so a call can pass floats.  A function of scalars whose body keeps the store can also be proved with `Func.implementsPure`, which concludes `ImplementsPure`: for every store, the call returns `f x` and leaves the store unchanged.  `ImplementsPure.implements` derives `Implements` from it.  `Stmt.callPure_spec` proves such a call where the store must not change, which is how a loop body or an element of `LeanExe.build` may call a function.  The compiler allows calls there only when every argument and result is a scalar, and it places the call's statement inside the loop body or element, before the expression that uses the result.  `Project.Gpt.softmax_implements` is the worked example: it calls `exp` in its sum loop and in each element.
