# Encoded first-match UInt64 equality search

Use `FixedArrayFindIdxEq.program_spec` when a checked `leanexe.array.find-idx-eq.v1` equality identifies `FixedArrayFindIdxEq.program scratch key` followed by an arbitrary continuation.  The program copies the array pointer, loads its length, initializes the scan index and encoded result to zero, and enters a block-wrapped forward loop.  Each continuing step loads one `UInt64`, compares it with the literal `key`, stores `index + 1` and exits on a match, or increments the index and continues.

The theorem accepts any literal `UInt64` key, scratch position, trailing-local count, continuation program, and postcondition.  Its frame has the input pointer in combined local zero, the loaded item in combined local one, an empty operand stack, `scratch + 3 + tail` internal locals, and `2 ≤ scratch`, while `UInt64Array.At` supplies the flat one-word input.  The none callback receives `input.findIdx? (predicate key) = none` and `noneFrame`, and the some callback receives the first matching index equation, `index < input.size`, and `someFrame`.

The result word uses the compiler's option encoding: zero denotes no match, while `UInt64.ofNat index + 1` denotes `some index`.  The theorem covers the emitted one-word forward search from index zero, the literal predicate order `element == key`, and fallthrough into an arbitrary following program.  Length dispatch, allocation, result construction, wider elements, different local roles, dynamic keys, other predicates, and searches starting at another index require separate proof boundaries.
