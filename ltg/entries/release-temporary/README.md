# Release of a temporary array

Use this entry when a hint has rule `release-temporary`.  The compiler releases an array literal that it created for a fold right after the fold, with `Stmt.release src`, a call of `release` (function 1) on the pointer in local `src`.  `Stmt.release_spec` proves the call from a precondition that fixes the store and the state, given `Heap.At` for the store and `Heap.Owned` for the array.  The state is unchanged, and the store becomes `heap.releaseStore store ptr`.

`Heap.At.release` then gives the allocator invariant for `heap.release ptr capacity`, whose free list holds the freed block in address order, merged with the free blocks it touches.  The released heap keeps `top`, and `heap.releaseStore` keeps the page count, so the bounds that `Implements` requires carry over from the allocation.  `Heap.releaseStore_bytes` states that every byte outside the array's header is unchanged.  `Heap.Borrowed.release` and `Heap.Owned.release` keep every other array borrowed or owned, given that its region is disjoint from the freed object.  These three lemmas take `Heap.Object` for the freed object, its block facts without its contents, which `Heap.Owned.object` gives for an array and which a record also has; the `borrowedApart` and `ownedApart` facts of `Heap.NewArray` supply that for arrays that existed before the temporary was allocated.  Together they give the frame clause of `Implements`.

`release_run` proves the runtime `release` for this case directly on its WASM code: the null and magic checks, the reference count, the pending-list loop with one iteration, and the child-mask check that skips the slot scan when the mask is zero.  `freeObject_spec`, which it applies, holds for any locals of `release` (`ReleaseVars`) and any count word, so the release of a tree uses it too.  Its proof keeps header addresses in the form `UInt32.ofNat (ptr.toNat - k)` and states each bounds check as a negated comparison, because `simp` otherwise tries to evaluate `(ptr - k).toNat` and exceeds its recursion limit.  `Project.PairSum.pairSum_implements` is the worked example.

A `let` at the top of a function body may bind an array produced by a call or a build.  The compiler records it as a temporary, stores every result in a local, and releases the temporaries at the end of the function, in reverse order.  Releasing one requires that every array still live lies apart from it.  `Implements` provides that for a call's result: every object the result owns lies apart from each array borrowed or owned before the call (`Represent.outside`), and each owned array keeps its capacity.  A temporary passed to a later call is lent with `Heap.Owned.borrowed`.  `Project.Gpt.matVec2_implements` is the worked example, with one temporary between two calls.

The components of a call's pair result that are arrays, lists, or values of recursive types are owned temporaries too, bound when the code takes the pair apart at the top of the body.  A tree or list temporary is released at the end with the release function, which frees every record through the child masks: `Stmt.releaseNode_keeps` states that release as a `Heap.Keeps` step, and `Heap.Keeps.trans` joins it to the call's frame, since the call leaves the temporary's blocks fresh.  A projection of a call releases the call's other heap components right after it (`release dropped component`).  An owned pair variable with heap components moves when the code uses it whole, projects such a component, or takes it apart, so no heap component is used twice.  `Project.Trees.sizeAfterDrop_implements` releases a tree temporary at the end and `Project.Trees.sizeFirst_implements` after a projection, both through `Project.Trees.sizeDrop_call`; `Project.Trees.sizeDropNext_implements` passes the temporary through to the result and `Project.Trees.sizeDropSmall_implements` to a call that consumes it.
