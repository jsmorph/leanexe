# List fold loop

Use this entry when a hint has rule `list-fold-loop`.  The compiler translates `xs.foldl g init`, for a `List UInt64` parameter `xs` and a `UInt64` or `Float` accumulator, to two statements: an assignment of `init` to a fresh accumulator local, with hint `fold start`, and `Stmt.listFold list acc cursor element body`, where `body` is the translation of `g acc element`.  `Stmt.listFold` copies the list pointer to the cursor and, while the cursor is not null, loads the element from the record's first slot, assigns the body to the accumulator, and loads the next pointer from the second slot.  The value that contained the fold reads the accumulator, with hint `fold result`.  The three fold locals follow the parameters and any earlier fold's locals, in the order accumulator, cursor, element.

`Stmt.listFold_spec` proves the fold from the precondition `store = initial ∧ state = before`.  Its premises are the distinctness of the four locals and their bounds, by `decide`; enough locals in `before` to cover the scratch index; `ListAt initial.mem ptr xs`, which `NodeBorrowed.listAt` gives from the allocator invariant and a borrowed argument; the pointer and the starting accumulator in `before`; and `hBody`, which says the body evaluates to `g a e` when the element local holds `.i64 e`.  The loop's measure is `listLength`, the length of the unique list at the cursor, so no ghost argument is needed.  `Project.Lists.listSum_implements` is the worked example: the per-program proof is 20 lines, the same as `sumArray_implements` in the `array-fold-loop` entry.
