# Match on a value of a recursive type

Use this entry when a hint has rule `node match`.  A value of a recursive type with one constructor without fields and one with fields is a pointer: 0 for the first, and a record of the second's fields for the second.  The compiler translates a `match` on such a parameter to `Stmt.ite` on `get p = 0` (or `≠ 0` when the record constructor comes first).  The record's branch loads every field from slot `i` at `get p + 8 * i` into a fresh local, with hint `field load`, and each branch assigns its alternative's value to a fresh local, with hint `match value`, which the enclosing value reads (`match result`).  In tail position the branches end in a tail call or a base case instead.  The fieldless constructor as a value is the constant 0 (`null constructor`).

No rule lemma covers the template yet: `Project.Words.first_implements` proves it directly, in 52 lines.  Case on the value.  For the fieldless constructor, `NodeBorrowed` says the pointer is 0, the condition holds, and `Stmt.ite_spec` with `Triple.of_false` for the other branch leaves one assignment.  For the record, `NodeBorrowed` gives `RecordSlots` (nonzero, inside the 32-bit space, below `top`), each word slot's value, and each child's `NodeBorrowed`.  `slotAddress_toNat` and `Heap.At.top` discharge the bounds of `Stmt.load_spec`, and the load address `(p + 8 * i).toUInt32` equals `slotAddress p i` by `simp [slotAddress]`.  Name every intermediate state with `let` and close each step with `rfl`, as the proof does; `simp` on states built by several updates is slow.
