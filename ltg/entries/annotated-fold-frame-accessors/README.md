# Generated fold-frame accessors

A matched `leanexe.array.fold.v1` region emits `<region>_continuing_frame_params`, `<region>_continuing_frame_locals_length`, `<region>_continuing_frame_values`, and one `<region>_continuing_frame_get_<index>` theorem for every combined parameter-and-local index.  Each theorem states an exact property of the generated scalar frame and checks by reduction in the artifact annotation module.  The fold recipe lists these artifact-specific declarations, so search the recipe before unfolding `ScalarTransition.U64State`, `Wasm.Locals.get`, or the internal local list.

When an application defines a semantic abbreviation around the generated continuing frame, use `simp only [<semantic-frame>, <generated-accessor>]`.  The restricted simplifier unfolds the semantic abbreviation and applies the exact accessor without reducing `Wasm.Locals.get` first.  An unrestricted `simp` may expand that getter into parameter and internal-list branches before the generated theorem can match.

Use `FixedArrayFold.resultFrame_get_result` after accumulator placement to read the written result local.  Use `FixedArrayFold.resultFrame_get_of_ne` to preserve a distinct nonparameter local, including a result root needed by the singleton suffix.  Discharge their frame-length premises with the generated parameter and local-length theorems instead of unfolding the complete generated state.

Treat the first residual frame-projection goal as a new retrieval checkpoint, even when an earlier query selected the surrounding fold or result theorem.  Search the recipe for `_continuing_frame_` declarations and the category indexes for `exact-local-get` or `frame` before introducing a local fact by reduction.  Record whether an exact accessor matched so later analysis can distinguish retrieval failure from an absent theorem.
