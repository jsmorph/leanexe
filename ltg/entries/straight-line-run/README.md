# Straight-line statements by evaluation

Use this entry to prove a `Triple` for statements built from assignments, loads, sequences, and conditionals, such as a loop body or the assignments before a loop.  `Stmt.run mem scratch s state` computes the final state or fails, and `Stmt.run_spec` turns `s.run initial.mem scratch state = some final` into a `Triple` from `state` to `final` that keeps the store.  `State.update` is `State.set?` without the `Option`, so the final state is a chain of updates that `simp` can inspect.  When only the postcondition of a function body matters, `Stmt.run_triple` takes `∃ final, s.run … = some final ∧ post initial final`, which one `simp` call can prove outright.

Compute the effect with one `simp` call: the statement's definition, `Stmt.run`, `Expr.eval`, `State.set?_eq_update`, the state's parameter and local counts, the known values of the locals read, `U64Op.apply`, and `Expr.readValue_at` for each array.  `simp` discharges the index bounds of `State.set?_eq_update` from the counts, and `get_update_same` and `get_update_ne` read locals through the updates.  A conditional whose branches leave the same state, such as the one `min` compiles to, reduces by `ite_some_pair` and `update_update_same`.  State the lemma as `∃ final, s.run … = some final ∧ Frame … ∧ …`.  After `simp`, prove the frame by repeating `refine State.Frame.update ?_ (by simp)` and finishing with `State.Frame.refl`.  Trying `State.Frame.refl` first at each step times out, because the definitional check unfolds the whole update chain.  `Examples.Clob.body_run` is the worked example: the body of `marketBuy`'s loop, with two reads, in 16 lines.
