# Loop with a test and a step call

Use this entry when a hint has rule `repeat while`.  The compiler translates `LeanExe.repeatWhile fuel init cond step`, where `cond` compiles to an expression over the state and `step` is one call of a compiled function that consumes every array of the state, to `Stmt.repeatWhile states limit counter fuel condition idx args`.  The state lives in the locals `states`, one per component, an array as its pointer.  While the counter is below the fuel and the test holds, the call writes the next state into `states`.  When the test fails, the counter jumps to the fuel.  The template allocates and releases nothing, because the call consumes the old state's array and returns the new one.

`Stmt.repeatWhile_spec` proves the template for any state type: its invariant is the owned state and `Heap.Keeps` from the heap before the loop, with the memory caps unchanged.  `Live.repeatWhileOne` restates it for a state of scalars and one array (`OneArray`), the form of both loops of the first-order Euler solver, inside the `Live` invariant of a composite function: the state's array is the newest live temporary before and after the loop.  Its premises `hCond` and `hArgs` receive the state locals' values as `State.Holds` facts and the `Live` facts of the current step.  Parameters come from the frame premise.

The test and the step of the source are lambdas with pattern matches.  Restating them in a proof elaborates new matchers, and the definitional check between the restated loop and the definition's loop can expand the loop through its fuel.  Name them once with an existential lemma proved by `refine ⟨_, _, ?_, ?_, rfl⟩`, so that `rfl` assigns the definition's own lambdas first (`Project.Euler.advanceWith_loop`).  The loop's result then appears as an opaque `LeanExe.repeatWhile` application, which `generalize` replaces by a variable before the exit branches.  `Project.Euler.advanceWith_implements` and `Project.Euler.runFrom_implements` are the worked examples.
