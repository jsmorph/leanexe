# Index loop

Use this entry when a hint has rule `loop`.  The compiler translates `LeanExe.loop n init f`, whose state is a `UInt64`, a `Float`, or a pair of states, to assignments of `init`'s components to fresh state locals, with hint `loop start`, and `Stmt.loop limit index count body`.  The body evaluates each component of the next state into a fresh temporary, with hint `next state`, and copies the temporaries to the state locals, with hint `state copy`; a `have` in `f` becomes an assignment with hint `let`.  A pattern match on the state, such as `fun i (remaining, cost) => …`, binds its variables to the state locals and produces no code.

`Stmt.loop_spec` takes the state as a value of a `Scalar` type, held in the list of state locals by `State.Holds`.  Its premises are the distinctness and bounds of `limit` and `index`, by `decide`; the count's evaluation; the initial state held before the loop; and `hBody`, a `Triple` for one run of the body at index `k`.  Prove `hBody` with the `straight-line-run` entry: `Stmt.run` computes the body's effect by `simp`, and `Stmt.run_spec` turns it into the `Triple`.  Relate the source to `LeanExe.loop n init f` by `rfl` with a named step function; a pattern match on the state in the source unfolds to projections by structure eta.  `Project.Clob.marketBuy_implements` is the worked example.
