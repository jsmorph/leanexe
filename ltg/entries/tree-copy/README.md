# Copy of a tree

Use this entry where the compiler copies a tree.  An owned call position, or a value position such as a pair part, that receives a tree the code may not move receives a copy (`tree copy`, and `copy` at a value position): the tree is borrowed, a later part of the value uses it, or another array or tree argument of the call names it.  The copy is a call of the type's copy function at depth 0, or at the caller's depth plus one inside a recursive body, and the module command appends the function after the internal functions (`depth guard`, `tree copy function`).  `Func.copy layout index` is its IR for a record layout, `true` for a child slot and `false` for a word: the guard, 0 for the null pointer, and for a record the loads of its slots, a call on each child at the depth plus one, and a new record.

`Examples.Trees.copy_rec` is the theorem for `KeyTree`, whose layout is `[true, false, true]`, at any index of any module.  Its specification is `Rebuilds` for the identity on a borrowed tree, proved by `Func.rebuildRecursion` as in the `consumed-recursion` entry: the two calls are `Stmt.selfCall_rebuilds`, `Heap.Keeps.nodeBorrowed` keeps the right child through the first call, `Stmt.record_spec` gives the new record, and `Heap.Rebuilt.newNode` turns the two rebuilds and the record into the copy's `Heap.Rebuilt`, which consumes nothing.

`Examples.Trees.keepOld_implements` and `Examples.Trees.addSelf_implements` are the worked calls.  The copy call is `Stmt.selfCall_rebuilds` with `copy_rec`, its argument borrowed (`NodeOwned.borrowed` for an owned tree).  In `keepOld`, `incr` consumes the copy, and `Heap.Rebuilt.keepNode` and `Heap.Keeps.node` keep the original tree through both calls, so the result is an owned pair (`treePair_owned`).  In `addSelf`, `addRoot` reads the original and consumes the copy, and `treePair_args` builds the call's premises from the copy's region clause.  `Heap.Keeps.trans` composes the region clauses, since the second call consumes only the copy's blocks.
