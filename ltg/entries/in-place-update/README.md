# In-place array update

Use this entry when a hint has rule `set in place`, `erase in place`, `insert in place`, or `push in place`.  The compiler writes an owned array in its own block when `set!`, `setIfInBounds`, `eraseIdxIfInBounds`, `insertIdx!`, or `push` is the array's last use at a result position.  An update of a borrowed array, or one that is not the array's last use, copies with the `array-build` templates.  The position and value go into locals first, and may read the array.  The array argument may itself be an update, as in `(xs.push a).push b`: the outer update computes its position and value, then the inner update, and writes the inner result in place.  Each template writes the length word last, since `Expr.read` checks a position against the length in memory.

`Stmt.setInPlace_spec`, `Stmt.eraseInPlace_spec`, and `Stmt.insertInPlace_spec` prove the templates from `Heap.Owned` to `Stmt.AppendPost`, through `Stmt.AppendPost.inPlace` for writes inside the block.  The erase loop is `Stmt.fill` with the element `.read src (index + 1)`.  `Stmt.fill_inv` proves it under the invariant that the store holds `shifted xs k j`.  The insert moves the later elements up from the top down with `Stmt.shiftUp`, whose rule `Stmt.shiftUp_inv` counts down under an invariant of the store, here that it holds `shiftedUp xs i` and, below the top, the last element one place up.  `arrayAt_grow` then writes the longer length.  When the block is full, the insert first copies the array into a block of twice the capacity with `Stmt.growFill_spec`, the growth rule of `Stmt.append` with any element, and `Stmt.AppendPost.trans` composes that step with the in-place one.  `Project.Clob.insertLevel_implements` and `removeLevel_implements` chain two such updates, keeping the second array through the first with the owned-array clause of `Stmt.AppendPost`.

The growth step is its own template, `Stmt.reserve`, whose rule `Stmt.reserve_spec` leaves the array owned at the pointer in `src` with room for one more element.  `Stmt.insertInPlace_spec` composes it with `Stmt.insertShift_spec`, and `Stmt.pushInPlace_spec` with `Stmt.pushStores_spec`, which writes the element after the last and then the longer length through `arrayAt_grow`.  A proof in the `Live` framework turns each `Stmt.AppendPost` into a new `Live` with `Live.appendPost`.  `Project.Clob.stepCommand_implements` does this for two pushes in a row.
