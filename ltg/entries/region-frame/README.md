# Region frame of a call or a step

`Implements` ends with a region clause: every region of the heap before the call, below `top` and outside every free block (`Heap.Region`), that lies apart from the consumed blocks keeps its bytes, is still such a region, and lies apart from the objects of the result.  The guard `0 < r.2` excludes empty regions, which a release that merges free blocks can swallow.  Inside proofs the same clause is `Heap.Keeps heap initial gone heap' store fresh`, with the consumed blocks in `gone` and the new objects' blocks in `fresh`.  `Heap.Keeps.implements` converts between the two forms, and `apart_blocks` converts `Apart` over pointers to apartness from their blocks.

`Heap.Keeps.borrowed` and `Heap.Keeps.owned` give the caller's arrays back from a frame, with the same contents and, for an owned array, the same capacity.  They use the page-free lemmas `Heap.Borrowed.keepIn` and `Heap.Owned.keepIn`, which bound the array in memory through `Heap.Region` and `Heap.At.top`.  `Heap.Keeps.node` gives an owned value of a recursive type back with the same blocks, and `Heap.Keeps.nodeBorrowed` a borrowed one, whose records' slot regions (`Node.slotRegions`) must have positive length and lie apart from the consumed blocks.  `Heap.Keeps.trans` composes two steps when the second consumes only blocks the first leaves fresh, and `Heap.Keeps.mono` adjusts the lists.  `Heap.NewArray.keeps`, the frame of `Stmt.AppendPost`, `Heap.Keeps.release`, and `Stmt.callImplements_spec` state their steps in this form.

`Live` carries one such frame for a body: the caller's regions apart from the consumed parameters are kept and lie apart from the live temporaries.  `Live.step` adds a step that consumes some temporaries and adds new ones, and the rules `Live.call`, `Live.callMove`, `Live.releaseFirst`, `Live.push`, `Live.appendPost`, and `Live.callTuple` are each one application of it.  `Live.borrowed`, `Live.owned`, `Live.apartB`, and `Live.apartO` give the old array facts.  `Project.Clob.two_updates` composes two in-place updates by hand, and `Project.Gpt.generating_step` reads the weights back from `Implements`'s clause with `Heap.Borrowed.keepIn`.
