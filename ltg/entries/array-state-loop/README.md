# Loop over an array state

Use this entry when a hint has rule `array loop`.  The compiler translates `LeanExe.loop n init f`, where `init` is an `Array Float` variable and `f l x` is one call of a function compiled into the same module, to one statement, `Stmt.arrayLoop state size limit index next src idx count args`.  The statement copies the array at local `src` into local `state` with `Stmt.copy`, then runs `Stmt.loop limit index count` with a body that calls function `idx` with `args`, leaving the result in `next`, releases the array at `state`, and assigns `next` to `state`.  The copy makes the state an array the function owns whatever `init` is, so every iteration may release it.  The copy's hint has rule `array copy`, and the call's hints lie inside the loop body at `loopBodyLoc`.

`Live.arrayLoop` proves the statement in continuation form, as `Live.call_seq` proves a call: the proof of the statements that follow receives the heap, the state's pointer, the store, and the state after the loop.  It takes the callee's `Implements` theorem, the argument tuple as a function `F l x` of the index and the state, and `hArgs`, which proves that the arguments evaluate and represent `F l x` in any state that frames the state before the loop.  In `hArgs`, a parameter's value comes from the frame premise and the state before the loop, the state local's value and representation from the `Live` premise at the head of the temporaries, and the index from its own premise.

The body needs one scratch local for the copy, so the function's scratch width is 1, and the proof names the scratch index with `decide +kernel` before the bounds on the loop locals are proved by `decide`.  `Project.Gpt.forward_implements`, generated by [`tools/gpt_composites.py`](../../../tools/gpt_composites.py), is the worked example.
