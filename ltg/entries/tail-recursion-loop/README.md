# Tail-recursion loop

Use this entry when a hint has rule `tail-recursion-loop`.  The compiler turns a definition whose recursive calls are all in tail position into `while done = 0 do step`, with `result` in the first compiler variable, `done` in the second, one temporary per parameter after them, and scratch locals last.  `Func.tail_implements` proves `Implements` for such a function from `TailStep`, an obligation about one run of `step`.

Apply `Func.tail_implements` with the source function over a tuple of its arguments, a measure on the arguments that decreases on each recursive call, the extracted `step`, `arity` by `rfl`, an injectivity proof for the argument values, the variables' types as `List.replicate (k + 2) .u64` by `rfl`, and the loop and result shapes by `rfl`.  Then prove `TailStep`: from `tailState args result 0 others`, the body either continues at `tailState args' result' 0 others'` with `f args' = f args` and a smaller measure, or ends at `tailState args (f args) 1 others'`.

For `TailStep`, destructure `others` by its length into concrete values, apply the `if`, sequence, and assignment rules in the shape of `step`, split on the source condition, and let `simp` evaluate each branch with `tailState`, `Scalar.values`, `Expr.eval`, `State.get`, `State.set?`, the function's `ir`, and `Func.scratch`.  After `simp`, the base case usually needs the source equation at the base, and the recursive case needs the source equation at the step and the measure decrease.  `Project.Gcd.gcd_step` is the worked example.  Its proof is 29 lines, against 63 for the same program proved directly with `Stmt.while_spec`.  `Project.PrimeFactors.countFactors_step` evaluates a body of four branches with `Stmt.run_triple` and `eval_state` instead of the statement rules, with one source lemma per branch.
