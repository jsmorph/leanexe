# Binary64 arithmetic

Use this entry when a hint has rule `float add`, `float sub`, `float mul`, `float div`, `float sqrt`, or `float variable`.  The compiler translates Lean's `Float` operations to IR expressions of type `f64`, whose values are bit patterns: `Expr.getF` reads an `f64` local, `Expr.binF` applies `F64Op.apply`, which is Talos's `IEEE64.add`, `sub`, `mul`, or `div`, and `Expr.unF` applies `F64UnOp.apply`, which is `IEEE64.sqrt`.  These are the meanings of WebAssembly's `f64` instructions in the deterministic profile.  A `Float` argument or result is an `f64` holding `Float.toBits`.

A proof evaluates the translated expression with `simp [Expr.eval, F64Op.apply, ...]`, which leaves an `IEEE64` expression over the arguments' bits, and rewrites the Lean side with `F64Bits.toBits_add`, `toBits_sub`, `toBits_mul`, `toBits_div`, and `toBits_sqrt`.  Each states `(a ∘ b).toBits = IEEE64.∘ a.toBits b.toBits` for every pair of floats, NaN included, so the two sides meet without case analysis.  `Project.Axpy.axpy_implements` and `Project.ScaledHypot.scaledHypot_implements` are the worked examples; each proof is one `simp` call after `Func.implements`.

The theorems rest on `F64Add.add_eq`, `F64Sub.sub_eq`, `F64Mul.mul_eq`, `F64Div.div_eq`, and `F64Sqrt.sqrt_eq`, which compare Lean's `Float.Model` with `IEEE64` on all bit patterns, and on `F64Bits.ofBits_toBits`, which holds because every NaN in Lean's model is the canonical NaN.  Comparisons, negation, absolute value, and conversions have no binary64 theorems yet.
