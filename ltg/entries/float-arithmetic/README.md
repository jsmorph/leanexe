# Binary64 arithmetic, comparisons, and sign operations

Use this entry when a hint's rule starts with `float` or is `word to float`.  The compiler translates Lean's `Float` operations to IR expressions of type `f64`, whose values are bit patterns, evaluated with Talos's `IEEE64` functions, the meaning of WebAssembly's `f64` instructions in the deterministic profile.  `+`, `-`, `*`, `/`, and `Float.sqrt` map to single instructions.  `-x` compiles to `-0.0 - x`, which is exact and yields the canonical NaN for NaN, as Lean does.  `Float.abs` compiles to `f64.abs`, which agrees with Lean on every Lean float because Lean's only NaN is positive.  `min a b` and `max a b` compile to an `f64.le` comparison and a conditional, following Lean's definitions `if a ≤ b then a else b` and `if a ≤ b then b else a`.  A literal compiles to `f64.const` with bits the compiler computes.  A proof checks them with `decide`, as in `(0.5 : Float).toBits = 4602678819172646912`.

For a function without conditionals, `Func.implements` followed by one `simp` call with `F64Bits.toBits_add` and its siblings proves the result (`Project.Axpy.axpy_implements`, `Project.ScaledHypot.scaledHypot_implements`).  With conditionals, supply the result word and final state explicitly, unfold the IR with `dsimp only [p.ir, Func.scratch]` so the result's type reduces to `UInt64`, and evaluate with `simp [Expr.eval, State.get, F64Op.apply, F64UnOp.apply, source, F64Bits.beq_eq, F64Bits.lt_iff, F64Bits.le_iff]`.  Then case on each IEEE condition as a Boolean, `cases h : IEEE64.lt a b`, and finish each case with `simp` and the `toBits` lemmas (`Project.Piecewise.piecewise_implements`).  `split_ifs`, `simp_all`, and `ite_bind` inside the large `simp` call looped or timed out there.

The comparison theorems rest on `F64Compare.compare_canonical`: decoding a non-NaN bit pattern gives a canonical unpacked float whose value is Talos's `scaledValue`, and Lean's comparison of canonical floats orders them by value.  Negation rests on `F64Sign.sub_negZero`, and the arithmetic on the translated binary64 chain.  `UInt64.toFloat` compiles to `f64.convert_i64_u` (`Expr.convertU`) and `Float.toUInt64` to `i64.trunc_sat_f64_u` (`Expr.truncSatU`).  `F64Convert.toBits_toFloat` and `F64Convert.toUInt64_eq` state their agreement with Lean, including NaN and out-of-range inputs, and a proof adds them to the `simp` call (`Project.Bucket.bucket_implements`, `Project.Mean.mean_implements`).

`Float.ofBits w` compiles to `Expr.ofBits`, `f64.reinterpret_i64`, which keeps a NaN payload.  Lean's model replaces every NaN with the canonical NaN, so `F64Bits.toBits_ofBits` gives `(Float.ofBits w).toBits = w` only when `w` is not a NaN pattern, and a proof that uses `Float.ofBits` must show that.  `F64Bits.shiftLeft_52_not_nan` covers words built as `v <<< 52`, which is how `Project.Gpt.exp_implements` builds powers of two.  Unsigned division compiles with its operands stored in scratch locals, so a state after it includes those locals.
