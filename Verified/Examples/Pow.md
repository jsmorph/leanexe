# The power function

[The implementation](Pow.lean) exports `pow`, a port of Arm's optimized-routines `pow` [1, 2, 3] in its configuration without fused multiply-add, which computes `x^y` as `exp (y log |x|)` with a logarithm carried to about 15 bits beyond double precision and with the exponential's table of 128 values of `2^(j/128)` [4].  The decided bound is one representable step from the nearest-even rounding of `x^y`, as for [the exponential](Exp.md).  `transcendentals` contains the port, its accuracy check, and its WebAssembly module, and no theorem about `pow`.  Branch `w/exp2` proves the decided bound for every pair of finite `x` and `y` with a real value of `x^y` (`PowTheorem.pow_within`), the exceptional results of C99 Annex F with two deviations for signaling NaNs, the exponential part of the port for both signs of the result, the symmetry of rounding under negation, `checkint`, the byte theorems of the compiled module (`PowBytes.pow_bytes_accuracy`), and the file theorems for `build/verified/pow.wasm` (`PowFile`), and these results are not yet merged.

## Specification

`pow x y` computes `x^y` for doubles `x` and `y`.  For a positive finite `x` and a finite `y` the value is `exp (y log x)`, Mathlib's `Real.rpow x y`, and for a negative finite `x` it is defined only for an integer `y`, as `|x|^y` with the sign of `x` when `y` is odd.  The results overflow to `±∞` from the threshold `2^1024 - 2^970` of clause 4.3.1 of IEEE 754-2019 [9], and results of magnitude at most `2^-1075` round to `±0`.  The decided bound is one step, `F64SignedRounding.WithinSteps 1`, defined in [the signed rounding reference](../../LeanExe/ProofKit/F64SignedRounding.lean), which places both zeros at position 0 and measures the distance of a word from the nearest-even reference of a signed real number.  `PowTheorem.pow_within` on branch `w/exp2` states `WithinSteps 1 (Real.rpow x y)` for finite `x` and `y` with `x > 0`, with `x < 0` and an integer `y`, or with `x = ±0` and `y ≥ 0`, and the module `PowSpecial` on that branch states the exceptional results.  For `x < 0` and an integer `n`, `Real.rpow x n` equals `(-1)^n |x|^n` (`PowTheorem.neg_rpow`), the value of Annex F.

| Inputs | Result of the port | IEEE 754-2019 9.2.1 [9] and C99 F.9.4.4 [10] |
|---|---|---|
| `y = ±0` | 1, or `x + y` for a signaling NaN `x` | `pow (x, ±0)` is 1 if `x` is not a signaling NaN.  C99 gives 1 even for a NaN. |
| `x = +1` | 1, or `x + y` for a signaling NaN `y` | `pow (+1, y)` is 1 for any `y`, even a quiet NaN. |
| `x` or `y` NaN otherwise | `x + y`, the canonical NaN | A quiet NaN for a NaN operand (clause 9.2). |
| `x = -1`, `y = ±∞` | 1 | 1. |
| `y = ±∞`, `\|x\| ≠ 1` | `+0` for `\|x\| < 1` and `y = +∞` or `\|x\| > 1` and `y = -∞`, else `+∞` | The same.  IEEE 754-2019, C11, and C23 list `pow (±0, -∞) = +∞` as a case of its own, and C99 covers it by its rule for `\|x\| < 1`. |
| `x = ±0` or `±∞`, `y` finite and nonzero | `x²` or `1/x²` for negative `y`, negated for negative `x` and odd integer `y` | `±∞` (with divideByZero) or `±0` for zero `x`, and `±0` or `±∞` for infinite `x`, signed for odd integer `y`. |
| `x < 0` finite, `y` finite and not an integer | NaN, as `(x - x)/(x - x)` | NaN with the invalid operation exception. |
| `x < 0` finite, `y` an odd integer | the result for `\|x\|`, negated through the sign bias `0x800 << 7` | `pow (x, y) = -\|x\|^y`. |
| `\|y\| < 2^-65` | 1 for `\|x\| = 1`, else `1 + y` for `\|x\| > 1` and `1 - y` for `\|x\| < 1` | No special rule.  `x^y` rounds to 1 or a neighbor. |
| `\|y\| ≥ 2^63` | 1 for `\|x\| = 1`, else the overflow product when `\|x\| > 1` and `y > 0` or `\|x\| < 1` and `y < 0`, and the underflow product otherwise | No special rule.  `\|y log x\|` exceeds the finite range. |
| `x` subnormal | normalized by `2^52` before the logarithm | No special rule. |

The rows follow [the ports' journal section](../../devnotes.md#2026-10-10-ports-of-exp2-exp10-log2-log10-and-pow) and the code of `powWith`.  C99's clause F.9.4.4 lists the cases of zero, infinite, and negative arguments [10].  The same list appears as F.10.4.4 in C11 [11] and as F.10.4.5 in C23 [12], and both add `pow (±0, -∞) = +∞` as a separate rule, which C11 lets raise divide-by-zero.  The dialect has no floating-point flags, so the port signals neither divideByZero nor invalid operation, and with `WANT_ERRNO` 0 the division by zero of `__math_divzero` does not occur.  Lean's `Float` holds no signaling NaN, so the `issignaling` tests affect only a WebAssembly caller that passes one.

## Algorithm

`pow` evaluates `exp (y log |x|)` with the logarithm in two parts.  A double `log |x|` would lose the accuracy of the result for large `|y log x|`, since an absolute error `δ` in the exponent's argument becomes a relative error of about `δ` in the result, and `|y log x|` reaches 745 within the finite range.  Arm's comment states the budget: a worst error of 0.54 units, about the exponential's 0.511 units without fused multiply-add plus `1024 · ln 2 · 2^53` times the logarithm's relative error of `1.5 · 2^-68` without fused multiply-add, a product of 0.0325 units [1].

The logarithm writes `x = 2^k z` with `z` in `[0x1.69555p-1, 0x1.69555p0)`, an interval around 1 that Arm chooses so that `logc + poly (z/c - 1)` suffers no large cancellation near `x = 1`, and splits that interval into 128 subintervals.  For subinterval `i` the table holds `invc = 1/c` for a `c` near its center, `logc`, and `logctail`, so that `log x = k ln 2 + log c + log (z/c)`.  Harrison, Kubaska, Story, and Tang describe this reduction for the logarithm, `ln x = ln (1/c) + ln (c x)` with `ln (1/c)` from a table indexed by the top bits of `x` [7].  Arm chooses `1/c` with few bits, so `r = z/c - 1` is exact, and rounds `logc` to a multiple of `2^-43`, so that `k ln2hi + logc` is exact [3].  Without fused multiply-add the code splits `z` at bit 32 into `zhi + zlo`, so that `rhi = zhi · invc - 1`, `rlo = zlo · invc`, and `rhi²` are exact.  A polynomial of degree 8 with leading coefficients 1 and `-1/2` approximates `log (1 + r)`, with a stated relative error of `0x1.11922ap-70` on `|r| ≤ 0x1.6bp-8`, and the code collects the rounding errors of the leading terms into a tail `lo`, returning `log x` as `hi + lo`.

The product `y (hi + lo)` keeps a tail as well.  The code clears the low 27 bits of `y` and of `hi`, so that `yhi · lhi` is exact, and forms `ehi = yhi · lhi` and `elo = ylo · lhi + y · llo`, with `|elo| < |ehi| · 2^-25` by Arm's comment [1].  The exponential `exp_inline (ehi, elo, sign_bias)` is [the exponential's](Exp.md#algorithm) table-driven reduction and polynomial [7, 8] with `elo` added to the residual, and with the sign bias `0x800 << 7` added to the key so that the scale's sign bit is set for a negative result.  Its `specialcase` differs from `exp.c`'s in two ways: it keeps the sign of the scale and compensates a sum whose magnitude is below 1 with `±1`, and for a positive key it returns `DBL_MAX` for `pow (0x1.fffffffffffffp1023, 1)` when rounding upward, a test that is false in rounding to nearest.

## Implementation

The sources are Arm's `math/pow.c` (`Copyright (c) 2018-2026, Arm Limited`), `math/pow_common.h` (`2026`), `math/pow_log_data.c` (`2018`), and `math/exp_data.c` (`2018-2023`), at commit `503fafe311c177de0e571c458c7c337b1ca5f522`, under `SPDX-License-Identifier: MIT OR Apache-2.0 WITH LLVM-exception` [1, 2, 3, 4, 6].  The module docstring of [the implementation](Pow.lean) repeats the copyright line and the SPDX line of `pow.c`.  The configuration is the one without fused multiply-add or rounding intrinsics: `POW_LOG_TABLE_BITS` 7, `POW_LOG_POLY_ORDER` 8, `EXP_TABLE_BITS` 7, `EXP_POLY_ORDER` 5, `WANT_ROUNDING` 1, `WANT_ERRNO` 0, and `IEEE_754_2008_SNAN` 1 [5].

`verified_compile compiled := [checkint, zeroinfnan, issignaling, powLog, powSpecialCase, powExpCore, powExp, powMain, powWith, pow]` generates the module, whose functions are `alloc` (0), `release` (1), and the ten functions of the list (2 to 11), so that `pow` is function 11.  `pow` passes `powLogTable`, borrowed at address 4096, and `Exp.expTable`, borrowed at 8200, to `powWith`, and `wasm-tools print` of the 11,156-byte `build/verified/pow.wasm` on minideb1 shows the two data segments at those addresses and every function exported.  `powExp` and `powExpCore` port `exp_inline` instead of calling `Exp.expWith`, since `exp_inline` takes the tail and the sign bias.

`powLogTable` holds Arm's `__pow_log_data.tab` for `N = 128`: 512 words, `invc`, the unused `pad`, `logc`, and `logctail` for each subinterval.  Its 512 words equal the 128 entries of `pow_log_data.c` at the pinned commit, and 27 constants of the port equal Arm's expressions evaluated in binary64: `ln2hi`, `ln2lo`, the seven polynomial coefficients written as Arm's scaled products such as `0x1.555555555556p-2 · -2`, the reduction and polynomial constants that `powExpCore` shares with `Exp.expCore`, and the factors of `specialcase`, `__math_oflow`, and `__math_uflow`.  A check of the table against Arm's comment in 80-digit decimal arithmetic finds every `invc` a multiple of `1/256`, every `logc` a multiple of `2^-43`, and `|log c - logc - logctail|` at most `3.05 · 10^-30`, below the `2^-97 ≈ 6.31 · 10^-30` that Arm states.  These comparisons ran outside the repository.  In `transcendentals` the kernel checks no entry of `powLogTable`, and `ExpTableBounds.checked_table_bounds` covers `Exp.expTable`.  On branch `w/exp2`, `PowLogTable.checked_entries` and `checked_logs` check every entry of `powLogTable` in the kernel, as the next section describes.

## Proof

The branch splits the proof at the pair `ehi + elo`.  `powExp_within` gives one step against `exp L` for every target `L` with `|ehi + elo - L| ≤ |L|/2^65` and `|elo| ≤ 17 · 2^-28 |ehi|`, so the logarithm and the product must deliver those two conditions.  The branch asks of the logarithm `|y + tail - log x| ≤ (7/8) 2^-65 |log x|` for every positive normal or subnormal `x` other than 1, with `x = 1` evaluated directly, against the relative error of `1.5 · 2^-68` that Arm states for `log_inline` without fused multiply-add, and `PowProduct.product_error` adds a relative error of `2^-74` for the product.

The exponential reuses `exp`'s reduction, table, and scale words, and only its residual differs, as `r = reduce (ehi) + elo`.  The reconstruction lemmas of `ArmReconstruction` allow `2^-56` for the polynomial word, too little once the residual carries `|y| · |Δ log x|`, so `ArmTight` repeats them with the allowance `(37/100) u`.  The table gives the budget inside that allowance on the main path, for `|ehi| ≤ 768`, where `|L|/2^65` is at most about `2^-55`.

| Term | Bound | Source |
|---|---|---|
| Evaluation of the polynomial, and the polynomial against `exp r - 1`, on `\|r\| ≤ 1/360` | `2^-59 + 2^-63 = 17 · 2^-63` | `PowExpEval.evaluation_exp_tight` |
| Target term, computed residual, and rounding of `+ elo` | `2^-55 + 2^-60 + 2^-61`, times at most `1 + 1/359 + 1/359²` | `PowExpCore.core_state` |
| Total | about `0.28 u` | against the allowance `(37/100) u` |

The sharper reduction bound `|x - k log 2/128| ≤ 677/250000` (`PowExpCore.ideal_tight`) replaces the `exp` track's `1/320`, because `|r| ≤ 1/360` must hold with `elo` added.  From 768 to 1024 the result is infinity or lies within one step of zero, and a coarse evaluation on `|r| ≤ 1/128` suffices (`PowExpFar`).  `powSpecialCase` differs from `exp.c`'s `specialcase`: for a positive scale and a positive sum its negative branch reduces to `ExpSpecialNegative.negativeResult` (`PowExpPaths.negative_eq`), and `ArmTight.mul_comm_finite` swaps the factors of its positive branch, which multiplies by `2^1009` on the right.

## Tests

[The accuracy check](PowAccuracy.lean) compares `pow` natively with the double nearest to `x^y` from [the power references](PowerReference.lean), which compute `y log |x|` at 500 bits after the binary point and its exponential with `Reference.exp`, and with the special cases of C99's Annex F implemented separately in the check's `reference`.  It fails at the first result more than one step away.  Its 110,922 pairs are 60,000 hashed pairs with positive `x` from `2^-60` to `2^60` and `|y|` from `2^-10` to `2^10`, 20,000 pairs with `x` within `2^20` units of 1 and `|y|` from `2^20` to `2^51`, 20,000 pairs of negative `x` with magnitudes from `2^-8` to `2^8` and the integers `y` from -100 to 100, the 6,333 pairs `(2, k)`, `(2, k + 1/2)`, and `(-2, k)` for the integers `k` from -1080 to 1030, 4,002 pairs with `x = 10` and `x = 0.1` near overflow and underflow, the 11 pairs of `WorstCases.pow`, and the 576 pairs of 24 special values.  The check's docstrings give C99's clause as F.10.4.4, which is its number in C11, and C99 numbers it F.9.4.4.

The worst-case pairs are those that give the largest known errors in Tables 5 to 11 of Gladman, Innocente, Mather, Ozaki, and Zimmermann's report [13].  Its Table 3 lists for `pow` 0.523 units for GNU libc 2.44 and the Arm Performance Library, 0.525 for Musl, and 636 for FreeBSD 15.1.  In `opus-verified-tests-14.log`, the run of `tests/verified/run.sh` in `build/transcendentals` on minideb1 after the `sinh` merge, all 110,922 results lie within one step of the reference, 79 of them unequal to it, so the largest measured distance equals the decided bound.  The C library on minideb1 also lies within one step with 79 results unequal, which fits glibc's use of Arm's routine, as [the ports' journal section](../../devnotes.md#2026-10-10-ports-of-exp2-exp10-log2-log10-and-pow) notes.  The first passing run, before the worst-case pairs were added, is `ports-PowAccuracy-4.log` in `/home/somebody/src/lt-ports/build/transcendentals` on minideb2, with 110,911 results and 78 unequal.  The reference's truncation errors are stated in docstrings and are not proved.

## Limits

No merged theorem covers the port, so its accuracy in `transcendentals` rests on the sampled check of 110,922 pairs, the Python models of the ports track, which lay within one unit of 150-digit values at about 23,000 pairs, Arm's stated error of 0.54 units, and the unmerged proofs of branch `w/exp2`.  Every limit of the exponential's theorem applies to `PowBytes.pow_bytes_accuracy`: Talos's semantics, the trusted decoder and `binary_file%`, the deterministic profile's canonical NaN, the canonical NaN argument of a Lean `Float`, and host actions between calls.  The signaling NaN cases depend on NaN words that a Lean `Float` cannot hold, so `PowBytes.pow_bytes_accuracy`, whose arguments are the words of `Float` values, does not cover them.  `WithinSteps` places both zeros at position 0, so `pow_within` leaves the sign of a zero result open, and for a negative base and an odd `y` the branch proves only the relation `PowSignRel.Rel` to `pow (-x) y`, which allows zeros of either sign.
