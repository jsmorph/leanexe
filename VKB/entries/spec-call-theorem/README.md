# A specification equality carried to a call theorem

A program often has a theorem that equates it with an independent specification, such as `compute_eq : xs.size < 2 ^ 64 → compute xs = expected xs`.  Its verified compilation has the generated `compiled.f.implements` and `compiled.f.trapFree` or, for a scalar function, `compiled.f.pure`.  The goal is a theorem about one export, called from a store that meets stated premises, whose result is the specification's value without a trap.

`Verified.Call m tables k f Pre Post` names that statement for function `k` of the module `m` compiled with the tables `tables`.  From a store that `Verified.Ready m tables` states ready, with arguments `x` that `params` represent and that move no object, and with `Pre`, the call returns `f x` without a trap and leaves a ready store.  Every array borrowed before the call stays borrowed, every region of the heap keeps its bytes and lies apart from the result's objects, and `Post` holds.  `Verified.CallSpec m tables k f B` is `Call` with room for `B x` bytes as `Pre` and a rise of `top` by at most `B x` as `Post`.  `Verified.Ready.initial rfl compiled.initial` proves that the store in which the module starts is ready, so a call theorem covers every call of a sequence that starts there.

`Verified.ImplementsTables.call` proves `Call` from `compiled.f.implements` or `compiled.f.trapFree`, the program's tables `compiled.tables`, and a proof that each table the entry reads is one of them.  An entry that reads no table passes its theorem through `Verified.ImplementsTables.ofA` and proves the last premise with `nofun`.  An entry that reads table `i` proves it with `fun _ ht => ⟨i, by decide, List.mem_singleton.mp ht⟩`, as `Library.Hashing.Sha256.sha256_call` does.  A table whose address depends on the size of a large table needs a raised `maxRecDepth`, as `Library.Hashing.Crc.crc32c_table` shows.  The call theorem applies the result to the environment, heap, store, argument values, and argument tuple, then to the readiness, a `Represent.borrowed` proof built by hand, `rfl` for the moves, and the precondition, and it composes with the specification equality in `Wasm.Runs.mono`.  Inside, `LeanExe.ProofKit.BorrowedKept.borrowed_kept` keeps each borrowed array borrowed, and `LeanExe.Pipeline.memoryCap_le_of_caps` keeps the cap.

`Verified.CallSpec` covers every shape that `Represent` describes: words, word arrays, and tuples of them as arguments, and a word, a tuple of words, or a word array as the result.  `Verified.Call.spec` turns `Call` into `CallSpec` for the specification, from implications from room for `B x` bytes to `Pre` and from `Post` to a rise of `top` by at most `B x`, and from the equality on represented arguments.  With `compiled.f.trapFree` and `B` the generated `compiled.f.bound`, the implications are `fun _ _ _ h => h`, or `fun _ _ _ _ => trivial` for a function that cannot abort, and `fun _ _ _ _ _ h => h`, as `Examples.Increment.compute_callSpec` and `Library.Numerics.Arithmetic.Gcd.gcd_callSpec` show.  `Verified.Call.array` restates `Call` for an owned array result, with the result's address and its block apart from every region before the call, as `Library.Hashing.Sha3.shake128_call` uses it.  `Examples.arrayCall` combines the two for a function from a borrowed `Array UInt64` to an owned `Array UInt64` in a module without tables.  Apply it to `compiled.f.trapFree`, a lemma `∀ xs, compiled.f.bound xs ≤ B`, and `fun xs h => compute_eq xs h`, and pass a bound stated as an equality as `fun xs => (compute_bound xs).le`, as `Examples.Lookup.lookup_call` does.  Inside it, `LeanExe.ProofKit.UInt64Array.At.size_lt` discharges the equality's size premise from the input's representation.

For a scalar function with a `pure` theorem, apply it at the argument tuple and close with `Wasm.Runs.mono`, as `Library.Numerics.Arithmetic.Gcd.gcd_call` does, where `simpa [Scalar.values] using congrArg List.reverse hv` turns `values.reverse = Scalar.values (f x)` into `values = [.i64 …]`.  Such a call holds from every store and keeps the store, so it needs no readiness, and `CallSpec` states neither fact.  `LeanExe.Pipeline.ImplementsPureA.implementsA` turns `compiled.f.pure` into an `ImplementsA` theorem whose `Post` keeps the heap and the store, and `Verified.ImplementsTables.call` then gives `Call` with that `Post`.  `Runs` lists the arguments with the top of the stack first, so a call of `f a b` takes `[.i64 b, .i64 a]`.

`p.f.implements` allows a trap whenever the function's abort flag is true, which holds for every function that returns an array, so a call theorem that excludes the trap starts from `trapFree`.  `Call` requires arguments that move no object, so an entry with an owned argument needs its own statement.  State the export's index with a theorem such as `({ name := "compute", funcIdx := k } : Wasm.Export) ∈ compiled.module.exports`, proved by `decide +kernel`, since the call theorem names a function index and a host calls an export by name.  Keep the equality in a module that imports only the program, the specification, and lemmas about the dialect, as `Examples.Increment.Proof` does, so that the verified compilation imports nothing of the LeanExe compiler.

`compiled.initial` given directly where `Ready` is expected reaches the recursion limit for the modules of CRC and of the exponential, and `Verified.Ready.initial rfl compiled.initial` does not.  The worked examples are `Library.Hashing.Sha256.sha256_call`, `Library.Hashing.Crc.crc32cUpdate_call`, `Library.Hashing.Sha3.shake128_call`, `Library.Regex.matchWith_call`, `Library.Numerics.Float64.Exp.ExpTheorem.exp_entry_call`, `Examples.Increment.increment_call`, and `Library.Numerics.Arithmetic.Gcd.gcd_call`.  `Examples.TreeLookup.treeLookup_call` and `Library.Numerics.Arithmetic.PrimeFactors.primeFactors_call` follow the patterns of an array result and of a scalar result from every store.
