# Safety theorems of a record machine over its history

The entry applies to a machine that a framing calls once for each record, `M → input → M × answer`, such as a protection or protocol machine, when a safety theorem about a run must be stated over the records and answers before an answer and not over the machine's state.  Requirements in English define such terms as the permit of the previous answer, whether the previous record was good, or the number of records since a relay's bit last changed, and a reviewer compares the statement with those definitions.  A statement that names the machine's state fields would only restate the program, so the proof's work lies in relating the state to the history.

Define the run over every sequence of inputs, `Demos.Bms.Spec.stateFrom` from any state and `Demos.Bms.Spec.stateAt` from the state after a reset, with `Demos.Bms.Spec.answerAt` as the step's second component.  Define each term of the requirements over the history: the previous answer's permit (`Demos.Bms.Spec.permitInForce`), whether the previous record was good (`Demos.Bms.Spec.syncedAt`), and the last earlier segment with a property, `Demos.Bms.Spec.lastBefore`, which `Demos.Bms.Spec.prevResetAt` and `Demos.Bms.Spec.ageAt` use as the requirements' text does.  Write the checks once, as an ordered list of a failure flag and a code (`Demos.Bms.Spec.checks`), whose first failing entry `Demos.Bms.Spec.firstFailure` gives the code.  The machine passes its state fields and the history terms pass their values, so both read one text of the checks, and `Demos.Bms.Spec.checks_none_iff` splits "no check fails" into its parts.

Prove one equation for each state field by induction on the segment, from a recursion lemma of its history term: `Demos.Bms.Spec.synced_eq`, `Demos.Bms.Spec.expected_eq`, and `Demos.Bms.Spec.prevReset_eq` with `Demos.Bms.Spec.prevResetAt_succ`, and `Demos.Bms.Spec.age_eq` with `Demos.Bms.Spec.ageAt_succ`.  A counter that the state caps relates to the uncapped history count through `min`, which suffices when the check only compares it with the cap.  `Demos.Bms.Spec.failure_eq` combines them: the machine's checks of a segment are the history's checks.  Then characterize the step by its source state (`Demos.Bms.Spec.next_active`, `Demos.Bms.Spec.next_inactive`, `Demos.Bms.Spec.next_standby`, and `Demos.Bms.Spec.next_precharge`), each by `cases` on the failure, the stop bit, and the state, `split_ifs`, and `simp_all`, and turn the named events into equivalences with transitions over the run (`Demos.Bms.Spec.resetAcceptance_iff` and `Demos.Bms.Spec.start_iff`).

The main theorem chooses the last segment up to `n` with a property by `Demos.Bms.Spec.exists_last` and the first by `Demos.Bms.Spec.exists_first`.  For a nonzero permit at `n`, the last state before `n + 1` that grants nothing is the reset acceptance, every state after it grants, and every record from it to `n` therefore passed every check, as `Demos.Bms.Spec.m1` shows.  A counter along consecutive equal states follows by induction on the run's length (`Demos.Bms.Spec.pc_run`), and an invariant over the codes of the states follows from one step lemma (`Demos.Bms.Spec.next_codeOf`).  A structure with one field for each item of the requirements, `Demos.Bms.Spec.Permitted`, holds the conclusion, so a reviewer compares the fields with the items.

A history term can need state that a requirements table omits.  The rule that every relay gets age 0 at segment 0 needed a field `first`, since a counter that wraps cannot identify segment 0, and a program's abstraction to the specification's state cannot rebuild an unbounded counter.  Bound every field of the specification's state as the program bounds it.

`cases h : f x` fails with "generalize: result is not type correct" when `f x` occurs under a binder with a `decide`, as in `List.filter (fun u => decide (c < u) && p u)`, and `by_cases h : f x = true` followed by `simp only [h]` works (`Demos.Bms.Spec.ageAt_succ`).  `rw [hl] at h` with `hl : lastBefore p t = none` leaves `match none with` unreduced in `h`, which `simp only [hl] at h` reduces (`Demos.Bms.Spec.m10`).  `tauto` on a disjunction of equalities with named numeric constants reached the heartbeat limit in `isDefEq`, and membership in a list that appends the extra constant, through `List.mem_append_left`, replaced it (`Demos.Bms.Spec.next_codeOf`).  `decide` on the projection of a structure literal that holds a free variable, such as the code of a `Next` with `pcCount := s.pcCount`, fails with "expected type must not contain free variables", and `simp` with the constant's definition closes it.

The worked examples are `Demos.Bms.Spec.m1`, `Demos.Bms.Spec.m7_count`, `Demos.Bms.Spec.m10`, and `Demos.Bms.Spec.codes` in `Demos/Bms/Theorems.lean`.  `Demos/Bms/Cases.lean` checks by `#guard` that the history terms equal the state's fields on a run through every state, which catches a wrong history definition before a proof attempt.
