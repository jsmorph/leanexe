# Bytes that a trusted rule leaves free

The entry applies when a host call returns data that its specification leaves open and the compiled code passes on, such as the bytes of an iovec's region after the count of a read, which WASI Preview 1 does not state, and a theorem must relate the compiled result to the source semantics.  A rule that fixes such bytes, to zeros or to the bytes that the region held before the call, fails for some host that meets the specification, and a compiler proof cannot discharge it.

Give the rule a free value constrained by exactly what the specification guarantees, and let the compiler's proof choose the value from the machine state.  `LeanExe.Wasi.Exec.read_return` takes a byte string `range` with the premises that its size is the read's capacity and that on errno 0 it begins with the bytes read, and passes `LeanExe.Wasi.readReply errno committed range` to the continuation.  `Verified.Wasi.wp_read_fill_with` chooses `Verified.Wasi.memoryRange` of the memory at the window after the call, whose size follows from its definition and whose prefix `Verified.Wasi.memoryRange_prefix` derives from the `Verified.Bytes.At` fact of the host's `readContract`.  A use that ignores the value supplies a canonical one: `LeanExe.Wasi.Exec.read_returned` takes `LeanExe.Wasi.readRange`, the bytes read followed by zeros, and `LeanExe.Wasi.readAllStep_reply` shows that `readAll`'s pass reads only the errno and the bytes.

Make every premise of the rule load-bearing.  A premise that no proof uses can be dropped from the rule without failing any check, and the semantics then admits results that no host gives.  `LeanExe.Wasi.readStdin_placed` derives from the prefix premise that a read with errno 0 places the bytes read at the window's start, so a rule without it fails that theorem.  A behaviour of the compiled code that the rule leaves free, such as keeping the window's bytes after the count, needs a test against the engine: the acceptance case `retained-one` of `tests/wasi/acceptance/cases.tsv` runs `Verified.Examples.WasiRetain.retain` on one byte of input and expects the byte that the second, empty read leaves in the window.

The native interpreter has no machine state to choose from, so it uses the canonical value, and a program whose result depends on the free bytes differs between the interpreter and the engine while both runs lie within the rule.  Record such a difference where the interpreter is described, as `docs/wasi.md` does in its section on the native interpreter.

The worked example is the read of stdin: `LeanExe.Wasi.readStdin`, `Verified.Wasi.wp_read_fill_with`, and the row "Preview 1 model" of `docs/trusted-base.md`.
