# Bounds on the windows of a step's phases

The entry applies when a Cortex-M7 step does long work in one phase, such as decoding a record and encoding its answer, and the goal bounds the windows of its other phases apart from that one, as the timing of polling windows against half a byte time requires.  `LeanExe.M7.staticCost` charges an `if` its longer branch, so `LeanExe.M7.Counted.uniform` bounds every window by the long window's cost.  The method applies when the step selects its phase with `if`s on the fields of its state and on the value read, which the reflector compiles into tests: code that reads the parameters with `local.get` and computes with `i64.const` and `i64` operations, ending in an `if`.  A step written as a dispatch to a polling function and a long function, with one test before one `if`, is the simplest case, and the echo of delimited records, whose `TestSupport.M7.Delim.dlPhases` nests its tests, is the worked example.

`LeanExe.M7.pathCost m k dec` bounds the runs of function `k` whose tests have the outcomes of the table `dec`, a list of pairs of a test's code and its outcome, `true` for the then-branch.  `LeanExe.M7.pathL` reads a list of instructions from its start, adds each form with a key of `LeanExe.M7.pureKey` to the test, and at an `if` charges the branch that `LeanExe.M7.testOutcome` gives for the test, or both when the table has no entry; after the first `if`, a call, or another form without a key it charges as `staticCost` does.  `testOutcome` compares codes through their keys, since Talos's instructions have no decidable equality.  Print the step's body with `#eval (m.funcs[k]!).body` to read the tests' code.  The reflector compiles `if c then a else b` into the code of `c`, `extendUI32`, `eqzI64`, and an `if` whose then-branch is `b`, so the outcome `true` selects the source's else-branch.  Write one table for each kind of window, listing the tests on its path from the body's start, and evaluate `pathCost` with `decide +kernel`, as `TestSupport.M7.dl_paths` does for `TestSupport.M7.dlRxTests` and the other tables.

`LeanExe.M7.TestOk m env ps pre b` states the outcome of a test from the step's parameters `ps`.  State it for every state and value with the outcome as a Boolean of the state, as `TestSupport.M7.dl_phaseTest` states `g.phase != n` for the parameters `(dlWords g ++ [v]).map Value.i64`, and prove it with `intro f st ls`, `simp [code, words, Wasm.exec, Wasm.execOne.eq_def, Locals.get]`, and `split <;> simp_all`, which evaluates a test of seven instructions in about a second.  Assemble the table's `LeanExe.M7.TestsOk` with `LeanExe.M7.TestsOk.cons` and `LeanExe.M7.TestsOk.nil`, rewriting each outcome to the table's Boolean with the case's hypotheses.  `LeanExe.M7.costRun_step_le_pathCost` then bounds `costRun` of the step from `LeanExe.M7.stepArgs`, given the step's number of parameters, which `decide +kernel` evaluates as `TestSupport.M7.dl_params` does.  A case analysis on the phase that picks one table for each case gives a bound for every state and value outside the long phase, as `TestSupport.M7.dl_poll` gives for every state and value that `TestSupport.M7.DlDecodes` does not hold of.

`LeanExe.M7.Counted.split` takes the counted run of `LeanExe.M7.Nucleo.boardWith_run_steps` or `LeanExe.M7.boot_run_steps`, the uniform bound from `staticCost`, and the predicate's bound, and states both bounds over one list of window counts, the second for each window whose state and value satisfy the predicate, as `TestSupport.M7.Delim.board_loop_poll` and `TestSupport.M7.Delim.qemu_loop_poll` do.  The file theorems `dl_board_poll` of `tests/TestSupport/M7/DelimBoardFile.lean` and `dl_qemu_poll` of `tests/TestSupport/M7/DelimQemuFile.lean` apply these to the images, and each new `#print axioms` line of a file module raises the count that `tests/baremetal/m7-board.sh` or `tests/baremetal/m7-qemu.sh` expects.

`rfl` does not prove a test's run, since the elaborator does not unfold `Wasm.exec` through the test's instructions, while `simp` with the equation of `Wasm.execOne` does.  A statement of the outcome with an existential value fails under `refine ⟨_, _⟩`, which must synthesize the value, so `TestOk` matches on the run's result instead.  A dispatch whose condition is the result of a call, or whose test code sets a local, gets no outcome, and `pathL` charges both branches, so write the condition inline over the state's fields.  The test of an inner `if` counts from the start of its branch, so a table lists the tests of the nested `if`s on the path in order.  In proofs about `pathL`, `rw [pathL]` picks the equation of the `if` case with a side condition, while `rw [pathL.eq_def]`, `dsimp only`, and `split` give both cases, as `LeanExe.M7.costExec_le_pathL` does.  The section "Delimited records" of `docs/m7-bare-metal.md` compares the bounds of the echo of records with the model's counts of its windows.
