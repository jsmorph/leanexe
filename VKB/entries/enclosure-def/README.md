# One source for a real formula and its interval program

This entry applies to a program in the verified compiler's dialect that evaluates a long real formula on intervals, with a theorem that each accepted result contains the formula's value.  The goal has the form `Library.Numerics.Interval.Encloses` of the program's result and the real value, or `Library.Numerics.Interval.prodRel` of two tuples, and the formula is a chain of `let` bindings over arithmetic, square roots, sines, cosines, the powers `2/3`, `3/2`, and `7/2`, maxima, and comparisons of real numbers.

State each part of the formula once with the command `enclosure_def` of `Library.Numerics.Interval.Enclose`.  The command declares the real function `f`, the interval function `fI`, and the theorem `f.encloses`, which the tactic `enclose` proves from the theorems with the label `enclose`, such as `Library.Numerics.Interval.encloses_add`, `Library.Numerics.Interval.encloses_div`, `Library.Numerics.Interval.encloses_sinI`, `Library.Numerics.Interval.encloses_twoThirds`, and `Library.Numerics.Interval.encloses_ifLt`.  A relation of this kind holds without a hypothesis of acceptance, since `Library.Numerics.Interval.Encloses` states the inclusion under the acceptance of the interval, so the proof of a chain applies one theorem for each operation and has no case analysis.  Write a call of another part as an application, bind the components of its tuple with `let (a, b) := g x`, and give a hand-written interval function `gI` the theorem `g.encloses` with the label `enclose`, as `Demos.Sgp4.Kepler.root.encloses` does for the root of Kepler's equation.  Around the parts, write the tests of the program by hand on the endpoints, and prove what each status implies with `Library.Numerics.Interval.Contains.pos_of_lo`, `Library.Numerics.Interval.Contains.neg_of_hi`, and their siblings, as `Demos.Sgp4.initStatus_sound` does.  For a constant outside the command, apply `Library.Numerics.Interval.encloses_ofInt'` or `Library.Numerics.Interval.encloses_ratio'` with the integer of the literal given by name, and close the side goals with `decide +kernel` and `norm_num`.

These approaches fail or cost time.  A function of 120 interval operations exceeds the default heartbeat limit of `verified_compile`, and functions of 20 to 45 operations compile, so split the formula into parts of that size.  The list of the file `Demos/Sgp4/BoxVerified.lean`, about 130 functions, compiles in about two hours with `set_option maxHeartbeats 0`, and with the default limit it fails in `whnf`.  `verified_compile` names its declarations by the last component of each listed function's name, so two listed functions `a.interval` and `b.interval` collide, and the command therefore names the interval function `fI`.  A function whose parameter or result is a tuple of more than about 25 intervals needs `set_option synthInstance.maxSize 4096` and `set_option synthInstance.maxHeartbeats 2000000` before `verified_compile`, as the file `Demos/Sgp4/BoxVerified.lean` sets them for `Demos.Sgp4.boxCompiled`, or the command reports that Lean has no `Represent` instance for the tuple.  The term `enclosure_relation% 35` takes no arguments, so apply it in parentheses.  A value that the model selects by a comparison becomes a selection that evaluates both branches on intervals, so a branch that divides by a quantity that may be zero is rejected alone and the selection still returns the other branch, and an interval with points on both sides of the threshold is rejected.

`Demos.Sgp4.Spec.longPeriod.encloses` is the theorem of a part of three bindings, `Demos.Sgp4.Spec.constants.encloses` composes the parts of the initialization through tuples, and `Demos.Sgp4.Spec.wgs72State.encloses` passes a tuple of 35 intervals as one parameter.  `Demos.Sgp4.box_cases` derives what each status of the whole program implies, and `Demos.Sgp4.sgp4Box_sound` is the resulting inclusion.
