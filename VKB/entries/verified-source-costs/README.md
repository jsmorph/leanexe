# Source forms and their costs in the verified compiler

The verified compiler accepts several ways to write one Lean function, and its universal theorem holds for each of them.  The choice still decides how much the code allocates, what the generated bound charges, how long `verified_compile` takes, and whether it finishes.  The regex, SHA-3, HMAC, slew, and heap-sum programs met the costs below, each with the form that avoided it.

A record parameter is always borrowed, so a listed function that updates an array field of its record parameter copies the array at every call.  The regex matcher's first compilation listed `Library.Regex.scanStep`, `push`, and `combine`, which take the `Library.Regex.Scan` record, and its bound charged copies of the stack, the follow table, and the set table at every pattern word, which passed the 4 GiB memory cap near 13,000 pattern words.  Marking the three helpers `@[inline]` and leaving them out of the list made the reflector unfold them into the loop of `scan`, whose state it updates in place, and the bound became linear (`Library.Regex.matchWith_bound`).  The slew planner's `Demos.Slew.round` and `relax` take the `Search` record in the same way, and `Demos.Slew.Bound.plan_bound` charges four array copies in each of them at every round.  `Verified.Expr.paramChoice` chooses the modes of array parameters, and the manual's section on ownership states its rules.

Inlining has its own limit.  SHA-3's round, split into `@[inline]` helpers over the 25-lane structure `Library.Hashing.Sha3.Lanes`, made `verified_compile` run out of heartbeats in `isDefEq` on the unfolded structures.  Listing the helpers as functions works there, because the lanes hold no array and a borrowed record of words costs no copy, and `Library/Hashing/Sha3/Compiled.lean` lists `thetaL`, `rhoPiL`, `chiL`, and `iotaL`.  Inline a helper whose record parameter holds arrays that it updates, and list a helper whose parameter holds only words.

Some forms change what the code evaluates, or fail with a message that does not locate the cause.  `&&` and `||` compile to both operands followed by one instruction, so `a && f x` runs `f x` even when `a` is false, and a nested `if` keeps the second test lazy, as `Demos.Slew.relax` does before it calls `edgeOk`.  `if p ∧ q` and `if p ∨ q` on propositions compile to the same eager connectives, as the `reflector-forms` entry states.  A `let` of a comparison without a type, such as `let big := sn ≥ axisMin`, binds a `Prop`, and the reflector rejects it with a message that names no function.  `set_option trace.Verified.reflect true` shows the last function that the reflector reached, and `let big : Bool := sn ≥ axisMin` gives the same meaning in the dialect.  An array position must be `i.toNat` for a word `i`, so a literal position becomes `(k : UInt64).toNat`.

A match copies a value that an alternative names whole.  In a match on a recursive type, a variable that names the matched value, as in `| s => f s`, compiles as the constructor rebuilt from the fields and makes the parameter owned, while `| _ => f t` reads `t` through a copy when `t` is owned.  In a match on a sum with heap fields, an alternative such as `| other => other` reads the whole matched variable, so each step of `Verified.Examples.HeapSums.grow` copies its state before the match takes it apart, while `regrow`, which rebuilds each constructor, moves the fields.  The generated bound charges each such copy.  The expected allocation counts of the heap-sum cases first assumed that `grow` moves its state, and 51 cases failed until the counts charged the copy.

A loop that builds a new array at each pass is charged a block for every pass, even when the array that it replaces dies, because the generated bound ignores the reuse of freed blocks.  Keep the arrays in the loop's state instead, write each pass into one of them with `set!`, and pass them on by moves.  `Verified.Expr.allocs` charges nothing for a `set` on an owned array that dies, through `Verified.Var.ownedCost`, and nothing for a move, so the bound no longer depends on the number of passes.  The Euler solvers built two grids for each try of a timestep, and 65,535 pages held the bound of a run on the 800 grid only for at most 69 tries.  `Demos.Euler.Buffered` keeps three grids in the states of the loops of tries and timesteps, writes the x sweep into the second grid with `Demos.Euler.Buffered.sweepInto` and the y sweep into the third, and rotates the three in `Demos.Euler.Buffered.tryInto` when a try is accepted.  `Demos.Euler.Verified.solve_bound` then charges the three grids and the packed result, 1,563 pages on the 800 grid for any number of tries.  The rewrite changes the definition, so a theorem about the original function needs an equality, which `Demos.Euler.Buffered.solve_eq` proves with the lemmas that the `loop-combinators` entry names.

Exports and generated theorems take the last component of each definition's name, so one `verified_compile` command cannot list two definitions whose names end alike, and `Library/Hashing/Hmac/Compiled.lean` therefore compiles the SHA-256 and SHA-512 helpers in two programs, `compiled256` and `compiled512`.  A program over a recursive type `T` needs `verified_recursive_type T` once, after `T`'s `Encode` instance, in a module that the program imports, because two modules that each derived the type's declarations could not be imported together.  Keep a program's `Flat` instances out of the program's module, in a module beside it such as `Library/Hashing/Sha3/Encoding.lean`.  An instance needs `LeanExe.Pipeline.Implements`, and when the SHA-3 program imported that module, the native vector test, which imports the program, built every module of the pipeline that `Implements` imports.
