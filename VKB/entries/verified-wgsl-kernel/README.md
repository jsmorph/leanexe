# GPU kernels of verified builds: WGSL dispatch and PTX launch

A function whose body is an outer `LeanExe.build` over words, Booleans, or binary32 values compiles after `verified_compile` to a WGSL kernel through `Verified.WGSL.compile` and to a PTX kernel through `Verified.PTX.compile`.  Both call `Verified.Kernel.KernelPlan.ofBuild`, which lowers the element with `Verified.Kernel.lower` into one plan, and then translate the plan for their target.  A WGSL dispatch theorem states that the kernel writes the Lean function's result into the output buffer and is race-free in the WGSL device model, and a PTX launch theorem states the same of a launch.  Each target also has a memory-model form: a consistent execution exists, and in every consistent execution no access is in a data race, every invocation or thread ends, and the reads after the run return the result's words.  The memory-model forms also rest on two rows of the trusted base that no proof covers, "No invocation runs past a stop" of [its WGSL section](../../../docs/trusted-base.md#wgsl-wgsl-kernels) and "No thread runs past a stop" of [its PTX section](../../../docs/trusted-base.md#ptx-ptx-kernels): each invocation or thread on the device performs the memory operations of `LeanExe.WGSL.Module.invokeE` or `LeanExe.PTX.Stmt.exec` for some oracle, so that none runs past a point where that semantics stops, such as an access outside a buffer.

Define the WGSL kernel as `(Verified.WGSL.compile (e := .float32) compiled.f.func.body).get (by decide +kernel)`, and its module as that kernel's `.module`.  The dispatch theorem's premises bound the input arrays below `2 ^ 29` elements, require an output of the result's size with its length word written, and require enough invocations.  Prove `gpu.spec.Fits (gpu.args env) n`, with `env` the arguments as a `Verified.Env` such as `.cons a (.cons x .nil)`, by `refine ⟨rfl, ?_, ?_, hn⟩`.  The sizes follow from `change ∀ ys, Arg.array ys ∈ [the explicit arguments] → ys.size < 2 ^ 29` and `simp`.  The count follows from a `change` to the form `∃ ys, some (Arg.array …) = some (.array ys) ∧ ys.size = n` when it is an array's size, or to `some (Arg.word w) = some (.word (UInt64.ofNat w.toNat))` with `UInt64.ofNat_toNat` when it is a word.  `Verified.WGSL.Compiled.dispatch_value _ env _ (compiled.f.denote_eq …) n fits output hOut hL0 hL1 count hCover h32` then closes the goal.  A local abbreviation for the words of a binary32 array, `x.map fun v => v.toBits.toUInt64`, makes the statement match by definition.  `LeanExe.WGSL.Dispatch.meets` turns the two conjuncts of `dispatch_value` into the memory-model statement `LeanExe.WGSL.Dispatch.Meets`, through `LeanExe.WGSL.Dispatch.executions`, and `Verified.WGSL.Kernel.executions_eq` states the memory-model form for a kernel and its source build.

Define the PTX kernel in the same way with `Verified.PTX.compile`.  `Verified.PTX.Compiled.launch_value` states `Verified.PTX.LaunchSeq`, the sequential run of a launch, which leaves the count followed by the encoded elements and in which distinct threads store to distinct words.  `Verified.PTX.Compiled.executions_eq` states `Verified.PTX.LaunchMeets`, the form under the PTX memory model, through `Verified.PTX.Kernel.executions_eq`.  Both take the generated `denote_eq`, the `Fits` premise, an initial output `ys` with one word for each element, and a launch of at least `n` threads in blocks of fewer than `2 ^ 32` threads, with fewer than `2 ^ 32` blocks and fewer than `2 ^ 60` threads in all.  When the build also compiles to WGSL, `Verified.PTX.Compiled.of_wgsl` equates the two compilations' `spec`, arguments, and encoding, so the PTX proof reuses the WGSL proof of `Fits`, as `Demos.Gpt32.VerifiedPtx.expKernel_launch` reuses `Demos.Gpt32.Verified.expGpu_fits`.  A kernel written by hand has no plan: `LeanExe.PTX.addOne_seq` proves its sequential run and race freedom from each thread's events with `LeanExe.PTX.Launch.seq_some`, and `LeanExe.PTX.Launch.executions` then gives `LeanExe.PTX.addOne_executions` for every consistent execution.

A host program composes kernel runs.  `Demos/Gpt32/Exec.lean` gives the meaning of the host's commands on a `Demos.Gpt32.Device`, whose `Meets` is the device's memory-model statement about one run, and `Demos.Gpt32.Backend` collects what a device must prove: the buffers of words, floats, and the empty array, and, for each kernel call that `Demos.Gpt32.KernelName.apply` accepts, a run that leaves the call's result and meets the memory model.  `Demos.Gpt32.Item.execAll_sim` turns a run of typed items into a run of the host's commands on any device with a backend, and `Demos.Gpt32.generate_host` states the GPT-2 generation step for such a device.  `Demos.Gpt32.Verified.backend` proves the backend of the WGSL device from `Demos.Gpt32.Verified.apply_dispatch` and `LeanExe.WGSL.Dispatch.meets`, and `Demos.Gpt32.VerifiedPtx.backend` that of the PTX device from `Demos.Gpt32.VerifiedPtx.apply_launch`.  They give `Demos.Gpt32.Verified.generate_host` and `Demos.Gpt32.VerifiedPtx.generate_host`.

`Verified.Kernel.lower` covers literals, variables, word, Boolean, and binary32 operations, conversions between binary32 values and their bits, reads, sizes, `let`, `if`, and counted loops.  It returns `none` for calls, for binary64 values, and for the signed comparisons and the arithmetic shift of `Int64`, which `Verified.Kernel.cmpExpr` and `Verified.Kernel.binOp` map to `none`, `Verified.Kernel.KernelPlan.ofBuild` returns `none` for an element other than a word, a Boolean, or a binary32 value and for a parameter other than these or an array of them, and the proof of `get`'s premise by `decide +kernel` then fails.  The WGSL translation accepts word division and remainder only by a constant power of two from 2 through 2³¹ and binary32 literals only when finite, and the PTX translation has neither limit ([the manual's section on PTX kernels](../../../docs/verified-manual.md#ptx-kernels)).  A function that the reflector rejects is never translated.

The WGSL examples are `Examples.Binary32.scale32_dispatch`, `Examples.Binary32.axpyArray32_dispatch`, `Examples.Binary32.matVec32_dispatch`, and `Demos.Gpt32.Verified.expKernel_dispatch`, which state the size, output, and invocation premises and prove `Fits` from them.  `Verified.Examples.Wgsl.scale_dispatch` keeps the abstract `Fits` premise instead.  `Examples.Binary32.condMix32_dispatch` takes mixed arguments in their order, `[Arg.array …, Arg.float lo.toBits, Arg.float hi.toBits, Arg.word n]`, with the count from the array at position 0, and its conjunction of propositions compiles to `Verified.Expr.and`.  The PTX examples `Verified.Examples.Ptx.words_executions` and `Examples.Binary32.scale32_executions` keep the abstract `Fits` premise, `Demos.Gpt32.VerifiedPtx.expKernel_launch` proves it from the WGSL theorem, and `LeanExe.PTX.addOne_executions` is the kernel written by hand.
