# Whole-program theorems of bare-metal C programs

A METAL program is the C translation of a module of `verified_compile` with a generated `main` (`LeanExe/Native/Bare.lean`), which runs without an operating system on QEMU's `virt` machine, on QEMU's `mps2-an500`, or on the NUCLEO-F767ZI.  Its Lean theorem is CompCert's Clight judgment for the whole program: `LClight.bigstep_program_terminates` for a `main` that returns, and `LClight.LoopReacts` for a `main` that runs forever, which states an initial trace and a nonempty trace for each window through an invariant indexed by the window.  The Rocq theorems of `rocq/Clight2Asm.v` carry either judgment to the Asm program.  The entry applies when a program on fixed arguments, a program that reads its input, a request loop, or a controller needs that Lean theorem, and `native-conclusion-patterns` describes how the lemmas below take apart the native theorem.

A program on fixed arguments needs no proof by hand.  The command `bare_program p.f x [a₁, …] r` of `Verified/Bare.lean` adds the theorem `p.f.program`: for every list `pre` of CompCert's declarations with `LeanExe.Native.PrefixOk pre`, the program `bareProgram pre p.translation (bareMain nativeCap k [a₁, …] kind)` terminates with result 0 after storing the bytes of `r` to `lx_out`, `encodeWord r` for a word and `encodeArray r` for an array, or, when `f` may abort, with no event and the code of `unreachable`.  The command reads the entry `k`, the flag `aborts`, and the result's type from `p.f.implements`, and it proves the theorem with `LeanExe.Native.bare_of_nativeA`.  When `p.f.implements` states `ImplementsTables`, it uses `Verified.bare_of_nativeTables` and proves from `p.initial` that each table is a borrowed array of the initial store, which its tactic does for at most four tables.  The words `a₁, …` are the words of the argument `x`, and `r` must be `f x`.

A program that reads its input runs `inMain`, which loads a length and the message's bytes from `lx_in`, allocates an array for them with `alloc`, and calls the entry on the array and the length.  `LeanExe.Native.input_program` gives, for every sequence `σ` of the values that the volatile loads read, a termination of `inProgram pre T (inMain cap k kind)` whose trace and result `LeanExe.Native.InResult σ aborts out` describes.  Its premise `LeanExe.Native.EntryInRuns` is the run of the entry on the array that `main` builds, for every length up to `inMax` for which the heap has room and every message.  `TestSupport.Bare.sha256_runs` proves it from the entry's tables theorem.  `LeanExe.Native.input_owned` gives the heap after the allocation, the owned array, the writes inside its block, and the array's bytes, and `Verified.borrowed_nativeStore` with `LeanExe.Pipeline.Heap.Borrowed.allocate_within` keeps the table of round constants borrowed across the allocation.  The proof then joins the native theorem's result with the specification through `Library.Hashing.Sha256.sha256_bytes`, and `LeanExe.Native.InResult.reads` gives `Reads σ t`, the Lean form of the `reads` premise of `clight2_bigstep_asm_reads`.

A request loop runs a step `tick : G → UInt64 → G × UInt64` forever and performs, in each window, the one register access that the step requests (`reqMain`).  `LeanExe.Native.req_program` proves `LoopReacts A X (reqProgram pre T (reqMain k (words s0))) E0 (reqTrace regBus tick s0 σ)` for every `σ` from `LeanExe.Native.ReqRuns`.  `LeanExe.Native.reqRuns_of_nativeA` gives `ReqRuns` for a step whose native theorem excludes the trap, whose precondition holds everywhere, and whose state's `Scalar` values are the words `words g`, of one length for every `g`.  The other premises are closed facts about the translation: the signature from `LeanExe.Native.sig_eq` by `decide +kernel`, the entry's C type from `LeanExe.Native.entry_type` and `rfl`, the number of result globals from `LeanExe.Native.translate_nres` and `LeanExe.Native.translate_funcs_eq` by `decide +kernel`, and the initial heap from `Verified.Ready.initial rfl p.initial` and `LeanExe.Native.heapAt_nativeStore`.  A controller with one word of state follows the same steps with `LeanExe.Native.ctl_program` and `LeanExe.Native.ctlRuns_of_nativeA`, and each of its windows loads a word from `lx_in` and stores the new state's bytes to `lx_out`.  `LeanExe.Native.req_reads` and `LeanExe.Native.ctl_reads` give the `reads` premise of `clight2_loop_to_asm`.

The theorems concern `bareProgram`, `inProgram`, and `reqProgram`, the Lean copies of the programs.  The step to the program that `clightgen` reads rests on a comparison that each build runs, which the trusted base lists (`docs/native-bare-metal.md`, section "From the Lean theorem to the machine code", and `docs/trusted-base.md`, section "METAL: Bare-metal images").  `bare_program` stops with an error that names the theorem when `p.f.implements` states neither `ImplementsA` nor `ImplementsTables`, or when the result is neither `UInt64` nor `Array UInt64`, and it raises `maxRecDepth` to 100,000 around the theorem it adds.  `reqRuns_of_nativeA` and `ctlRuns_of_nativeA` take a native theorem whose flag `aborts` is `false` and whose precondition every state meets, so a step that may trap or that needs a precondition does not fit them.  A request loop's theorem states its register accesses, and the bytes that they exchange need the framing proofs of `request-output-prefix`.  The tests use `TestSupport.Native.sig_of`, a copy of `LeanExe.Native.sig_eq`.

`TestSupport.Bare.sha256_input` is the program with input.  `TestSupport.Bare.echo_program` and `TestSupport.Bare.deadline_program` are request loops over UART0 and Timer0 of `mps2-an500`, `TestSupport.Bare.sum_program` and `Demos.Energy.gw_program` are request loops whose states are structures with `Flat` instances, and `Demos.Energy.gw_usart3_program` runs the energy gateway on USART3 of the NUCLEO-F767ZI.  `TestSupport.Bare.filter_program` is the controller, a low-pass filter.  `tests/TestSupport/Bare/Theorems.lean` applies `bare_program` to CRC-32, SHA-256, the Euler solver, and a recursion that may reach the depth limit.
