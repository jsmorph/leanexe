# A proof about a value that a later argument fixes

A lemma may take a proof about a value that only a later argument determines, such as a proof about the program's tables when only the readiness hypothesis names them.  Lean elaborates the arguments of an application in order, so it elaborates the proof while the value is still a metavariable.  A term such as `List.mem_singleton.mp ht` then fails to unify with `tableAddr ?tables 0`, and the error has the form `Application type mismatch … expected to have type x ∈ [(tableAddr ?m 0, ?m[0])]`.

Make the value an explicit argument placed before the proof, as `Verified.ImplementsTables.call` takes `tables` before the proof that the entry's tables are among the program's.  A proof stated once as a named lemma at the concrete value avoids the problem as well, as `Library.Hashing.Crc.crc32c_table` does, and `Verified.tables_at` states the fact for a list of table indices.  A tactic block also elaborates, because Lean postpones it to the end of the application, but the explicit argument keeps the call readable and the error local.

A form of the generic call theorem that takes the tables from the readiness hypothesis, after the table proof, fails in this way at every call site.  `Library.Hashing.Sha256.sha256_call` passes `compiled.tables` and then `fun _ ht => ⟨0, by decide, List.mem_singleton.mp ht⟩`, and `Library.Numerics.Float64.Bessel.BesselBytes.y0_entry_call` passes `Verified.tables_at [0, 1, 4, 5, 2] (by decide) rfl`.  The `rfl` evaluates the sizes of the tables before the last index, so a declaration that uses it beyond the first table raises `maxRecDepth`, as the Bessel entries do.

When the later argument fixes a large literal, the unification can unfold the literal until it reaches the maximum recursion depth instead of failing at once.  `ClightN.Proof.program_to_n` of `LeanExe/Native/ClightN/Exec.lean` takes the check `progOk p.prog_defs p.prog_main S = true` before the execution that names the program `p`, and in the SHA-256 instance of N the unification of `?p.prog_defs` with the definitions of the file's program unfolded the program's literal past `maxRecDepth`.  `ClightN.Proof.terminates_n` of `LeanExe/Native/ClightN/Instance.lean`, through which the instances reach `program_to_n`, therefore supplies the program by name: `program_to_n (p := fileProgram fd fm)`.
