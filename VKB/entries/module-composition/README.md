# Functions added to or appended with a compiled program

A program of `verified_compile` carries its typed program `p.program : Verified.Prog S`, the meanings `p.funs` of its functions, and the proof `p.meaning` that relates them.  A typed function written over those signatures can call the compiled functions, and `Verified.Prog.append` joins two compiled programs into one.  The entry applies when the functions of such a combined module need theorems of the form `ImplementsA` or `ImplementsPureA` without a second reflection of the callees.  The method's only uses are the compiler's examples in `Verified/Examples`, and `Library/Random/SplitMix64/README.md` and [the manual's section on module composition](../../../docs/verified-manual.md#module-composition) describe it for the reuse of a library program.

To add a function, write a `Verified.Func S` over the program's signature list `S`, which lists the newest function first, and call a compiled function with `.call` of an `FVar` that counts from the head of `S`, as `Verified.Examples.Composition.wordFunc` calls `add` with `.there .here`.  `Prog.cons f p.program` builds the larger program, and `Verified.compile` its module.  `Verified.Prog.correct_funs` gives `Verified.Calls` for every function of a program without recursive or tail-recursive functions and without literals, with the meanings that the program defines, and `Verified.Prog.correct` gives it from a meaning proof such as `.cons p.meaning`.  For the compiled functions alone, `Verified.Prog.calls_extension` gives `Calls` with their own meanings and bounds from `p.meaning` and a prefix of the function lists, which `Verified.Prog.functions_prefix_cons` builds one added function at a time.

To join two compiled programs, `source.program.append library.program` keeps the library's functions at their indices and places the source's after them, and `Verified.Funs.append` and `Verified.Prog.Meaning.append` join the meanings.  A new function refers to a retained library function with `Verified.FVar.appendRight` and to a relocated source function with `Verified.FVar.appendLeft`.  `Verified.Prog.calls_append`, or `calls_extension` with `Verified.Prog.functions_prefix_append`, gives the library's `Calls` in the combined module, and `Verified.Prog.covered_append` gives the coverage premises of a shared literal pool.

Each function's theorem comes from `Calls` at the function's `FVar` and depth 0.  `Verified.ImplementsA.lean ((calls v 0).implementsB_unpaid rfl rfl).implementsA` states `ImplementsA` over Lean's tuples at the module index `v.callIndex`, which is 2 plus the function's position in the module's function list counted from the oldest, since the runtime's `alloc` and `release` are functions 0 and 1.  The two `rfl` premises of `Verified.FunSpec.implementsB_unpaid` state that the function's code does not take the call depth and that no parameter is paid.  For scalar arguments and results, `Verified.implementsPure_of_uniform` turns `ImplementsA` with trivial conditions into `ImplementsPureA`, the theorem that a call keeps the store, from an `EntryUniform` fact that `Wasm.EntryUniform.of_code` proves for an instruction list written out by hand, or that `Verified.Reflect.scalarEntryProof` builds in a `run_cmd`.

When the new function's `denote` differs from the intended Lean function, an execution proof that unfolds the imported definitions to close the difference exhausts the heartbeats.  A separate lemma such as `Verified.Examples.Relocation.caller_denote` proves the equation from the callees' generated `denote_eq` with `congrArg₂`, and the execution theorem rewrites with it, as `callBoth_implements` does with `simpa only [caller_denote]`.  The intermediate statement of `callBoth_implements` names its types with `(α := UInt64) (β := UInt64)`, which instance search does not find through the projection of the source function.  `prefix` is a keyword of Lean, so a compiled program named `prefix` does not parse, and the relocation example names its program `seedLibrary`.  `Verified.Prog.correct` requires a program without literals, and `Verified.Prog.correctStatic` takes a literal pool and its coverage premise otherwise.

`Verified.Examples.Composition` adds `wordCaller` and `floatCaller` to `Verified.Examples.CompositionBase.compiled`, with `Verified.Examples.Composition.base_calls` from `calls_extension` and `Verified.Examples.Composition.wordCaller_implements` from `correct_funs`.  `Verified.Examples.CompositionBase.add_pure` proves the store-keeping theorem of a compiled function in any module whose functions after the runtime begin with the program's, through `Verified.Prog.calls_prefix` and `Wasm.EntryUniform.of_code`.  `Verified.Examples.Relocation` places the program of `Verified.Examples.ScalarComposition.compiled` after `seedLibrary` with `Verified.Prog.append`, adds `callBoth`, which calls a function of each, and proves `Verified.Examples.Relocation.callBoth_implements` and `Verified.Examples.Relocation.callBoth_pure`.
