# Closed computations

Many steps of a program proof are closed facts: a table entry, a constant of a standard, the address of a table in the initial store, an export of a module, or the bytes of an emitted file.  `decide +kernel` proves such a fact by having the kernel evaluate it.  The elaborator's plain `decide` often stops at its recursion limit on the same goals.

Do not use `native_decide` or `bv_decide`.  Both add an axiom that trusts compiled code, and the library's theorems depend only on `propext`, `Classical.choice`, and `Quot.sound`.  The SHA-512/t initial values of the copied FIPS 180-4 transcription were proved with `native_decide`, and they now use `decide +kernel`, which takes 40 seconds.

When the kernel's evaluation runs deep, raise the limit for one declaration with `set_option maxRecDepth N in`.  `Library.Hashing.Crc.crc32c_table` uses 10,000, because the address of the second CRC table depends on the size of the first.  The file theorems use 100,000, because the bytes they compare nest as deep as the file is long.  Lean also refuses to evaluate a power whose literal exponent exceeds `exponentiation.threshold`, 256 by default, so a proof that evaluates such a power raises that option.

A goal that `decide +kernel` takes minutes to check usually states more than it needs.  Check constants as whole words rather than bit by bit: each SHA-3 round lemma, such as `Library.Hashing.Sha3.RoundProof.round_0`, checks its round constant as one list of 64 bits, after the elaborator's `decide` reached its recursion limit from round 10 on.  Prove a table's entries against a short definition once, rather than at every use: `Library.Hashing.Crc.Proof.crc32Table_of` unfolds `TableOf` and `Holds` and checks all 256 entries against eight bitwise steps of `lfsr`.  A fact over a bounded range of a natural number can take the form `∀ E, E < N → … = true`, which `decide +kernel` checks over the whole range, as `Library.Numerics.Decimal.PrintFloat.PrintFloatSteps.wide_binary64` does for 2,048 binades.  An export's membership in a module's export list is another closed fact, as `Library.Hashing.XxHash64.xxh64_export` shows.

When a closed fact concerns a compiled module, keep the module from reaching the kernel as one term.  `compiled.initial` states the initial store of `Verified.compileWith` at the default literal pool, and given directly where `Verified.Ready compiled.module compiled.tables` is expected, it reaches the recursion limit for the modules of CRC and of the exponential.  `Verified.Ready.initial` takes the pool's equation as a premise, so that Lean matches `compiled.module` by its definition, and `Verified.Ready.initial rfl compiled.initial` checks without a raised limit, as `Library.Numerics.Float64.Exp.ExpTheorem.exp_bytes_accuracy` shows.  `compileWith` takes the pool as an optional argument and Lean otherwise inserts the default, so a rewrite that should use a supplied pool must name it, since rewrites that left it implicit selected the default pool.  The `large-term-unfolding` entry gives the related rule for rewriting a store before a kernel check.

`Verified.Prog.Covered prog pool` states that the pool holds every byte literal of the program, and it has no decidability instance.  For a program without literals, prove `prog.literals = []` by `decide +kernel` and close the coverage with `simp only [Prog.Covered, noLiterals, List.nil_subset]`, as `Verified.Examples.CompositionBase.add_pure` does.  The equation on `literals` is the closed computation, and the subset step needs no evaluation.
