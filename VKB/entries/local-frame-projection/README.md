# Equality and projections of raw Wasm locals

The entry applies to proofs that step through Wasm code with Talos's `wp` rules and must reason about `Wasm.Locals`: the parameters, the internal locals, and the operand stack of a Talos frame.  The lemmas of `LeanExe/ProofKit/Frame.lean` serve proofs of hand-written code, such as the runtime's `alloc` and `release`.  The proofs of the verified compiler's generated code use the lemmas of `Verified/LocalFrame.lean` for the same facts, and `Verified.Frame` there relates the locals before and after an expression's code position by position.

Talos's `Wasm.Locals` has no extensionality theorem of its own.  `LeanExe.ProofKit.Frame.ext`, tagged `@[ext]`, proves two frames equal from equal parameter lists, internal-local lists, and operand stacks, either applied to the three equations or through `ext <;> simp_all` when they follow from the context.  The runtime's proofs use it as `Frame.ext _ _ rfl rfl hValues.symm`, from `hValues : frame.values = []`, to show that `{ frame with values := [] }` is `frame`, so that a rule stated for a frame with an empty operand stack applies, and `LeanExe.ProofKit.Frame.of_withValues` states that step as one lemma for any operand stack.

`LeanExe.ProofKit.Frame.withValues_get`, `LeanExe.ProofKit.Frame.withValues_params`, `LeanExe.ProofKit.Frame.withValues_locals`, and `LeanExe.ProofKit.Frame.withValues_values` give the fields of `{ frame with values := vs }` after a block, branch, or call rule replaces only the operand stack, and `Verified.Locals.get_values` is the verified compiler's form of `withValues_get`.  Prefer them to unfolding `Wasm.Locals.get`, a `simp` definition whose unfolding splits on whether the index is a parameter or an internal local.  The verified compiler's proofs write a store to an internal local as `Verified.setLocal`, which `Verified.Locals.set?_local` relates to Talos's `Wasm.Locals.set?`, and read it back with `Verified.Locals.get_setLocal_same` and `Verified.Locals.get_setLocal_ne`.

For repeated stores that keep a different index, `List.getElem?_set_ne` with the index inequality avoids the `if` that `simp` makes of every update, as the proof of `Verified.Locals.get_setLocal_ne` does.  `LeanExe.ProofKit.Frame.parameter_getElem_of_get` turns `frame.get index = some value`, for a parameter index, into `frame.params[index] = value`.  `LeanExe.ProofKit.Frame.internal_getElem?_of_get` and `LeanExe.ProofKit.Frame.internal_getElem_of_get` turn the same fact at index `parameterCount + localIndex` into one about `frame.locals[localIndex]`, from the parameter count and the bound on `localIndex`, for every `Wasm.Value` kind and any number of locals.

A long proof over generated code that stores to many locals names each state.  A record update of a state that is not a variable, such as `{ setLocal s i v with values := vs }`, elaborates to a binding `__src` of the state followed by a literal, as [the entry on lemmas that close goals of structure literals](../structure-update-lemmas/README.md) describes, so after several stores of `Verified.setLocal` the states differ in form from the sides of the `rw` and `simp` lemmas that should match them, and the length of a state's locals becomes a length of `List.set` that only `List.length_set` reduces.  `Verified.Wasi.wp_sys_reported_with` and `Verified.Wasi.wp_sys_reported_call_with` name each state with `let s1 := setLocal s base (.i64 0)`, restate the goal with `change wp target _ Q initial s1 env` after each store, prove the facts of the named state, and supply them with `exact`, which compares up to definitional equality.  `Verified.Wasi.wp_localGet_get` takes the value of a local as a hypothesis, `s.get i = some v`, and so reads a local without a rewrite inside the state.

`LeanExe.ProofKit.MemoryGrowth.ensureProgram_spec_available`, `LeanExe.ProofKit.FixedArraySearch.guardProgram_spec`, `LeanExe.ProofKit.FixedArrayHeader.writeLocal_specA`, and `LeanExe.Pipeline.joinProgram_spec` each prove one part of `alloc` or `release`, with `wp` or its aligned form `wpA`.  All four close a frame equality with `LeanExe.ProofKit.Frame.ext`, and the first three also rewrite with `LeanExe.ProofKit.Frame.withValues_get`.  They are the models for a proof of further hand-written code.
