# Satisfiable hypotheses and complete conclusions

The entry applies to a theorem whose hypotheses come from a configuration, a tool's settings, or a predicate of a model, and to a theorem whose conclusion is a prefix, a bound, or an existential.  Such a theorem holds vacuously when no case of interest meets its hypotheses, and its conclusion says little when a trivial run meets it.  The kernel accepts both, so no failing proof reveals them, and further theorems must show that the hypotheses can hold and that the conclusion excludes the trivial run.

Prove each hypothesis of a witness built from every configuration in which the theorem is claimed.  The floating-point theorems of `tools/sail/F7` hold for every state that satisfies `F7.Hyp`, and `F7.hyp_tcg`, `F7.hyp_kvm`, and `F7.hyp_sme` of `tools/sail/F7/Isla.lean` prove `Hyp` of the state that `F7.islaState` builds from each Isla profile, for every value of the profile's unknowns.  `F7.names_tcg`, `F7.names_kvm`, and `F7.names_sme` check, for each feature that the proofs read, that the line of the profile's `features` file at the feature's index names it ([the Sail README's section on the join with the Isla equations](../../../tools/sail/README.md#the-join-with-the-isla-equations)).  For a predicate of a model, prove that something satisfies it, as `Demos.Energy.Spec.admitted_exists` builds a trajectory that the energy controller admits and [the entry on specification call theorems](../spec-call-theorem/README.md) describes.  State a premise over a quantity that the caller controls and derive the specification's premise from it: `TestSupport.M7.Sha.sha_digests` takes fewer than 2^62 windows, and `LeanExe.Requests.frame_reads`, which bounds the bytes read by half the windows, with `LeanExe.Requests.decode_lengths` gives the fewer than 2^55 blocks that the SHA-256 specification needs.

A premise taken from a tool's configuration describes the state at which a check starts only when the reference changes nothing it sets before that point, so compare each configured value with the reference's code from reset to the start.  The Isla traces start at the decode, and the Sail model's `__InstructionExecute` sets the PipeAdv field of EDSCR before the decode, so `LeanExe.A64.Isla.Profile.sys` gives `_EDSCR` with PipeAdv set, as its docstring and the comment of `tests/isla/traces.sh` state.  A profile with a value that the reference overwrites before the decode describes no state that the processor reaches at the decode, so every theorem of `Agrees` under it speaks of no run of the processor while its proof succeeds.  [The Sail README's section on the state hypothesis](../../../tools/sail/README.md#the-state-hypothesis) traces the registers that `F7.Hyp` names to their sources in Isla's configuration and the profiles in the same way.

A prefix theorem `out <+: spec inp` holds of a run that writes nothing, so pair it with a statement that bounds what is missing.  `LeanExe.Requests.delim_prefix` states that the bytes written begin the answers to the segments read, and `LeanExe.Requests.delim_answered` states that whenever a window reads a byte, the bytes written are all those answers.  `TestSupport.M7.Crc.crc_replies` adds to its prefix that at most one byte read waits for its reply, and `TestSupport.M7.CrcBoardFile.crc_board_prefix` of `tests/TestSupport/M7/CrcBoardFile.lean` carries both clauses to the board.  An existential conclusion holds trivially when its witness is free: `TestSupport.M7.Gw.board_bytes` states the gateway's output for records `recs` whose bytes are the bytes read up to the last complete record, and `LeanExe.Requests.flatMap_recordBytes_inj` states that records of `kin` words are determined by their bytes, so the records of the conclusion are those that the bytes encode.

Leave out a premise that the model's own stop already excludes, since it restricts nothing and reads as a restriction.  `exec` gives no state for UDIV with a zero divisor, and `Agrees` concerns the states that `exec` gives, so `TestSupport.M7.Isla.udiv_agrees` of `tests/TestSupport/M7/Isla/MulDiv.lean` takes no premise on the divisor.  The module's header states instead that the theorem covers no zero divisor, for which the trace writes 0.

The worked examples are `F7.hyp_tcg`, `F7.hyp_kvm`, `F7.hyp_sme`, `Demos.Energy.Spec.admitted_exists`, `TestSupport.M7.Sha.sha_digests`, `LeanExe.Requests.delim_answered`, `TestSupport.M7.Crc.crc_replies`, and `TestSupport.M7.Gw.board_bytes`.  The `F7` theorems lie in tracked files that the repository's build does not compile, and the board's file module and the Isla theorems read files at elaboration, so `entry.json` lists their names under `unimported`.  [The entry on the output of request programs](../request-output-prefix/README.md) proves the prefix theorems that the completeness statements accompany, and [the entry on floating-point equations from Sail](../sail-fp-equations/README.md) uses `F7.Hyp`.
