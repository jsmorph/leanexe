# Bytes packed eight to a word

A program that reads a byte string takes it as an `Array UInt64` with eight bytes to a word in little-endian order, and its specification reads the string through `Library.Bytes.bytes msg n`.  The proof that the program computes its specification meets the same goal at every byte it reads.  The compiled expression `msg[(UInt64.ofNat i >>> 3).toNat]! >>> ((UInt64.ofNat i &&& 7) <<< 3)`, often masked with `&&& 255`, must equal byte `i` of the string.

`Library.Bytes.byteAt msg i` is byte `i`, and a word past the end of `msg` reads as zero, as a read past the end of an array does in the compiled code.  `Library.Bytes.bytes msg n` is the first `n` bytes, `bytes_size` and `bytes_get!` give its size and its bytes, and `byteAt_eq` rewrites byte `8 * i + k` to `byteOf msg[i]! k`.  The proof of the goal takes three steps for `i < 2 ^ 64`.  First, `UInt64.toNat_ofNat_of_lt'` turns `(UInt64.ofNat i).toNat` into `i`.  Second, `UInt64.toNat_shiftRight` with `Nat.shiftRight_eq_div_pow` turns the word index into `i / 8`, and `UInt64.toNat_and` with `Nat.and_two_pow_sub_one_eq_mod` turns the shift amount into `8 * (i % 8)`.  Third, `UInt64.toNat_inj` reduces the equation to natural numbers, where the definitions of `byteAt` or `byteOf` close it.

Three libraries proved this goal separately: `Library.Hashing.Crc.Proof.natBits_word`, `Library.Regex.RunProof.input_byte`, and `Library.Hashing.XxHash64.Proof.byte_eq`.  They differ only in the form of the result: a list of bits, a masked word, and `byteOf` of a word.  A new program should reuse the closest of them rather than prove the goal a fourth time.  One shared lemma in `Library.Bytes` would replace all three, as a separate code change.

A specification that reads eight bytes as a little-endian word, as the SipHash and XXH64 transcriptions do, writes the word's value as `bs.foldr (fun b acc => b.toNat + 256 * acc) 0`.  `Library.Bytes.foldr_byteOf` shows that the eight bytes `byteOf w 0` through `byteOf w 7` have the value `w.toNat`, through `foldr_range`, which writes the fold as a sum of digits, `sum_digits`, which collects the digits below a power of 256, and `byteOf_toNat`.  `foldr_le` splits off an initial value, and `chunk_eq` writes the `k` bytes of a list from position `i` as a map over positions, which is the form in which the transcriptions take each 8-byte chunk.  `Library.Hashing.SipHash.Proof.le64_bytes` and `messageWords_eq` use them to equate the packed message's words with the message words of the SipHash paper, and `Library.Hashing.XxHash64.Proof.lane_le` does the same for XXH64's lanes.
