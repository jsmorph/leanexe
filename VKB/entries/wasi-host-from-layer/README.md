# WASI hosts built on a lower layer

The entry applies when a lower layer whose steps record events, such as the Linux call layer of `LeanExe/Linux/`, implements the WASI imports of a compiled module, and a theorem must state what the lower layer did in a run that the WASI command theorem describes.  `Verified.Wasi.compiled_native_start_run_with` holds for every host environment that satisfies `Verified.Wasi.hostSpecWith host calls`, so the work is a host whose relations name the lower layer's events, an environment that satisfies its specification, and a lift of the theorem's classification of a run to a statement about those events.  [The WASI manual's section on the Linux shim's specification](../../../docs/wasi.md#the-linux-shims-specification) describes the shim of `Verified/Shim/`, which does this for `fd_read`, `fd_write`, `proc_exit`, and the flat calls of `Verified.Shim.shimCalls`.

Define the host's relations from an image relation that sees no store.  `Verified.Shim.Image` states which lower events a WASI event makes after the lower events before it, fixes each event's call, descriptor, count, and inputs, and derives the WASI reply from the lower results, and it leaves free the buffer's address and a read's bytes before the call, which depend on the store.  `Verified.Shim.ShimStep` appends an image to the world, with `Verified.Shim.Carried`, which ties each event to its reply by the number of events before it, and with the bound `Verified.Shim.WritesWithin` on the events' output regions, and `Verified.Shim.linuxHost` answers reads, writes, and flat calls with it.  The host's bounds on stream replies, its laws `read_bound` and `write_bound`, follow from the bounds of the reply functions, `Verified.Shim.readReply_valid` and `Verified.Shim.writeReply_valid`, its law `sys_bound` from `Verified.Shim.sysImage_shape`, which gives each flat reply the sizes of the call's description, and its laws of the exit marker from the updates of the world.

The world holds an exit marker beside the lower events.  `LeanExe.Wasi.Host` requires an accepted exit to set the marker (`exit_recorded`) and every other step to keep it, so a host whose world is only the log of lower events, with the marker computed from the log, accepts an exit only from a world whose marker already holds the status when the exit adds no lower event, as the shim's exit adds none.  No run from a world without a marker then reaches an accepted exit, so a theorem over such a host says nothing of a program that exits, a defect of the kind that [the entry on satisfiable hypotheses and complete conclusions](../non-vacuous-statements/README.md) describes.  `Verified.Shim.LinuxWorld` therefore holds the events, the marker, which the exit of `linuxHost` sets, and the outputs that the reported sizes of flat calls need.

`LeanExe.Wasi.Host.sys_reports` requires that, in the world after a successful flat call, every call whose reporter has that call's name reports the sizes that the call's outputs give.  `Verified.Shim.LinuxWorld.answer` records the outputs of every successful flat call by name with `Verified.Shim.recordReports` and keeps them in later worlds, and `Verified.Shim.shimReported` gives each call the sizes of the recorded outputs of its reporter, except that it takes the sizes of `args_get` and `environ_get` from the launch.  A host that takes reported sizes from a parameter must show that the reporter's outputs agree with it, and `Verified.Shim.sysImage_reporter` shows that a successful `args_sizes_get` or `environ_sizes_get` in an image returns the launch's outputs.

A host whose answer depends on its own earlier calls reads that state from the world's lower events.  `Verified.Shim.openNumbers` gives the descriptor numbers that the shim holds open, 3 when the launch grants it and each number below `Verified.Shim.descriptorLimit` that an `openat2` returned and no later `close` ended, and `Verified.Shim.preopened` whether 3 is still the preopened directory.  `Image` takes the events before the call, and `Verified.Shim.Images` threads them from image to image.  A property of the lower trace then follows image by image: `Verified.Shim.image_namesHeld` proves `Verified.Shim.NamesHeld` of one image, `Verified.Shim.images_namesHeld` places an event of the lower trace in its image by induction on `Images` with `List.append_eq_append_iff`, and `Verified.Shim.footprint_namesHeld` holds for every command and every reply sequence, since the host refuses every number outside `openNumbers` without a call.

A loop of lower calls inside one WASI call, such as the `getrandom` calls of `random_get`, each of which asks for the bytes that remain, or the calls of `openat2` that `path_open` makes again after `EAGAIN`, is a relation defined by recursion on the image's events, `Verified.Shim.RandomCalls` and `Verified.Shim.OpenCalls`, and a function defined by well-founded recursion in the environment, `Verified.Shim.randomLoop` and `Verified.Shim.openLoop`.  `Verified.Shim.randomLoop_spec` and `Verified.Shim.openLoop_spec` prove that the function's events meet the relation and hold their replies by strong induction on the measure, after `rw` with the function's equation.  `randomLoop` states the condition of its recursive call with the reply itself, `(replies k).ret.toNat`, for the reason that [the entry on tactics whose failures mislead](../tactic-combinator-pitfalls/README.md) gives for `omega` in `decreasing_by`.

A lower event records the bytes of its output region before the call, so two memories give the same event only when they hold the same bytes there.  The image fixes those bytes where the shim writes them before the call and leaves them free where the store determines them: the shim clears the timespec of its scratch before each `clock_gettime`, so `Verified.Shim.ClockImage` and `Verified.Shim.clockEvent` record zeros, while a read's bytes before the call stay free.  The requests of `clock_gettime` and `openat2` name only the shim's scratch, outside the Talos store, and `Verified.Shim.step_clock` and `Verified.Shim.step_openat2` give their events for every `LeanExe.Linux.Memory` and every memory that holds the bytes that the shim writes there, so they hold of a binding's memory as well as of the shim's.

Implement the environment with the lower layer's own step on a view of the guest's memory.  `Verified.Shim.shimMemory` meets `LeanExe.Linux.Memory.Lawful` for every base, with offsets taken modulo 2^64 (`Verified.Shim.shimMemory_lawful`), `Verified.Shim.shim_readBytes` and `Verified.Shim.shim_writeBytes` state the layer's byte strings as `Wasm.Mem.readBytes` and `Wasm.Mem.writeBytes`, and `Verified.Shim.step_read` and `Verified.Shim.step_write` evaluate the step for a request inside the memory.  Each stream contract's proof rewrites the request's checks with the premise's fields, evaluates the step, generalizes the reply, and closes the frame with `Verified.Wasi.frame_payload`, `Verified.Wasi.frame_count`, `Verified.Wasi.frame_host`, `Verified.Wasi.written_at`, and `Verified.Wasi.at_count`, as `Verified.Shim.read_contract` and `Verified.Shim.write_contract` do.  `Verified.Shim.linuxEnv` places the stream functions first and a function for each call of `calls` after them, and `Verified.Shim.linuxEnv_satisfies` proves that it satisfies `hostSpecWith (linuxHost F L I replies) calls` for every module with at most the stream imports and `calls`, when `shimCalls` holds every call of `calls`.

A flat call's contract `Verified.Wasi.sysContract` holds for a function whose result for every admitted request is the shim's answer with a memory, lower events, and a reply.  `Verified.Shim.sys_contract_of` reduces the contract to three facts: the shim's step in the host's relation, `Verified.Shim.MemFrame` of the memory over the request's output regions, and the outputs in their regions on errno 0, and `Verified.Shim.sys_contract` gives the contract of each call of `shimCalls`.  A contract's proof reads the request's shape off `Verified.Wasi.argsFit` one parameter at a time with `Verified.Shim.argsFit_takes`, and `cases` on each argument followed by `simp` of its fit closes the other kinds before the next argument, as `Verified.Shim.open_shape` does, where a case split of every argument at once makes a goal for each combination of kinds.  It states the request's output regions as a literal list by an equation proved by `rfl` and rewrites with it before it applies a lemma about a literal list of regions.  It writes the outputs of a successful reply with `Verified.Shim.placeReply` and takes the frame and `ShownAt` from `Verified.Shim.placed`, which applies `Verified.Wasi.OracleSys.shownPlaces_spans`, `Verified.Wasi.OracleSys.shownAt_of`, and `Verified.Wasi.placeAll_at`, or from `Verified.Shim.placed_one` for one region, as `Verified.Shim.open_contract` does.

The lift follows the runs.  `Verified.Shim.exec_appended` inducts on `LeanExe.Wasi.Exec` with `LeanExe.Wasi.Exec.rec` and both motives, as `Verified.Wasi.exec_observed` does, and `Verified.Shim.prefix_appended` inducts on `LeanExe.Wasi.Prefix`, each to `Verified.Shim.Appended`, which chains the events, their images, and their replies with `Verified.Shim.Images.append` and `Verified.Shim.Carried.append`.  `Verified.Shim.footprint_of_result` cases on the native result, applies `Verified.Wasi.exec_observed` or `Verified.Shim.prefix_observed` to pass from the observed world to the host's, excludes a returned command with `Verified.Wasi.bind_exit_not_returned`, and gives `Verified.Shim.Footprint`, which `Verified.Shim.shim_footprint` composes with `compiled_native_start_run_with` and `linuxEnv_satisfies`.  `Verified.Shim.Images.readData` and `Verified.Shim.Images.writeData` give the bytes that the lower reads and writes of a descriptor moved, by `LeanExe.Linux.readData` and `LeanExe.Linux.writeData`, as the bytes that the WASI trace's events read from or wrote to it, `Verified.Shim.committedReads` and `Verified.Shim.committedWrites`, the form that a corollary over the lower trace needs.

A corollary under `linuxHost F L I R` states its premises on the replies `R`, a `LeanExe.Linux.Replies`, which maps the number of a lower call to its reply and does not know which call each number names.  A premise over that function alone, such as a positive result for every write, also constrains replies that no call uses and the replies of reads, for which 0 means end of input, so it excludes real runs.  A premise that the corollary needs only of a finished run is a predicate over the run's final lower events, in the form of `LeanExe/Linux/Replies.lean`, which constrains exactly the replies that the run consumed: `Verified.Examples.WasiReadAll.linux_exec_message` and `Verified.Examples.WasiReadAll.linux_message` conclude the exit's status and `Verified.Examples.WasiReadAll.Copies` for the runs whose events meet `Verified.Examples.WasiReadAll.ReadsSucceed` and `Verified.Examples.WasiReadAll.WritesAdvance`.  A premise that must hold before any run exists, such as the budget of `Verified.Wasi.Resource.CallPrefixBound`, which bounds every prefix from the start world, cannot come from final events, since a run that traps in the guest ends before the calls that would leave the class.  `Verified.Examples.WasiReadAll.Steady` therefore constrains `R k` at the residual of each prefix of the action, in the form of `LeanExe.Wasi.Host.NoTrapsAlong`, and `Verified.Examples.WasiReadAll.Steady.along` turns it into `Verified.Examples.WasiReadAll.SteadyAlong`, a condition on the host's WASI replies, which the proof of the budget carries along the commands, as [the entry on WASI effect charges](../wasi-effect-charges/README.md) describes.  `Verified.Examples.WasiReadAll.succeeded_of_steady` gives `Verified.Examples.WasiReadAll.Succeeded` of every event of a run from it, which `Verified.Examples.WasiReadAll.linux_exec_succeeded` takes, so `Verified.Examples.WasiReadAll.linux_steady` has no premise on the final events.  The module docstring of `Verified/Examples/WasiReadAllSteady.lean` states which of Linux's replies the class holds and which it excludes, from read(2), write(2), and pipe(7).

A run of an action that makes no flat call is a run under every choice of the open flags and the launch, since `Verified.Shim.linuxHost` reads them only in the images of flat calls.  The transfer needs the absence of flat calls from the action, since neither `Images` nor the footprint gives it: a flat call can have an image without lower events, as `clock_time_get` of clock 2 or 3 does.  `Verified.Shim.StreamAction` states that absence of an action by structural recursion through every continuation, `Verified.Shim.Exec.streamTrace` and `Verified.Shim.Prefix.streamTrace` derive `Verified.Shim.StreamTrace` of the run's trace, and `Verified.Shim.Exec.streams`, `Verified.Shim.Prefix.streams`, and `Verified.Shim.Images.streams` move the run and its images to another choice.  `Verified.Shim.ShimStep` checks `Verified.Shim.WritesWithin`, whose second disjunct reads the layout's timespec, so the two layouts must agree on the timespec as well as on `base`: a `read` whose output region is the timespec meets `WritesWithin` under one layout and can fail it under another.  A `LeanExe.Wasi.Prefix.bind` step leaves the residual of a sub-action, so the induction of `Verified.Shim.Prefix.streamTrace` needs a stronger hypothesis than `StreamAction action`: `Verified.Shim.Prefix.streamTrace_bind` states the result for `action.bind next` and every `next`, and `LeanExe.Wasi.Action.bind_pure` recovers the plain form.  `Verified.Shim.Images.streamCalls` adds that every lower event of such a trace is a `read` or a `write`, and `TestSupport.A64.ImageFilesWasiElf.readall_elf` of `tests/TestSupport/A64/ImageFilesWasiElf.lean` combines these lemmas with `Verified.Examples.WasiReadAll.main_streams` to hold for every choice of flags and launch.

`Wasm.HostEnv.Satisfies` requires each contract at every store, including stores that no run reaches, and the host's relations see a world and a request but no store.  A bound that holds only along runs, such as writes within a memory that stays below a native cap, therefore cannot enter the host: at a store whose memory exceeds the cap, a request whose buffer lies beyond the cap passes the contract's premise, every reply that such a host admits carries an event within the cap, and the environment satisfies the contract only by recording an event at an address that it did not use.  The host bounds what the contract's premise gives, as `linuxHost` bounds each output region by the guest's 2^32 bytes, and `Verified.Shim.readEvent_writesWithin` and `Verified.Shim.randomEvent_writesWithin` bound the output region of a `read` or a `getrandom` event by any size that holds its buffer, such as the memory's size at the call, for a binding whose relation keeps the store within the cap.  The host's bound is also wider than a binding's in another way, since the second disjunct of `WritesWithin` admits the scratch's timespec as the output region of any event, so a binding states its own bound in its trace relation and its conclusions and relates it to the host's.  `Verified.ShimA64.WritesNative` admits a region outside linear memory only for a `clock_gettime` into the timespec, `Verified.ShimA64.WritesLinear` admits none, `Verified.ShimA64.WritesNative.writesWithin` and `Verified.ShimA64.WritesLinear.writesWithin` give the host's bound from them, and `Verified.ShimA64.WritesNative.linear` gives `WritesLinear` for an event of another call, as `readall_elf` concludes for a trace of reads and writes.  An environment that differs from the shim in the fields that the image leaves free, such as one whose event names the base address while the bytes land at the guest's pointer, still satisfies every contract, so only a simulation of the environment by a machine excludes it.

The worked examples are the modules of `Verified/Shim/`, `Verified.Examples.WasiReadAll.linux_footprint`, which applies the generated `command.start` of the readAll command at the shim's host, with `Verified.Examples.WasiReadAll.linux_bytes`, which states the bytes of its reads and writes, `Verified.Examples.WasiSys.linux_footprint` for flat calls, and `Verified.Examples.WasiFiles.linux_names`, which states the descriptor corollary for a command that opens files. [The entry on tactics whose failures mislead](../tactic-combinator-pitfalls/README.md) records the `cases` on two replies, which `injection` replaces, the `split` of a contract's goal, which the contract proofs replace by rewriting, and the `simp` that rewrites a request's pointers, which `generalize` precedes.
