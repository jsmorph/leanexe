# WASI hosts built on a lower layer

The entry applies when a lower layer whose steps record events, such as the Linux call layer of `LeanExe/Linux/`, implements the WASI imports of a compiled module, and a theorem must state what the lower layer did in a run that the WASI command theorem describes.  `Verified.Wasi.compiled_native_start_run` holds for every host environment that satisfies `Verified.Wasi.hostSpec host`, so the work is a host whose relations name the lower layer's events, an environment that satisfies its specification, and a lift of the theorem's classification of a run to a statement about those events.  [The WASI manual's section on the Linux shim's specification](../../../docs/wasi.md#the-linux-shims-specification) describes the shim of `Verified/Shim/`, which does this for `fd_read`, `fd_write`, and `proc_exit`.

Define the host's relations from an image relation that sees no store.  `Verified.Shim.Image` states which lower events a WASI event makes, fixes each event's call, descriptor, count, and inputs, and derives the WASI reply from the lower result, and it leaves free the buffer's address and a read's bytes before the call, which depend on the store.  `Verified.Shim.ShimStep` appends an image to the world, with `Verified.Shim.Carried`, which ties each event to its reply by the number of events before it, and with the bound `Verified.Shim.WritesWithin` on the events' output regions, and `Verified.Shim.linuxHost` answers reads and writes with it.  The host's bounds on replies, its laws `read_bound` and `write_bound`, follow from the bounds of the reply functions, `Verified.Shim.readReply_valid` and `Verified.Shim.writeReply_valid`, and its laws of the exit marker from the updates of the world.

Implement the environment with the lower layer's own step on a view of the guest's memory.  `Verified.Shim.shimMemory` meets `LeanExe.Linux.Memory.Lawful` for every base, with offsets taken modulo 2^64 (`Verified.Shim.shimMemory_lawful`), `Verified.Shim.shim_readBytes` and `Verified.Shim.shim_writeBytes` state the layer's byte strings as `Wasm.Mem.readBytes` and `Wasm.Mem.writeBytes`, and `Verified.Shim.step_read` and `Verified.Shim.step_write` evaluate the step for a request inside the memory.  Each contract's proof rewrites the request's checks with the premise's fields, evaluates the step, generalizes the reply, and closes the frame with `Verified.Wasi.frame_payload`, `Verified.Wasi.frame_count`, `Verified.Wasi.frame_host`, `Verified.Wasi.written_at`, and `Verified.Wasi.at_count`, as `Verified.Shim.read_contract` and `Verified.Shim.write_contract` do.  `Verified.Shim.linuxEnv_satisfies` matches each import index of a module with at most three imports to its contract.

The lift follows the runs.  `Verified.Shim.exec_appended` inducts on `LeanExe.Wasi.Exec` with `LeanExe.Wasi.Exec.rec` and both motives, as `Verified.Wasi.exec_observed` does, and `Verified.Shim.prefix_appended` inducts on `LeanExe.Wasi.Prefix`, each to `Verified.Shim.Appended`, which chains the events, their images, and their replies with `Verified.Shim.Carried.append`.  `Verified.Shim.footprint_of_result` cases on the native result, applies `Verified.Wasi.exec_observed` or `Verified.Shim.prefix_observed` to pass from the observed world to the host's, excludes a returned command with `Verified.Wasi.bind_exit_not_returned`, and gives `Verified.Shim.Footprint`, which `Verified.Shim.shim_footprint` composes with `compiled_native_start_run` and `linuxEnv_satisfies`.  `Verified.Shim.Images.readData` and `Verified.Shim.Images.writeData` give the bytes that the lower reads and writes moved, by `LeanExe.Linux.readData` and `LeanExe.Linux.writeData`, as the bytes that the WASI trace committed, the form that a corollary over the lower trace needs.

`Wasm.HostEnv.Satisfies` requires each contract at every store, including stores that no run reaches, and the host's relations see a world and a request but no store.  A bound that holds only along runs, such as writes within a memory that stays below a native cap, therefore cannot enter the host: at a store whose memory exceeds the cap, a request whose buffer lies beyond the cap passes the contract's premise, every reply that such a host admits carries an event within the cap, and the environment satisfies the contract only by recording an event at an address that it did not use.  The host bounds what the contract's premise gives, as `linuxHost` bounds each output region by the guest's 2^32 bytes, and `Verified.Shim.readEvent_writesWithin` bounds a read by the memory's size at the call, for a binding whose relation keeps the store within the cap.  An environment that differs from the shim in the fields that the image leaves free, such as one whose event names the base address while the bytes land at the guest's pointer, still satisfies every contract, so only a simulation of the environment by a machine excludes it.

The worked examples are the modules of `Verified/Shim/` and `Verified.Examples.WasiReadAll.linux_footprint`, which applies the generated `command.start` of the readAll command at the shim's host, with `Verified.Examples.WasiReadAll.linux_bytes`, which states the bytes of its reads and writes.  [The entry on hosts that satisfy the WASI premise](../wasi-host-premise/README.md) covers the satisfying environments of other hosts, and [the entry on Linux calls through the call layer](../linux-call-layer/README.md) the layer's rule.  [The entry on tactics whose failures mislead](../tactic-combinator-pitfalls/README.md) records the `cases` on two replies, which `injection` replaces, and the `split` of a contract's goal, which the contract proofs replace by rewriting.
