# Theorems over every run of a WASI command

The entry applies when a theorem states what a WASI command writes and with which status it exits, for every reply that a host gives: a statement about `LeanExe.Wasi.Exec` of the command's `main` followed by its exit, under any `LeanExe.Wasi.Host`, and its composition with the generated `command.start` or `command.total` theorem of the command's module.  The statement quantifies over the host, so it covers the replies of every host whose specifications a module's host environment satisfies, the Linux shim's among them.  The random histogram, the random choice, and the manifest checker prove their command theorems in the form below.

Unbind `main` and its exit with `LeanExe.Wasi.Exec.unbind`, then each bind of `main` in turn, and pass a loop's `LeanExe.Wasi.LoopExec` to a lemma that recurses on the passes left, as [the entry on mutual execution induction](../mutual-relation-induction/README.md) describes for readAll.  After `cases` of an `Exec` of a `.sys` action, the continuation applied to the reply is a beta-redex, and `split at next` fails on it until `beta_reduce at next` reduces it.  Helpers that take a returned run of a `.sys` action apart into the reply, the host's relation, and the run of the continuation, as `Demos.RandomHistogram.exec_sys_returned` does, and that read a run of `pure`, as `Demos.RandomHistogram.exec_pure` does, keep each branch short.  A loop lemma takes the step function as a variable with a hypothesis that states it, such as `Demos.RandomHistogram.DrawStep` in `Demos.RandomHistogram.draw_loop`, and the caller proves the hypothesis with `fun _ _ => rfl`, since a step written in `do` notation with `let` bindings equals the explicit `.sys` action by definition.  State each lemma for every outcome: that the outcome is never `.exited`, or what the trace holds when it is, and what holds when it is `.returned`, so that a trapped outcome needs no case of its own.  A step that can exit, such as a draw whose errno ends the run, adds a conclusion for `LeanExe.Wasi.LoopExec.exit` with the trace split as `events ++ [.exit c]`, as `Demos.RandomChoice.draw_loop` states.

The replies bound what the program reads from them.  The bytes of a returned `args` result number fewer than `2^32`, from the reporter's four-byte words, through `LeanExe.Wasi.Host.sys_reports` and `Verified.Wasi.littleEndian_four_lt`, which meets the size premise of a pure function's equation on the buffer, and an errno that a reply carries is at most 76, so a status below `2^32` passes `LeanExe.Wasi.exitStatus` unchanged.  `Demos.RandomHistogram.args_returned` states both facts of `args`.

Compose with the generated `command.start` at `aborts := true` and `budget := 0`, from `command.initial`, and classify its `Verified.Wasi.NativeFunctionResult` as `Demos.RandomHistogram.ends_of_result` does: `Verified.Wasi.bind_exit_not_returned` excludes a normal return, `Verified.Wasi.exec_observed` and `Verified.Shim.prefix_observed` pass from the observed world to the host's, and `LeanExe.Wasi.Exec.exited_marker` gives the exit marker of an accepted exit.  `Demos.RandomHistogram.start_ends` then states that every run of `_start` with enough fuel is an accepted exit after the specified events, a trap of the host or a rejected exit, or a trap of the guest after a prefix of `main`.  `Demos.RandomHistogram.total_meets` takes the premises of `command.total`, a budget that bounds every prefix of `main` and a host that traps nowhere along it, and states the accepted exit alone, with the budget that [the entry on WASI effect charges](../wasi-effect-charges/README.md) proves.  `startIndex` names `_start` as `Wrappers.effectIndexWith command.sysCalls command.pure.module k`, where `k` counts the program's effect functions: 2 for a `main` that calls `LeanExe.Wasi.writeAll`.  A `cases` on the result of `results fuel enough`, whose index is `run fuel command.module …`, fails, since the index is no variable, so the classification is a lemma over a variable result applied to `results fuel enough`, or a `generalize` of the run precedes the `cases`, as `Demos.RandomHistogram.total_meets` does.

A `main` that calls a library function with a literal table, such as `Library.Hashing.Sha256.update` with its round constants, takes the table as a hidden borrowed parameter, so the generated `command.start` and `command.total` take the representation of that argument where a program without tables passes `rfl`, and the separation of its read regions from the low memory, `Verified.Wasi.ABI.low`, where such a program passes `fun _ m => nomatch m`.  `Demos.ManifestCheck.table_rep` gives the representation from `Verified.Env.withTables_rep` and the table's `Borrowed` in the static heap that `command.initial` gives, and `Demos.ManifestCheck.table_low` gives the separation from `Verified.Env.withTables_reads`.  Both take the mode function as a variable with the hypothesis `modes 0 = .borrowed`, which `rfl` proves at the call, since `command.mainEntry` is an `Option` whose signature no projection names.  `Verified.Wasi.Resource.CallPrefixBound` and the budget take the argument `Demos.ManifestCheck.mainArgs` in place of `.nil`, as `Demos.ManifestCheck.start_ends` shows.

A safety property, such as the manifest checker's confinement to the files that it names, must hold of the events of the runs that `command.start` admits besides the accepted exit: a run that traps in the host, whose events are those of an `Exec` that traps, and a run that a guest trap cuts short, whose events are those of a `LeanExe.Wasi.Prefix`.  `Verified.Wasi.Stops` states either, and `Verified.Wasi.Stops.bind` splits a stopped run of `bind first next` into a stopped run of `first`, or a returned run of `first` followed by a stopped run of `next`, through `Verified.Wasi.prefix_unbind`.  `Verified.Wasi.Every ok action`, defined by recursion over the action, gives `ok` of every event of every stopped run through `Verified.Wasi.Every.stops`, which serves for the bodies of brackets, for `args`, and for loops whose events all have one form.  The parts of the program that return reuse the lemmas of the whole runs, so no prefix form of each run lemma is needed: `Demos.ManifestCheck.main_stops` and `Demos.ManifestCheck.stops_soFar` prove `Demos.ManifestCheck.SoFar` this way, and `Demos.ManifestCheck.start_ends` states it in the two trap cases.

The worked examples are `Demos.RandomHistogram.exec_main` with `Demos.RandomHistogram.start_ends`, `Demos.RandomChoice.exec_main` with `Demos.RandomChoice.start_ends`, and `Demos.ManifestCheck.exec_main` with `Demos.ManifestCheck.start_ends`.  `Verified.Examples.WasiReadAll.exec_message` states a command's output over the events of every run in the same way.  [The entry on tactics whose failures mislead](../tactic-combinator-pitfalls/README.md) records the parse of `nomatch` inside an anonymous constructor that these proofs meet.
