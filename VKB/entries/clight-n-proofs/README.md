# Proofs of the Clight copy against N

The entry applies to the Lean proofs of N, the reference semantics for the Clight forms that the C translator emits.  `clightn/N.nsx` specifies N, and `clightn/nsx.py` renders it into `LeanExe/Native/ClightN/Spec.lean`.  A form added to N needs a theorem about the Lean copy of Clight at `LClight.Archi.aarch64` whose type `clightn/check.sh` compares with the rendered statement, and a program added as an instance needs its carried statement proved from the copy's theorem of the program.  [The README of N](../../../clightn/README.md) describes the specification, the renderings, the check, and the instances.

Each leaf statement of `LeanExe/Native/ClightN/Leaf.lean` takes two steps.  The first computes the copy's operation on every shape of value by `cases v1 <;> cases v2 <;> rfl` and states the result as a function of words, as `ClightN.Proof.eq_add_ul_ul` states the addition of two `unsigned long` values as `ClightN.Proof.onLongs` of the sum, which gives nothing for the other shapes.  The second inverts that form with `ClightN.Proof.onLongs_some`, or with `ClightN.Proof.onInts_some`, `ClightN.Proof.onLong_some`, and `ClightN.Proof.onInt_some` for 32-bit words and for one operand, and matches the result with the constructors of N's relation, as `ClightN.Proof.add_ul_ul` does.  Each test of the copy has a lemma that equates the test's result `true` with a relation of integers: `ClightN.Proof.cmpu_long` states the unsigned comparisons and `ClightN.Proof.long_ltu_64` the test of a shift amount, each proved by `show decide (...) = true ↔ _`, which exposes the copy's `decide`, and then `simp [holds]` or `rw [decide_eq_true_iff]`.  `ClightN.Proof.of_bool_cases` then splits the truth value that `LClight.Val.of_bool` makes of such a test, as `ClightN.Proof.eq_ul_ul` does for `==`.  The laws of the bitwise base symbols follow from `ClightN.Proof.bit_cases` of `LeanExe/Native/ClightN/Laws.lean`, which [the entry on word identities](../word-bit-identities/README.md) describes.

Inside the namespace `ClightN.Proof` with `open LClight`, the names `Int64.xor` and `Int.repr` resolve to core Lean's `Int64.xor` and `Int.repr` in place of the copy's `LClight.Int64.xor` and `LClight.Int.repr`, so a statement that writes the short names fails with a type mismatch between `UInt64` and `Int64`, and the proofs of `LeanExe/Native/ClightN/Leaf.lean` write the copy's names in full.  `simp` on `decide (u64 y < LClight.Int64.unsigned LClight.Int64.iwordsize) = true ↔ u64 y < 64` removes the `decide` and leaves `LClight.Int64.unsigned LClight.Int64.iwordsize` unevaluated, so the goal stays open.  `ClightN.Proof.long_ltu_64` rewrites with `decide_eq_true_iff` instead and closes the rest by `exact Iff.rfl`, which unfolds the copy's constant to 64.

An instance's proof, `clightn/gcd/Gcd.lean` or `clightn/sha/Sha.lean`, carries the copy's theorem of the program to the program of the file that `clightgen` prints.  `LClight.bigstep_program_terminates_rename_on` renames the translation's whole program into the file's, `ClightN.Proof.program_to_n` of `LeanExe/Native/ClightN/Exec.lean` carries the termination to N's judgment `nprog`, and `ClightN.Proof.reads_nreads` of `LeanExe/Native/ClightN/Reads.lean` carries the volatile loads to `nreads`.  The premises of the renaming are closed facts, which the kernel checks by `decide +kernel` while it computes the translation of the compiled module: `ClightN.Proof.gcd_defs_eq` of `clightn/gcd/Gcd.lean` states that renaming the whole program gives the file's definitions.  The comparison of two programs needs decidable equality of the copy's syntax, which `LeanExe/Native/ClightN/Instance.lean` derives for expressions, statements, functions, and global definitions.  The renaming reads the file's identifiers off the two lists of definitions by position, and the kernel's comparison of the renamed program with the file's definitions confirms that reading.  [The entry on definitions that the kernel evaluates](../kernel-evaluated-definitions/README.md) gives two forms that keep these checks within the kernel's reach: the renaming's injectivity decided as membership and the absence of repetitions, through `ClightN.Proof.inj_of_nodup_map` of `LeanExe/Native/ClightN/Instance.lean`, and structural recursion in the translator's functions, such as `LeanExe.Native.initStores`.  [The entry on proofs about a value that a later argument fixes](../explicit-before-dependent-proof/README.md) gives a third, the program supplied by name to `program_to_n`.  `ClightN.Proof.exec_to_n`, `ClightN.Proof.call_to_n`, and `ClightN.Proof.eval_to_n`, on which `program_to_n` rests, follow the copy's derivations as [the entry on mutual execution induction](../mutual-relation-induction/README.md) describes.  The worked examples of instances are `ClightN.Proof.gcd_terminates` of `clightn/gcd/Gcd.lean` and `ClightN.Proof.sha_reads` of `clightn/sha/Sha.lean`, which `clightn/check.sh` elaborates outside the build against the renderings that it writes.
