# Determinism of the Lean copy of Clight

A proof about the Clight copy sometimes holds two derivations from one state and needs them to agree.  Examples are carrying a conclusion from the execution that a theorem asserts to every other execution, and showing that an outcome is the only one.  The copy's big-step relations are deterministic relative to the event trace, and these theorems state it.

Apply `LClight.exec_stmt_determ` or `LClight.eval_funcall_determ` when the two traces are equal, and `LClight.eval_expr_determ`, `eval_lvalue_determ`, or `eval_exprlist_determ` for expressions, which need no hypothesis.  The statement and call theorems take `hX : X.Determ`, which every semantics of external functions meeting CompCert's `ec_determ` satisfies.  The built-in functions and the volatile loads and stores of the copy satisfy it with no hypothesis.  When the traces may differ, use `LClight.exec_stmt_determ_prefix` or `eval_funcall_determ_prefix` with `t₁ ++ u₁ = t₂ ++ u₂`.  With `u₁ := t` and `u₂ := []`, an execution with the empty trace is the only one, as `LClight.bigstep_program_terminates_E0` shows.

A hypothesis on `X` that covers only equal traces does not suffice.  The two executions of a sequence can split one trace differently, and an external function with the outputs `[e]` and `[e, e']` then gives two results for one trace.  `NativeA` holds for every `X`, but `LeanExe.Native.NativeA.unique`, which carries `NativeA`'s conclusions to every execution whose trace agrees with the asserted one, needs `X.Determ`.

Determinism makes the copy's interpreter `LClight.run`, which `run_sound` relates to the relation, agree with every derivation from the same state and trace.  The differential tests against `ccomp -interp`, which run `run`, therefore cover derivations through rules that `run` does not follow.  A transcribed rule that gives an outcome to a state that CompCert leaves stuck, and from which `run` also finds none, remains outside both the tests and the theorems.
