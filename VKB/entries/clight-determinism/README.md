# Determinism of the Lean copy of Clight

A proof about the Clight copy sometimes holds two derivations from one state and needs them to agree.  Examples are transferring a conclusion from the execution that a theorem asserts to every other execution, and showing that an outcome is the only one.  The copy's big-step relations are deterministic relative to the event trace, and these theorems state it.  The entry also applies when a semantics of external functions is chosen for calls whose theorems must reach the compiled program through CompCert.

Apply `LClight.exec_stmt_determ` or `LClight.eval_funcall_determ` when the two traces are equal, and `LClight.eval_expr_determ`, `eval_lvalue_determ`, or `eval_exprlist_determ` for expressions, which need no hypothesis.  The statement and call theorems take `hX : X.Determ`, which every semantics of external functions meeting CompCert's `ec_determ` satisfies.  The built-in functions and the volatile loads and stores of the copy satisfy it with no hypothesis.  When the traces may differ, use `LClight.exec_stmt_determ_prefix` or `eval_funcall_determ_prefix` with `t₁ ++ u₁ = t₂ ++ u₂`.  With `u₁ := t` and `u₂ := []`, an execution with the empty trace is the only one, as `LClight.bigstep_program_terminates_E0` shows.

A hypothesis on `X` that covers only equal traces does not suffice.  The two executions of a sequence can split one trace differently, and an external function with the outputs `[e]` and `[e, e']` then gives two results for one trace.  `NativeA` holds for every `X`, but `LeanExe.Native.NativeA.unique`, which extends `NativeA`'s conclusions to every execution whose trace agrees with the asserted one, needs `LClight.ExtSem.Determ X`.

CompCert proves its compiler for every semantics of external functions that meets `extcall_properties` of its `common/Events.v`, which limits what one call may carry.  Its field `ec_trace_length` allows at most one event per call, and `ec_determ` requires that two calls from the same arguments and memory have traces that `match_traces` relates, which for a system-call event lets them differ only in its one result value, and that with equal traces they have the same result and memory.  A semantics whose reply holds more than one value that the environment chooses, such as the 16 bytes of `clock_gettime` or of `getrandom` or the bytes that a `read` writes into memory, cannot meet both: with one event, two calls with equal traces and different bytes leave different memories, and a trace that records the bytes needs several events or arguments that `match_traces` does not let differ.  The copy's `LClight.ExtSem` admits such a semantics, and CompCert's theorem does not carry a theorem of the copy for it to the compiled program, since that theorem assumes `extcall_properties` of every external function (`external_functions_properties`), a hypothesis that the copy's `ExtSem` leaves out, as the header of `LeanExe/Native/Clight/Events.lean` states.  A C binding of the Linux call layer, whose replies set whole output regions as [the entry on Linux calls through the call layer](../linux-call-layer/README.md) describes, therefore reaches the binary only with one external call for each value, or with a proof outside CompCert's theorem that the compiled program refines the source under that semantics.

Determinism makes the copy's interpreter `LClight.run`, which `run_sound` relates to the relation, agree with every derivation from the same state and trace.  The differential tests against `ccomp -interp`, which run `run`, therefore cover derivations through rules that `run` does not follow.  `tests/native/clight-rocq.sh` compares `run` with a second reference on the programs that `tests/native/clight.sh` writes: `coqc` runs the evaluator of `rocq/ClightEval.v`, which is sound for CompCert's big-step semantics of Clight, on each program as `clightgen` prints it, and checks that its output equals the output that `run` gave.  An agreeing program whose output is not UB therefore has an execution of CompCert's semantics, as Rocq checks it, with the output that `run` gives.  The evaluator omits rules of the semantics, among them bit-field accesses, assignment of structs and unions, volatile accesses whose event is a pointer, and external calls other than the built-in functions and the volatile loads and stores, and it is stuck at a program that reaches one of them, so its stuck result shows no absence of an execution, and a program on which both give UB rests on the report of undefined behavior by `ccomp -interp`.  A transcribed rule that gives an outcome to a state that CompCert leaves stuck, and from which `run` also finds none, is detected by neither comparison nor the theorems, since both comparisons test `run`.
