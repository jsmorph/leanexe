# Line-oriented WASI processes

`Demos.StreamFold` holds a WASI process that reads its input in chunks, splits it into lines, and applies a line kernel to each line, together with the proofs about it.  A program that reads lines and writes output for each line can instantiate it with a kernel and take termination, the output, and the exit status from the shared proofs.  The integer and binary64 running sums are its two applications.

A kernel `Demos.StreamFold.Kernel Acc` maps an accumulator and a line to a validity bit, the next accumulator, and the bytes to write.  `KernelSpec` gives an invariant `Good` of the accumulator and a size condition `Room` for a line, and it asks that an accepted line keep `Good` and produce nonempty output.  `process kernel seed` is the process.  `initial_terminates_output` states that, from the initial state, it returns the status of `Model.foldOutcome kernel seed (Model.lines input)` after writing the outputs of the same fold, under `StreamHost` and `Model.LineRooms`, and `process_exec_correct` and `process_terminates` give the same for any state that satisfies the stream invariant.

An application states its own specification with `Model.LineValues Denotes lines values status`, where `values` holds the values of the lines before the first line without a value and `status` is 0 or 28.  It proves that `foldOutcome` of its kernel matches `LineValues` for its predicate, and `LineValues.unique` then shows that a functional predicate determines both the values and the status.  An application states its own process and relates it to `process` by `Process.Rel` in its stream view, and `repeatWhile_map` maps its loop onto the shared one.

The allocation charges of the `wasi-effect-charges` entry need bounds on the sizes of the buffers.  `Demos.StreamFold.step_within` keeps the input buffer within one read and the output buffer within a bound on the kernel's output whatever the host replies, and `Model.pending_le` and `StreamFuture.line_le` bound the pending line by any line length that `Room` implies, since the pending line is a prefix of a line whose `Room` holds.  The theorems cover successful transfers, and an I/O error stops the process with its errno, which the application drivers test.

The integer application first kept a private copy of the buffering and termination proofs, and twelve files left it when it moved onto StreamFold.  `Termination.lean` and `TerminationTarget.lean` are still the same in `Demos/RunningSum` and `Demos/RunningSumFp` apart from their namespaces, and `TerminationTyped.lean` differs by eight lines.  A third application should move those proofs into StreamFold rather than copy them a third time.
