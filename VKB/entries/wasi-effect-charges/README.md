# Allocation charges of WASI effect functions

A WASI program's total-execution theorem needs a bound on what each effect function allocates: `begin`, each step, and the read and write steps that a step calls.  `Verified.Wasi.Resource.Bounded` states that every run and every prefix of a command spends at most a budget and its frames fit the call depth, and `CallBounded` states the same of a call.  The integer and binary64 running sums prove these bounds for their effect functions with one method, which a new WASI program can follow.

Apply `Verified.Wasi.Resource.bounded_of_rule` at each command of the body.  It reduces `Bounded` to `Rule`, which matches on the form of the command and requires only facts about its parts.  For a `bind`, `Rule` requires a bound on the continuation only at values that some run of the first command returns, through `Returns`, and `Verified.Wasi.Resource.Returns.read_size` bounds the count of a read by its buffer's size and states that the buffer keeps its size, which lets a read step's charge depend on the size of the read.  The reflector binds each argument of an effect command that is not a variable by a `bind` of a `ret` before the command, and `Verified.Wasi.Resource.Returns.bind_ret` carries a value that the step returns through each such `bind` to the command, as the read steps of the running sums and the order book do with three applications before `Verified.Wasi.Resource.Returns.read_size`.  A call takes its bound from its body's, through `callBounded_here` for the first function of the program and `callBounded_there` for a later one.

Each leaf of the proof is the cost of an expression.  Reduce it with `simp +decide only [PureContext.ownedCost, PureContext.exprCost, PureContext.ofProg, Expr.allocs, Var.cost, Expr.mode, argsSum, callCredits, ↓reduceIte, Nat.add_zero, Nat.zero_add, coerceCost]`, which leaves the table entry of the called pure function, then identify it with the generated bound by `show io.pureSources.f.bound … ≤ _` and bound that with a closed-form lemma of [the entry on closed-form allocation bounds](../verified-bound-closed-form/README.md).  `Verified.Ty.copyCost_of_scalar` removes the copy of a scalar argument whose type is an unreduced entry of a parameter list, and `Verified.Expr.fits_of_depthCalls` gives the frames of a condition that calls no function.

A loop's charge follows by induction on the number of passes left, over `Verified.Wasi.Resource.ResourceLoopExec` and `Verified.Wasi.Resource.ResourceLoopPrefix`, which bounds the spending by that number times the charge of one pass.  The private lemmas of `Verified/Examples/WasiRetainBudget.lean` do this for the loop of `Verified.Examples.WasiRetain.retain`, whose passes charge nothing, since its read moves the state's buffer, and `Verified.Examples.WasiRetain.call_prefix_bound` closes the prefix bound of the call with `Verified.Wasi.Resource.call_prefix_rule`.  [The entry on WASI process totality](../wasi-process-total/README.md) describes the total theorem that takes this bound.

`Verified.Wasi.Resource.ResourceLoopExec` adds the charge of each pass to that of the passes after it and credits no release, while the compiled code releases what a pass allocated and the allocator reuses the block, so a loop whose number of passes depends on the host's replies has a charge that grows with them unless its passes charge nothing.  A pass that writes part of its bytes therefore writes a window of a buffer in place, `LeanExe.Wasi.writeStdout buffer start count`, and allocates nothing: the loop of `LeanExe.Wasi.writeAll` binds the start and the count of the window that remains, words, and writes it from the borrowed buffer.  `Verified.Wasi.Resource.loop_bounded` bounds a loop whose test and step charge at most constants from the states of an invariant that every pass keeps, and with both constants 0 and the invariant `True` it gives the loop of `writeAll` the charge 0, as `Verified.Examples.WasiReadAll.writeAll_bounded` shows, and `writeAll_bounded` of `Demos/RandomHistogram/Budget.lean` for the histogram's output.  `Verified.Examples.WasiReadAll.budget_bounded` then bounds every prefix of `Verified.Examples.WasiReadAll.main` under every host by the block of `readAll`'s buffer, through `Verified.Wasi.Resource.call_prefix_rule` and `Verified.Examples.WasiReadAll.body_bounded`.

A loop whose pass charge depends on the pass has a bound quadratic in the input under a constant charge for each pass.  The manifest checker's loop over its lines copies each line's name and its output line, and `Verified.Wasi.Resource.loop_bounded_sum` bounds such a loop by `Verified.Wasi.Resource.passSum` of a charge function of the pass's index, which `Verified.Wasi.Resource.passSum_le` bounds by a sum over the elements.  `Demos.ManifestCheck.lines_total` bounds the sum of the lines' lengths, each with its newline, by the manifest's size plus one, and `Demos.ManifestCheck.checkLines_bounded` combines them.  It takes the array of line positions as a variable with the hypothesis `entries = parse m`, since unification with `parse m` makes Lean evaluate `parse`.  The elaboration of that budget exhausted its memory from three causes: `simp +decide` evaluated `Verified.Prog.flags` at every pure call, which `Demos.ManifestCheck.flags_toList` computes once by `decide +kernel`; charge lemmas stated only at depth 0 left bound terms that `decide` unfolded at calls of other depths; and a `simpa` with the default simp set ran on a reflected body.  The charge lemmas of `Demos/ManifestCheck/Budget.lean` therefore take the depth as a variable.

A record call and a poll place their regions in the call area, `Verified.Wasi.ABI.callArea`, which `LeanExe.Wasi.callFits` requires them to fit, and allocate nothing, so `Verified.Wasi.sysCost` charges them 0 and a loop of them has the charge 0 for every number of passes.  `Verified.Examples.WasiRecordLoop.body_bounded` bounds the loop of `fd_fdstat_get` calls of `Verified.Examples.WasiRecordLoop.stat` by `Verified.Wasi.Resource.loop_bounded` with both constants 0, and `Verified.Examples.WasiRecordLoop.call_prefix_bound` closes the call's prefix bound.  `body_bounded` holds for every count, every list of modes, and every liveness.  The charge of the loop's count is `Verified.Var.cost` of a word variable, an `if` over the variable's mode and liveness whose branches are both 0.  With the modes and the liveness as variables, neither `ite_self` in the `simp` set of the charge nor a `split` after that `simp` removed the `if`, and `omega` reported a counterexample with the `if` as an atom.  The private lemma `var_cost_elem` of `Verified/Examples/WasiRecordLoop.lean`, which states that a variable of an element type costs 0 and which `simp` applies in place of unfolding `Verified.Var.cost`, avoids the `if`.

`Verified.Wasi.Resource.Bounded` and `Verified.Wasi.Resource.Rule` bound a command from every world, and the rule of a `bind` bounds the second command from every world for every value that a run of the first returns, so the bound of a loop whose charge depends on the replies is its charge in the worst world.  `Verified/Wasi/ResourceRulesAt.lean` states `Verified.Wasi.Resource.BoundedAt`, `Verified.Wasi.Resource.LoopBoundedAt`, and `Verified.Wasi.Resource.CallBoundedAt` from one world, and `Verified.Wasi.Resource.RuleAt` gives, for a `bind`, an `ite`, a call, and a loop, the facts from which they follow, with the second command of a `bind` bounded from the world in which the first returned, and `Rule` for every other command.  A bound that depends on the replies applies `Verified.Wasi.Resource.boundedAt_of_rule` along the body's spine, `Verified.Wasi.Resource.Bounded.at` at the commands whose charge depends on no reply, and `Verified.Wasi.Resource.call_prefix_rule_at` at the calls, with `Verified.Wasi.Resource.callBoundedAt_here` for the first function of the program and `Verified.Wasi.Resource.callBoundedAt_there` for a later one, and carries a condition on the replies along the run, as [the entry on WASI hosts built on a lower layer](../wasi-host-from-layer/README.md) describes.

`Demos.ManifestCheck.body_bounded` applies these rules to a charge that depends on one reply.  The manifest's buffer has the size that `fd_filestat_get` reports, so the budget's premise, `Demos.ManifestCheck.StatAlong host M main world`, `LeanExe.Wasi.Host.Along` of `Demos.ManifestCheck.StatAt`, constrains only the replies to the requests of that call that a prefix of `main` makes from the start world: it bounds by `M` each size below `2^32` bytes that such a reply with errno 0 reports.  `Demos.ManifestCheck.main_along` carries it from `main` to the reflected body, with `Verified.Shim.along_observed` and `LeanExe.Wasi.Host.Along.of_rel` through `command.main.related`, as `Verified.Wasi.Resource.CommandAlong` of `StatAt`, which states `LeanExe.Wasi.Host.Along` of the action of a command.  The proof applies `Verified.Wasi.Resource.boundedAt_of_rule` along the path from the body's start to the call that reads the reply, with `Verified.Wasi.Resource.Bounded.at` at every command off that path.  `Verified.Wasi.Resource.CommandAlong.next` carries the premise to the second command of a `bind`, from the first command's `ResourceExec` through `Verified.Wasi.Resource.ResourceExec.erase` and `LeanExe.Wasi.Host.Along.bind_right`, `Verified.Wasi.Resource.CommandAlong.first` to the first command with `Demos.ManifestCheck.StatAt.of_bind`, and `Verified.Wasi.Resource.CommandAlong.no` and `Verified.Wasi.Resource.CommandAlong.body` to the second branch of an `ite` whose condition is false and to the body of a `letPair`.  A later command whose charge depends on a value that an earlier call returned needs the world in which that call started, which `Verified.Wasi.Resource.ReturnFact` drops: `Verified.Wasi.Resource.CommandAlong.split` takes a returned run of a `bind` apart with `LeanExe.Wasi.Exec.unbind`, and `Verified.Wasi.Resource.CommandAlong.branch` gives the run of the branch of an `ite` that the condition chooses, each with `CommandAlong` at the worlds of the parts, so the manifest's size after the bracket of `main` follows from the reply at the world in which `readManifest` started.

The reflected term decides each charge.  The reflector binds each argument of an effect command that is not a variable before the command, so `writeStdout output written (output.size - written)` of a process step reflects to a `bind` of the subtraction, and of the projection `written` where the state keeps it in a pair with another word, before the write, and the proof of the step's charge follows those bindings, as `Demos.RunningSum.writeStep_bounded` does with a `repeat` over the rules of a `bind`, a `ret`, and a `write`.  The reflector splits a value of a pair type where the action binds it, with `Verified.Wasi.Command.letPair`: the result of a bind, a loop's state at the start of each step, and a tuple parameter at a function's entry, and a pure operand destructures only the variables that it names (`Verified.Wasi.Reflect.splitThen` and `Verified.Wasi.Reflect.pureOperand`).  `Verified.Expr.allocs` charges a copy at an operand only when the operand names an owned variable that stays live after it, so a split value is copied at no later use.  A review of a charge therefore reads the reflected term, as the goals of `RuleAt` print it.

The rule of a `sys` command in `Verified.Wasi.Resource.Rule` bounds the command's charge over the `Exec` and `Prefix` derivations of its action from any world, which `Verified.Wasi.Resource.ResourceExec.sys` and `Verified.Wasi.Resource.ResourcePrefix.sys` carry, rather than over every trace.  A bound over every trace fails for a charge that depends on the host's reply: a reported call, such as `LeanExe.Wasi.Call.argsGet`, allocates a block of the size that its reporter's reply gives, which reaches nearly `2^32` bytes over all traces.  `Verified/Wasi/SysRule.lean` derives both premises of the rule from a bound on the replies that the host permits, `Verified.Wasi.Resource.reported_rule` for a host and `Verified.Wasi.Resource.reported_rule_observed` for the observed host of a run, and `Verified.Wasi.Resource.sys_rule_of_bound` from a bound on every trace for a call whose charge does not depend on the reply.  The first event of a prefix follows by induction on `LeanExe.Wasi.PrefixProgress`, which `LeanExe.Wasi.Prefix.progress` gives from a `Prefix` and which has the constructors `refl`, `advance`, and `trans` and none for a bind, so each `advance` case is a step of the action's own head constructor, as in `Verified.Wasi.Resource.prefix_sys_first`.

The charge of a later command can depend on what a `sys` command returned.  The reflector splits a record result, such as the `LeanExe.Wasi.ArgsResult` of `args`, into its components where the action binds it, so the budget of `Verified.Examples.WasiSys.main`, `Verified.Examples.WasiSys.budget` of `Verified/Examples/WasiSysTotal.lean`, holds the block of the argument bytes once (the module docstring of that file).  The demos' budget modules import `Verified/Examples/WasiSysTotal.lean`, so the first step of the full check builds it, and `tests/wasi/sys-example-run.sh` audits its axioms.  The `bind` rule gives the continuation only `Verified.Wasi.Resource.Returns` of the first command, so the bound needs a lemma that limits what a run of the call returns, as `Verified.Wasi.Resource.Returns.read_size` does for a read.  `Verified.Examples.WasiSys.args_bytes_le` of `Verified/Examples/WasiSysTotal.lean` bounds the bytes of a returned `args` result by the bound on the reporter's replies, through `LeanExe.Wasi.Host.sys_bound` of both calls, `LeanExe.Wasi.Host.sys_reports`, and `Verified.Wasi.littleEndian_four_lt` for the reporter's words.  A call with an output buffer, such as `LeanExe.Wasi.randomGet`, writes into a buffer that the program builds, so the budget holds the block of the program's `LeanExe.Bytes.build`, and the call charges `Verified.Wasi.Resource.PureContext.sysTakeCost`, which is 0 when the buffer's variable dies at the call, as `Verified.Examples.WasiSys.body_bounded` shows with its `free_bound` tactic.

The order book's process states its charges for every state whose arrays have the program's sizes, whatever records the input holds.  A read step's charge covers every reply of at most 4,096 bytes and takes the generated bound of `run` on a batch through a term `R` with `Demos.OrderBook.Process.RunBound R`, which `Demos.OrderBook.Process.runBound_74` gives from the closed form of that bound, `Demos.OrderBook.Bound.run_bound_le_sized`.  `Demos.OrderBook.Process.begin_prefix_bound` and `Demos.OrderBook.Process.step_prefix_bound` give the prefix bounds of `begin` and of every step, the latter through `Demos.OrderBook.Process.stepBudget_le` with the one charge `Demos.OrderBook.Process.stepCharge R`.  The steps take the state owned, so a write step and a stopping step charge nothing, and a read step charges the read's buffer, the credits of the state's arrays at its call of `afterRead`, whose state parameter is paid, and the batch.  The step's call of the write or read step binds the state whole, `Command.bind (.ret value) (.call f [x])`, and `Verified.Wasi.Resource.Bounded.bind_ret` bounds such a binding by the `ret`'s charge and a bound on the call.  The call's argument cost of the bound variable, which dies there, is 0 by `rfl`.

The order book's effect bodies split the state's 13 fields at their entry, one `Verified.Wasi.Command.letPair` for each field but the last, and each level of the environment holds the previous level twice, so the elaborator's conversion of a call's arguments to the state unfolds a tree exponential in the depth.  The simproc `envGetOfIndex` of `Demos/OrderBook/ProcessCharges.lean` reads `Env.get env (Var.ofIndex Γ i h)` as the `i`-th value of a chain of `Verified.Env.cons` in one definitional step, which `simp` applies once to each shared subterm (its docstring).  `envGetOfIndex` reads the environment after `whnfR`, which does not unfold `Verified.Wasi.Resource.letPairEnv`, so the order book's `read_state` unfolds `letPairEnv` in the same call.  The cost of the stopping branch's status is an `if` whose condition `read_state` unfolds while its instance still holds the effect body's environment, so the instance's type matches the condition only at the default transparency and `ite_self` and `split` do not apply, as [the entry on tactics whose failures mislead](../tactic-combinator-pitfalls/README.md) describes, and `Demos.OrderBook.Process.ite_le_zero` bounds an `if` whose branches are at most 0 for any instance.  On the closed goal of `begin`, `simp +decide only []` evaluates the whole goal and reaches the recursion limit, so `Demos.OrderBook.Process.initial_entry` states the table entry of the called function by `decide +kernel`, and `Demos.OrderBook.Process.begin_bounded` uses that equation.

An effect body that binds the results of effect commands, as `Verified.Examples.WasiSys.main` binds the results of `sys` commands, builds its environment with `Verified.Wasi.ResultTy.bindEnv`, a definition that `whnfR` does not unfold.  The type and the context of each `Verified.Env.cons` of that chain are those of the command that bound the value, such as the type that `Verified.Wasi.SysForm.ty` gives a form, while the list `Γ` of the reflected variable states them in another form, and `simp` matches implicit arguments at reducible transparency, so a rewriting lemma for `Verified.Env.get` of `Verified.Env.cons` does not apply.  The `dsimproc` `envGet` of `Verified/Examples/WasiSysTotal.lean` reads the `i`-th value of the chain after `whnfD`, which unfolds `bindEnv`, while `envGetOfIndex` of the order book reads it after `whnfR`, which suffices for the order book's environments.  `Verified/Wasi/BudgetTactics.lean` holds the shared copy, `Verified.Wasi.Resource.envGet`, which its tactics apply, while `Verified/Examples/WasiSysTotal.lean` and `Verified/Examples/WasiReadAllSteady.lean` keep copies of their own.

For a body that is one chain of commands without a loop, `Verified/Examples/WasiSysTotal.lean` defines local macros for the forms of `Verified.Wasi.Resource.Rule` that its body repeats, `bind_bound`, `ite_bound`, `ret_bound`, and `write_bound`, and `flat_bound` for a flat call without an output, which reduce the proof of `Verified.Wasi.Resource.Bounded` to one budget for each `bind` and `ite`.  Its macro `charge` closes each leaf by a `simp +decide only` over the cost definitions and `envGet` followed by `omega`, and the `simp` evaluates every liveness test of the leaf, since the modes and the liveness functions are closed terms.  `ite_bound` bounds the budget term `if c then b else b` of the `ite` rule with the private lemma `ite_cost`, stated for any instance of the decision as `Demos.OrderBook.Process.ite_le_zero` is, before `charge` runs, since the `simp` of `charge` unfolds the condition, after which the `ite_self` of the same call does not apply.  `Verified.Examples.WasiSys.body_bounded` of the same file is the proof in this form, and it proves the reported `args` call and `randomGet` without the macros.

`Verified/Wasi/BudgetTactics.lean` holds the tactics that the budgets of the random histogram and the random choice share, in place of such local macros.  `rule_charge` and `rule_init_charge` prove the charge of an expression and of a loop's initial state, the latter summing the charge of a built buffer with `Verified.sumBelow_const`, and `rule_ret`, `rule_write`, `rule_bind`, `rule_sys`, `rule_ite`, and `rule_free` apply the rules of `Verified.Wasi.Resource.Rule`, with `Verified.Wasi.Resource.ite_cost` for the budget of an `if`.  A budget proof gives the equations of its pure functions' charges the simp attribute `charge_eqs` of `Verified/Wasi/BudgetAttr.lean` as a local attribute, and `rule_charge` rewrites with them.  `Demos.RandomChoice.body_bounded` bounds a loop whose state carries a draw buffer and an output buffer, which every pass moves, by `Verified.Wasi.Resource.loop_bounded` with a charge of 0 for each pass, so the budget does not depend on the number of passes.  Its statement bounds the whole body by a constant, which a program that allocated its buffers in its first pass would also meet, so a review that must confirm a charge of 0 for each pass reads the proof's use of `loop_bounded`.

A `Verified.Wasi.Command.letPair` charges `Verified.Wasi.Resource.letPairCost`, the copy of an owned pair that stays live, before its body.  `Verified.Wasi.Resource.Bounded.letPair` and `Verified.Wasi.Resource.BoundedAt.letPair` reduce a bound on the command to one on its body, and `Verified.Wasi.Resource.Bounded.letPair_free` and `Verified.Wasi.Resource.BoundedAt.letPair_free` do so when the charge is 0, which `Verified.Wasi.Resource.letPairCost_borrowed` gives for a borrowed pair and `Verified.Wasi.Resource.letPairCost_dead` for a pair that dies at the split.  The tactics `letPair_free` and `letPairAt_free` of `Verified/Wasi/ResourceRules.lean` and `Verified/Wasi/ResourceRulesAt.lean` apply these at each `letPair` at the head of the goal, and they prove the premise with `rfl`, since `decide` refuses a proposition with a free variable, such as the liveness function `live` of a budget stated for every liveness, even where the reduction never reads it.  `Verified.Wasi.Resource.Returns.letPair` turns a run of a `letPair` into a run of its body, through a predicate that matches on general indices, since `cases` on a run of the fixed command fails by dependent elimination.  `Demos.RandomHistogram.body_bounded` applies `letPair_free` after the binding of `args`, at the start of each pass, after the binding of the draw, and after the loop.

Call rules that fix the program and the callee before the case analysis fail by dependent elimination.  `CallBoundRule` instead cases on general indices and reduces by its own pattern matching, and a new rule over indexed commands should take the same form.  The inversion of a run fails in the same way: `cases` on a `Verified.Wasi.Resource.ResourceExec` whose command is fixed, such as `.ret value` or `.sys Call.argsGet .reported [] []`, fails by dependent elimination on the result index of the constructor `call`.  `Verified.Wasi.Resource.ReturnFact` of `Verified/Wasi/ResourceRules.lean`, of which `Verified/Examples/WasiSysTotal.lean` keeps a private copy, matches on the command and the outcome, and one proof by `cases` on general indices, `Verified.Wasi.Resource.returnFact`, which `Verified.Wasi.Resource.returns_fact` applies to a returned run, gives every inversion that the charges of `main` need: a `ret` returns its expression's value, a `sys` command ends as a run of its action, and a `bind` that returns has a first command that returns and a second command that returns the same value.  Each application's step theorems set `maxHeartbeats` to 4,000,000.  `Demos.RunningSum.writeStep_bounded` and `Demos.RunningSumFp.writeStep_bounded` have the same proof, as do the two `readStep_bounded`, and `Demos.RunningSum.step_body_bounded` shows the step that chooses between them.
