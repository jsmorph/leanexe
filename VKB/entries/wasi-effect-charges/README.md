# Allocation charges of WASI effect functions

A WASI program's total-execution theorem needs a bound on what each effect function allocates: `begin`, each step, and the read and write steps that a step calls.  `Verified.Wasi.Resource.Bounded` states that every run and every prefix of a command spends at most a budget and finds its frames, and `CallBounded` states the same of a call.  The integer and binary64 running sums prove these bounds for their effect functions with one recipe, which a new WASI program can follow.

Apply `Verified.Wasi.Resource.bounded_of_rule` at each command of the body.  It reduces `Bounded` to `Rule`, which matches on the form of the command and asks only for facts about its parts.  For a `bind`, `Rule` asks for a bound on the continuation only at values that some run of the first command returns, through `Returns`, and `Returns.read_size` bounds the bytes of a read by its capacity, which lets a read step's charge depend on the size of the read.  A call takes its bound from its body's, through `callBounded_here` for the first function of the program and `callBounded_there` for a later one.

Each leaf of the recipe is the cost of an expression.  Reduce it with `simp +decide only [PureContext.ownedCost, PureContext.exprCost, PureContext.ofProg, Expr.allocs, Var.cost, Expr.mode, argsSum, callCredits, ↓reduceIte, Nat.add_zero, Nat.zero_add, coerceCost]`, which leaves the table entry of the called pure function, then identify it with the generated bound by `show io.pureSources.f.bound … ≤ _` and bound that with a closed-form lemma of the `verified-bound-closed-form` entry.  `Verified.Ty.copyCost_of_scalar` removes the copy of a scalar argument whose type is an unreduced entry of a parameter list, and `Verified.Expr.fits_of_depthCalls` gives the frames of a condition that calls no function.

The first drafts of the call rules fixed the program and the callee before the case analysis and failed by dependent elimination.  `CallBoundRule` instead cases on general indices and reduces by its own pattern matching, and a new rule over indexed commands should take the same form.  Each application's four step theorems set `maxHeartbeats` to 4,000,000.  `Demos.RunningSum.writeStep_bounded` and `Demos.RunningSumFp.writeStep_bounded` have the same proof, as do the two `readStep_bounded`, and `Demos.RunningSum.step_body_bounded` shows the step that chooses between them.
