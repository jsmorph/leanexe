# Writes confined to an interval of memory

The entry applies when code writes into one object and a proof must show that everything else in the store is unchanged, and when overlapping stores build a block whose every byte a proof must state.  `LeanExe.ProofKit.Memory.WritesRange initial final start stop` states that `final` equals `initial` except in the bytes of memory 0 in `[start, stop)`: every other field of the store, the page count, and every byte outside the interval are unchanged.  The unchanged fields include the memory caps, the globals, the tables, and the host state, and the relation holds for stores of any host-state type.

`LeanExe.ProofKit.Memory.WritesRange.refl` starts a chain, `LeanExe.ProofKit.Memory.WritesRange.write64` adds an eight-byte store inside the interval, and `LeanExe.ProofKit.Memory.WritesRange.write8` adds a one-byte store.  `LeanExe.ProofKit.Memory.WritesRange.trans` composes two relations with the same interval, and `LeanExe.ProofKit.Memory.WritesRange.mono` enlarges an interval, so that writes into different intervals compose once each is enlarged to one interval that contains both.  `LeanExe.ProofKit.Memory.WritesRange.read64` gives the unchanged value of a word whose eight bytes lie outside the interval, and `LeanExe.ProofKit.UInt64Array.At.writesRange` and `Verified.Bytes.At.writesRange` keep an array or a byte buffer that lies apart from it, as [the entry on array layout](../array-memory-framing/README.md) describes.

A loop that writes into one object puts the relation from the store at the loop's start into its invariant, and each pass composes it with the pass's write by `LeanExe.ProofKit.Memory.WritesRange.trans`.  `Verified.wpX_copyInto` keeps the interval of the destination array this way and passes the relation to its continuation.  `Verified.Wasi.wp_moveCode` keeps an interval that grows with the passes, `[pdst, pdst + 8 k)` after `k` passes, together with the equation of the bytes already moved.  `Verified.writeLength_frame` and `Verified.RecordStorage.writeHeader_range` state the write ranges of a length store and of a store into a record's header, which the proofs of array and tree code compose with the loops' relations.

Code that zeroes a block with 64-bit stores and then stores each field with stores of the field's width writes some bytes twice, and a proof of the finished block states every byte of the block.  `Verified.Wasi.BlockAt before mem pointer size byte` states that `mem` has the pages of `before`, holds `byte i` at `pointer + i` for each `i < size`, and agrees with `before` at every other address.  `Verified.Wasi.BlockAt.write64`, `Verified.Wasi.BlockAt.write32`, and `Verified.Wasi.BlockAt.write8` turn `byte` into `Verified.Wasi.writeByte byte offset width value`, and `Verified.Wasi.writeByte_two` joins the two byte stores that `Verified.Wasi.fieldStoreCode` emits for a field of two bytes, so the proofs of the zeroing, `Verified.Wasi.wp_zero_words`, and of the field stores, `Verified.Wasi.wp_field_stores`, end at a fold over the fields and their values, `Verified.Wasi.blockFold`, with no reasoning about the order of overlapping stores.  `Verified.Wasi.BlockAt.congr` replaces the function of the bytes by an equal one, as the poll proof does when the field stores start from the zeroed block.  The bytes that the host reads, `Verified.Wasi.subscriptionBytes`, are the same fold, `Verified.Wasi.blockByte`, so `Verified.Wasi.BlockAt.at_` with `Verified.Wasi.subscriptionBytes_get` gives their `Verified.Bytes.At`, and `Verified.Wasi.BlockAt.frame` gives the `Verified.Wasi.GuestFrame` of the whole sequence of stores.  The fields' disjointness, `Verified.Wasi.fieldsApart_pairwise`, serves the reading of each field back from the block, `Verified.Wasi.subscription_fields_at`, through which `Verified.Wasi.OracleSys.decodeArgs_lower` recovers the arguments of a request, and `Verified.Wasi.wp_sys_poll_accept_with` is the worked example of the stores.
