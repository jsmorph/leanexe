# Writes confined to an interval of memory

The entry applies when code writes into one object and a proof must show that everything else in the store is unchanged.  `LeanExe.ProofKit.Memory.WritesRange initial final start stop` states that `final` equals `initial` except in the bytes of memory 0 in `[start, stop)`: every other field of the store, the page count, and every byte outside the interval are unchanged.  The unchanged fields include the memory caps, the globals, the tables, and the host state, and the relation holds for stores of any host-state type.

`WritesRange.refl` starts a chain, `WritesRange.write64` adds an eight-byte store inside the interval, and `WritesRange.write8` adds a one-byte store.  `WritesRange.trans` composes two relations with the same interval, and `WritesRange.mono` enlarges an interval, so that writes into different intervals compose once each is enlarged to one interval that contains both.  `WritesRange.read64` gives the unchanged value of a word whose eight bytes lie outside the interval, and `UInt64Array.At.writesRange` and `Verified.Bytes.At.writesRange` keep an array or a byte buffer that lies apart from it, as [the entry on array layout](../array-memory-framing/README.md) describes.

A loop that writes into one object puts the relation from the store at the loop's start into its invariant, and each pass composes it with the pass's write by `WritesRange.trans`.  `Verified.wpX_copyInto` carries the interval of the destination array this way and hands the relation to its continuation.  `Verified.Wasi.wp_moveCode` carries an interval that grows with the passes, `[pdst, pdst + 8 k)` after `k` passes, beside the equation of the bytes already moved.  `Verified.writeLength_frame` and `Verified.RecordStorage.writeHeader_range` state the write ranges of a length store and of a store into a record's header, which the proofs of array and tree code compose with the loops' relations.
