# Checks that can fail

The entry applies when a check passes and its passes are to count as evidence: a co-simulation, the replay of a log against a specification, the kernel's check of an image file, a comparison of an encoder with an assembler, a driver's count of axiom reports, the self-test of an independent reference, or a host script that judges a run on a board.  Each of these passes vacuously when it compares nothing, compares a result with itself, or accepts every outcome.  A check counts as evidence after a recorded run in which a fault of the kind that it should catch makes it fail.  [The entry on independent review](../independent-review/README.md) applies the same test to a specification's cases with wrong programs, [the entry on testing a statement before its proof](../statement-testing/README.md) applies it to a statement's tests with false variants of the statement, such as a property that the procedure is known to fail, and [the entry on encodings and co-simulation of machine forms](../machine-form-validation/README.md) describes the co-simulations whose seeded faults appear below.

Keep a seeded fault whose failures can be predicted as a required step of the check.  `tests/baremetal/m7-board.sh cosim-check` checks the board's results against the model and then against the model with `ADC`'s carry in replaced by 0, the option `adc-carry` of `m7-cosim board-check`, and it fails unless the second check reports a differing case of `ADC` with registers.  On each run of the board's co-simulation exactly the `ADC` cases with the carry flag set on entry differed under the changed model, as the table of [the Cortex-M7 document's section on co-simulation](../../../docs/m7-bare-metal.md#co-simulation) records.  The step fails as well when the changed model's check fails without that difference, so the predicted set of failures separates a check that detects the fault from one that fails for another reason, such as an unreadable result file.

Give the self-test of an independent reference a negative control beside its positive cases.  `self_test` of `tests/cic/reference.py` requires that the 64-bit cascade agree with the exact outputs for inputs within Hogenauer's bound, and that a constant input of -2^B, one bit past the bound, give a reading that differs from an exact output.  The second requirement shows that the comparison detects the overflow that the bound excludes, and a reference whose comparison could not detect it would pass the first requirement as well.

Show for each kind of check that one changed byte or bit makes it fail, and record the run.  With one byte of an image changed, the kernel rejects the image's theorem, and for an image in parts it rejects the part that holds the byte ([the images and their kernel checks](../../../docs/m7-bare-metal.md#the-images-and-their-kernel-checks)).  With one bit of the assembled bytes changed, `tests/baremetal/m7-encode.sh` reports that sample ([encoding](../../../docs/m7-bare-metal.md#encoding)).  Altered copies of a mirror's log, with a changed digit of an answer, a missing or an extra answer, a missing `reset` line, or an input line that is not hexadecimal, each made `bms-replay` fail at the altered line ([the replay against the specification](../../../Demos/Bms/Host.md#the-replay-against-the-specification)).

Require a positive or an exact count of what the check reads.  `tests/isla/theorems.sh` and `tests/isla/m7-theorems.sh` fail when a module prints no axioms, `check_axioms` of `tests/verified/run.sh` fails when an audit prints no report, and `m7-cosim check` of `tests/TestSupport/M7/CosimMain.lean` fails when the harness's output holds no case line and no division line.  `m7-board.sh check`, `m7-qemu.sh`, `a64-images.sh`, and `m7-image.sh` require each file module to print an exact number of axiom reports, none of which names an axiom beyond `propext`, `Classical.choice`, and `Quot.sound`, so a new `#print axioms` line in a file module raises the count that its driver expects, as [the entry on bounds for a step's phases](../m7-phase-bounds/README.md) notes.  `m7-board.sh cosim` requires the result header's word `0x600DCAFE` and as many saved cases as the image holds.

Make the pass criterion exclude every outcome that the hypothesis under test rules out.  `tests/baremetal/uart_sha.py --overrun` tests the SHA-256 step with USART3's overrun detection disabled: after blocks A and B in one write, it sends single bytes until an answer arrives and requires the answer to equal the digest of the bytes before A, A, the last bytes of B, at least one, and the single bytes.  It stops after 63 single bytes, since an answer after 64 would mean that USART3 delivered no byte of B, while OVRDIS keeps B's last byte in `USART_RDR` until the step reads it.  The control run of the same phase against `sha.bin`, whose initialization leaves overrun detection enabled, got no answer after 63 single bytes and read `ORE` set ([the programs on QEMU, in Renode, and on the board](../../../docs/m7-bare-metal.md#the-programs-on-qemu-in-renode-and-on-the-board)).

Keep a control input for each edit of a reference's harness.  The A64 row "The Isla check" of [the trusted base](../../../docs/trusted-base.md#a64-aarch64-images) lists, as evidence for the edit `tests/isla/armv9p4-checked.diff`, which makes Isla's run stop when the decoder throws an exception, a control encoding that the edit stops.  Without such an input, an edit that stopped nothing would leave every trace as it was and pass every comparison.  [The entry on code around an executable reference](../reference-harness-audit/README.md) covers the audit of such edits.

A driver that runs a check over the files of a directory or the matches of a pattern passes when there are none, so it requires a nonempty set or the number of items that it expects, as the drivers above count axiom reports and saved cases.  A digest that combines many results by addition or by exclusive or lets an error in one result cancel an error in another, so compare the results one by one, or a cryptographic hash of their bytes.  A seeded fault that makes the check fail for an unrelated reason shows nothing, so the step that runs it requires the predicted difference, as `cosim-check` requires a differing case of `ADC`.

The worked examples are the step of `m7-board.sh cosim-check` that runs `adc-carry`, the negative control in `self_test` of `tests/cic/reference.py`, the overrun phase of `uart_sha.py --overrun` with its control run against `sha.bin`, and the exact counts of axiom reports in `m7-board.sh`, `m7-qemu.sh`, `a64-images.sh`, and `m7-image.sh`.  `cosim-check` and the image drivers repeat their controls on every run, and `reference.py` runs its self-test by default.  The altered logs of the BMS replay and the changed bytes of the M7 images are single runs that the documents record, so a change to `bms-replay` or to the image checks needs them run again.
