# Calls with operands below the arguments

The entry applies when code calls a function while the operand stack holds values below the call's arguments, and the callee's theorem is stated on its arguments alone.  Talos lists operands with the top of the stack first, so the stack at the call is `args ++ rest`, where `rest` is the part under the arguments.  A theorem about the runtime's `alloc` or `release`, or about a compiled function, takes exactly its arguments, and the caller extends it to `args ++ rest` at the call.

`Wasm.Runs.append_args`, of `LeanExe/Pipeline/Aborts.lean`, extends `Runs aborts env m id store args P` to `args ++ rest`.  It takes three side conditions: that `id` is not an import, the lookup of the internal function, and the equality of the argument count with the function's parameter count.  Its postcondition gives the results `out` with `values = out ++ rest` and `P` of `out`, and a trap that `aborts` allows stays a trap.  `Wasm.wp_call_runs` then composes the extended run with the caller's continuation, and `Verified.wpX_call_runs` does so under the alignment flag of the verified compiler's proofs, with `LeanExe.ProofKit.RunsA.append_args` for an aligned run.

`Wasm.TerminatesWith.append_args` and `Wasm.run_append_of_success`, of `LeanExe/ProofKit/CallRemainder.lean`, are the forms for a `TerminatesWith` theorem and for one run at a fixed fuel.  Talos's `Wasm.wp_call_tw` composes a `TerminatesWith` theorem with the continuation, and `Wasm.TerminatesWith.runs` turns one into `Runs`.  The WASI helper proofs, such as `Verified.Wasi.wp_effect_helper`, apply `run_append_of_success` to the run of one helper.

`Verified.wp_release` turns the theorem of `release` on its one argument into `Runs`, extends it with `Runs.append_args`, and closes the call with `wp_call_runs`.  It proves the side conditions with `by simp [hm.imports]`, `by simpa [hm.imports] using hm.release`, and `by rfl`, from `hm : Verified.Runtime m`, which states that function 0 of `m` is `alloc`, function 1 is `release`, and `m` has no imports.  `Verified.wp_alloc` does the same for `alloc`, and `Verified.FunSpec.runs` for a compiled function, including one whose code takes the call depth as an added first argument.
