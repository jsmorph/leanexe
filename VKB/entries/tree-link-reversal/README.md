# Tree updates by link reversal

A program that inserts into or deletes from a binary search tree using only tail recursion descends by reversing links: each node it leaves holds the path above it in the field of the child it moves to, and an ascent restores the links on the way back to the root.  The compiler translates both tail recursions into loops, so the module's theorems have no call-depth premise (`Library/Trees/Avl/Compiled.lean`, header).  The specification is a structural recursion, such as Knuth's Algorithm T as `algorithmT`, Algorithm A as `algorithmA`, or the deletion `deleteA`, and the proof first equates the program with it and then proves the recursion's properties.

Prove that the descent returns what the ascent returns from the specification's result below the same path, by induction on `t` generalizing `path`: `Library.Trees.Search.descend_eq` states `descend x path t = ascend x path (algorithmT x t).2`, and `Library.Trees.Avl.descend_eq` states `descend x path t = ascend x (algorithmA x t).1 path (algorithmA x t).2`, whose first component is the flag that the subtree grew.  When the ascent carries such a flag, state one step of the ascent through a left and through a right child as lemmas, in terms of the specification's adjustments.  `Library.Trees.Avl.ascend_left` rewrites `ascend x g (.node p k b c) t` as `ascend x (growLeft t k b c).1 p (growLeft t k b c).2` when `g` holds and as the ascent above the rebuilt node otherwise, and `growLeft_rotate` matches the program's rotation with the specification's.  The induction step then closes with `simp only [descend, h, ↓reduceIte, ihl, ascend_left h, algorithmA]` and `cases (algorithmA x l).1 <;> rfl`, and the program's entry follows from `simp [insert, descend_eq, ascend]`, since the path starts as a leaf.

The properties follow by structural induction on the specification.  `Ordered t := (keys t).Pairwise (· < ·)` states the order over the keys in symmetric order, and `ordered_node` splits the order of a node into its subtrees' orders and the bounds of their keys against the node's key.  `Library.Trees.Avl.keys_algorithmA` states the keys after an insertion as `List.orderedInsert`, with `Library.Trees.Search.orderedInsert_append_cons` and `orderedInsert_append_of_lt`, and `algorithmA_props` with `growLeft_props` and `growRight_props` follows the heights through the cases of steps A7 to A9.  The deletion repeats the method with `Library.Trees.AvlDelete.ascendDel_left`, `ascendDel_right`, `ascendMin_step`, and `ascendMin_found`, and `descendDel_eq` and `minDel_eq` state its two descents.

`UInt64.zero_sub` is a `simp` lemma, which rewrites the balance factor `0 - 1` of the programs to `-1`.  `ascend_right` therefore splits on `b = 0 - 1`, the height lemmas take the factor's cases as hypotheses, and both substitute the factor and let `simp +decide` decide the comparisons of literals.  `simp` with the equation of `minDel` unfolds it at every node, because `minDel` tests its left subtree with `isLeaf` where the insertion's functions match a pattern, so `minDel_eq` splits on that subtree with `cases` and unfolds one level with `rw [minDel]`.  The compilations of the AVL insertion and deletion set `maxHeartbeats 1000000` before `verified_compile` (`Library/Trees/Avl/Compiled.lean`, `Library/Trees/AvlDelete/Compiled.lean`), and that of the search tree does not.

The worked examples are `Library.Trees.Search.descend_eq` and `searchTree` for the search tree, `Library.Trees.Avl.descend_eq` and `searchTree` for the insertion, and `Library.Trees.AvlDelete.descendDel_eq`, `minDel_eq`, and `removes` for the deletion.  `searchTree` and `removes` combine the order, the keys, and the heights into the structures `SearchTree` and `Removes` of the specifications.  The compiled modules join the equalities `insert_eq` and `delete_eq` with the generated theorems through `Verified.implementsA_congr`.
