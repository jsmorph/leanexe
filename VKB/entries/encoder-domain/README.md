# Instructions that the encoder accepts

The entry applies when a change to the verified compiler, to the code of a WASI command, or to the runtime emits an instruction that the existing code does not emit.  Talos's `Wasm.Instruction` has more forms than the verified encoder accepts, and Talos's semantics gives each of them a meaning, so a proof over code that uses such a form checks while no module that holds the code can be written as bytes.  The encoder accepts the instructions of `Wasm.Encoding.InstructionForm` in `LeanExe/Encoding/Domain.lean`, whose loads are `load8U`, `load32`, and `load64`, while Talos has other loads, among them `Wasm.Instruction.load16U`, `Wasm.Instruction.load8UI64`, `Wasm.Instruction.load16UI64`, `Wasm.Instruction.load32UI64`, and signed loads.

The failure appears when a program whose module holds the new code compiles, after the general proofs of the code have checked.  `Verified.Wasi.Reflect.emitEncoding` runs `Wasm.Encoding.encodeParts` on a compiled WASI module and stops `verified_compile_wasi` with `module … does not encode`, `verified_compile` stops with `the module does not encode` in the same way, and the encoder's message for an instruction outside the domain is `instruction is outside LeanExe's emitted WASM`.  The proofs that move pure code into a WASI module, such as `Verified.Wasi.PureTransport.wp_prefix_with`, also take `Wasm.Encoding.ProgramForm` of that code as a premise, so pure code must lie in the domain before those proofs apply to it.

Check the domain before choosing the instructions of new code, and build a missing form from accepted ones.  The record form of `Verified.Wasi.Command.sys` is the worked example: `Verified.Wasi.fieldLoadCode` loads a record field of one byte with `load8U` and `extendUI32`, of four bytes with `load32` and `extendUI32`, of eight bytes with `load64`, and of two bytes with two `load8U` whose second byte it multiplies by 256 and adds to the first.  `Verified.Wasi.littleEndian_read16` proves that the two byte loads give the field's little-endian value, and `Verified.Wasi.wp_field_load` states the result of the code for each of the four widths.  Extending the domain instead changes `Wasm.Encoding.InstructionForm`, the encoder, and the decoder `Wasm.Encoding.decode`, which belongs to the trusted base as [the encoder's interface](../../../LeanExe/Encoding/README.md#interface) states, and it adds cases to the encoder's completeness and decoding proofs.
