# Corollaries over the layer events of a WASI executable

The entry applies when a WASI command has a theorem over its WASI events, and its Linux executable needs a corollary that states the request over the layer events of the shim, the calls that Linux answered.  The executable's theorem holds the layer events of a run of `main` and its exit under `Verified.Shim.linuxHost`, which [the entry on WASI hosts built on a lower layer](../wasi-host-from-layer/README.md) describes together with readAll's corollary.  The random histogram and the random choice add to that form the exclusion of trapped runs, the shape of the layer events, a statement that mirrors the command's specification, and a witness.

When the command's charge does not depend on the replies, a budget excludes the guest's trap for every reply sequence, as `Demos.RandomHistogram.linux_footprint_bounded` does, and the condition on the replies can be a predicate on the layer events of the finished run.  `Demos.RandomHistogram.Full` states that every `getrandom` returned the count that it asked for and every `write` an error number or at most the count that it offered, and `Demos.RandomHistogram.linux_exec_counts` proves `Demos.RandomHistogram.Counts` for every run whose layer events meet it, a run that ends at the accepted exit.  The trapped runs need excluding without a class of reply sequences: `Demos.RandomHistogram.main_trapped` shows by the structure of `main` that every trapped run has a trapped call among `args_sizes_get`, `args_get`, `random_get`, and the write, and `Demos.RandomHistogram.image_untrapped` shows that no layer events that meet `Full` are the image of such a call.  A lemma over every action would also have to exclude a trapped exit inside `main`, which needs a predicate that `main` makes no exit, and the lemma over the structure of `main` needs none.  The file theorem `histogram_elf_counts` of `tests/TestSupport/A64/ImageFilesRandomHistogram.lean` concludes `Full ls → Counts args ls (q.core.x 0)` for every reply sequence.

A corollary that states only the bytes that the calls returned and wrote admits extra calls, one call where the design asks for several, and other flags.  `Counts` therefore states the sequence of the layer events: calls of `getrandom`, each of at most 4,096 bytes with flags 0 (`Demos.RandomHistogram.Drawing`), followed by writes of descriptor 1, each of which offered the bytes of the output that the writes before it did not take (`Demos.RandomHistogram.OfferedLayer`).  The review of the histogram's theorems found the gap (`Demos/RandomHistogram/review.md`), and the shape followed from the images that the proof already held.  The conditions of `Full` hold of Linux's replies for the command's calls, by the facts that [the entry on hardware facts](../hardware-facts/README.md) cites.

A command whose specification over WASI events is an inductive relation of passes, such as `Demos.RandomChoice.Rounds` in `Demos.RandomChoice.Meets`, keeps that relation for the layer events.  Restating the passes over layer events would copy the inductive and every lemma about it.  `Demos.RandomChoice.Mirrors x e` instead states, for each kind of WASI event that the command makes, the one layer event that the shim makes for it under `Full`, and it is `False` for every other kind.  `Demos.RandomChoice.Choices` then states `List.Forall₂ Mirrors events ls` together with `Rounds` over the random bytes `Demos.RandomHistogram.randomData ls` that Linux returned, so the layer events are the passes of the command's own specification.  `Demos.RandomChoice.rounds_mirrors` proves it by induction on `Rounds`, with one lemma for each kind of event, `Demos.RandomChoice.random_mirror` and `Demos.RandomChoice.write_mirror`, and the output and cap facts of `Meets` transfer without a new proof, since `Verified.Shim.Images.writeData` equates the bytes that the layer's writes took with the WASI trace's.  The reviewer's model found that the clauses of `Choices` on status 0 and on the cap reject no run that the `Mirrors` and `Rounds` clause accepts, so they restate its consequences in the terms that `Demos.RandomChoice.output_count` takes.

A corollary of the form `∃ q ls, … ∧ (Full ls → Counts …)` holds vacuously if no process meets its premises with layer events that meet `Full`, so a witness shows that the premises hold together, as [the entry on satisfiable hypotheses and complete conclusions](../non-vacuous-statements/README.md) requires.  `Demos.RandomHistogram.fullReplies_run` follows the action under one reply sequence, `Demos.RandomHistogram.fullReplies`, without evaluating a run of the machine.  The replies are indexed by the call's position, so `Verified.Shim.Carried` gives each event's result once the proof knows the events before it, and `Demos.RandomHistogram.carried_split` splits `Carried` over an append.  `histogram_elf_witness` of the same file reuses the footprint lemma of the corollary, `histogram_elf_runs`, with a memory that holds the file's segments as `LeanExe.A64.ElfLoaded` reads them and an initial stack whose bytes `decide +kernel` checks.  `cases` on a `Verified.Shim.Images` whose index is `[] ++ []` fails by dependent elimination, which `Demos.RandomHistogram.images_nil` with a `show` avoids, and `congr 1` on `byteAt` of the file's number recurses into the literal, which `congrArg (byteAt histogramElfBytes)` avoids.  `Demos.RandomChoice.witness_run` and `choice_elf_witness` of `tests/TestSupport/A64/ImageFilesRandomChoice.lean` give the random choice's witness in the same way.  `tests/TestSupport/A64/ElfWitness.lean` holds what the witnesses of the histogram, the random choice, and the manifest checker share: the loader's memory `TestSupport.A64.ElfWitness.loadedMem`, which meets `LeanExe.A64.ElfLoaded` by `TestSupport.A64.ElfWitness.loadedMem_loaded`, the transfer of an initial stack to it, `TestSupport.A64.ElfWitness.loadedMem_initial`, and the initial stack of the two one-byte arguments `h` and `1`, which `TestSupport.A64.ElfWitness.loadedMem_stack` places.  A witness whose arguments are `h` and `1`, such as `manifest_elf_witness` of `tests/TestSupport/A64/ImageFilesManifestCheck.lean`, takes the memory and the stack from the module, and a witness with other arguments proves its own stack over `TestSupport.A64.ElfWitness.stackMem` by `decide` and takes the rest, as `witness_stack` of `tests/TestSupport/A64/ImageFilesRandomChoice.lean` does for the random choice's three arguments.

The worked examples are `Demos.RandomHistogram.linux_exec_counts`, `Demos.RandomChoice.linux_exec_choices`, and the file theorems `histogram_elf_counts` and `choice_elf_choices`, which `tests/linux/a64-wasi.sh` elaborates beside the executables.
