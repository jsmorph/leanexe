# Hosts that satisfy the WASI premise

Every WASI theorem assumes `targetHost.Satisfies module (hostSpec host)`, or `targetHost.Satisfies module (hostSpecWith host calls)` for a module that imports flat calls: the Talos host environment meets the specifications that `Verified.Wasi.hostSpec` or `Verified.Wasi.hostSpecWith` derives from the relational host `host`.  A theorem under that premise says nothing about a host for which no such environment exists.  A reader or a later proof that must show that the premise can hold uses the results below, and a change that adds a host contract proves them for it.

`LeanExe.Wasi.Host.Total` states that `host` permits a reply to every read and write and either accepts or rejects every exit.  `LeanExe.Wasi.Host.Total.satisfiable` builds, for every module with the three WASI imports, an environment that satisfies `hostSpec host`, from an oracle that chooses a permitted reply, through `Verified.Wasi.OracleHost.env_satisfies`.  Conversely, `LeanExe.Wasi.Host.Answers.of_satisfies` shows that every satisfying environment answers each request that the one-iovec ABI can express with its payload at address 16, which `LeanExe.Wasi.Host.Answers` states: reads of capacity at most `2^32 - 16`, writes of at most `2^32 - 16` bytes, and every 32-bit exit status.  `LeanExe.Wasi.Host.Total.answers` derives the second condition from the first.

`hostSpecWith host calls` adds `Verified.Wasi.sysContract` for each call, and `Verified/Wasi/HostTotalWith.lean` gives the two conditions for it.  `LeanExe.Wasi.Host.TotalFor` adds to `LeanExe.Wasi.Host.Total` a permitted reply to every fitting, accepted request of each call, `LeanExe.Wasi.Host.TotalFor.satisfiableWith` builds a satisfying environment from it, and `LeanExe.Wasi.Host.Answers.of_satisfiesWith` derives `LeanExe.Wasi.Host.AnswersFor` from every satisfying environment.  The environment's import for a call, of `Verified/Wasi/OracleSys.lean`, decodes the request from the core arguments, and `Verified.Wasi.OracleSys.decodeArgs_lower` proves that it decodes every admitted request.  `tests/wasi/SysWitness.lean` gives a host that meets `LeanExe.Wasi.Host.TotalFor` for the calls of the flat call example and an environment that satisfies `hostSpecWith` for its module.

A contract that states, for every request whose lowering is the call's core arguments, that the result records that request holds only when at most one admitted request lowers to each list of arguments, since one result cannot record two requests.  `Verified.Wasi.lowerArgs` reads a missing argument, or an argument of another kind, as the word 0, so `[.bytes b]`, `[]`, and `[.word 0]` share the core arguments of a `word32` parameter, and a premise that admitted every request that the call does not reject would leave `hostSpecWith host calls` without a satisfying environment for every nonempty `calls`.  Every theorem that assumes such an environment would then hold vacuously while every build and test passed.  The premise `Verified.Wasi.SysRequest` therefore requires `Verified.Wasi.argsFit`, one argument of the parameter's kind for each parameter that takes one, within its core type, and no other, on which `lowerArgs` is injective.  The proof of a satisfiability theorem decodes each admitted request from its arguments and fails on a premise that admits two requests with the same arguments, so a change that adds a contract states and proves its satisfiability, as [the entry on satisfiable hypotheses and complete conclusions](../non-vacuous-statements/README.md) asks of every hypothesis, and checks each way in which two requests can share their core arguments.

For the necessary direction, `LeanExe.Wasi.Host.Answers.layoutRequest` builds a request's memory with `Verified.Wasi.layoutPointers` and `Verified.Wasi.layoutMemory`, which lay the inputs and the output regions out one after another from address 16 in the order of the parameters, and `Verified.Wasi.Layout.laid` proves the invariant `Verified.Wasi.Layout.Laid` of that layout.  The invariant states that the spans of the regions and then those of the inputs are pairwise apart, the order of `SysRequest`, while the layout interleaves them, so the proof moves each new input to the front of the list with `List.Perm.pairwise_iff` and `List.perm_middle`, which need only the symmetry of `LeanExe.Runtime.regionsDisjoint`.  A layout that ends at `2^32` can place a region of size 0 at `2^32`, whose pointer is 0, and `Verified.Wasi.Layout.Within` states each span's address modulo `2^32`, so that `omega` treats that span with the others, as in `Verified.Wasi.Layout.disjoint_of_below`.

State the result as a sufficient condition and a necessary one.  `LeanExe.Wasi.Host.Total` and `LeanExe.Wasi.Host.TotalFor` are sufficient, `LeanExe.Wasi.Host.Answers` and `LeanExe.Wasi.Host.AnswersFor` are necessary, and neither pair is exact.  The scripted host of the WASI tests is one such oracle, and `tests/wasi/ScriptHostAxioms.lean` audits its theorems.
