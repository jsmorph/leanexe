# Byte updates in place

The entry applies when a program writes the bytes of a buffer one at a time, as a renderer of text into an output buffer does, and the buffer's memory must not grow with the input.  `LeanExe.Bytes.set buffer index byte` replaces byte `index` with the low eight bits of `byte` and leaves the buffer unchanged when `index` is not below its size, as `Array.set!` leaves an array.  The verified compiler reflects it to `Verified.Expr.bytesSet`, whose code takes the buffer with `Verified.Var.ownedCode`: the buffer moves when its variable is owned and dies at the update, and the code then writes the byte into the buffer's block, and otherwise the code copies the buffer and writes into the copy.  `Verified.Expr.allocs` charges the copy through `Verified.Var.ownedCost`, so an update that moves its buffer charges nothing.

The update is in place only when it is the buffer's last use.  `Verified.Examples.BytesSet.setKept` reads its buffer after the update, so its code copies the buffer, and the cases of `tests/wasi/bytes-set.tsv` count two allocations and one release for it, where the cases of the updates in place count one allocation, the host's argument block.  A loop whose state is the buffer, as in `Verified.Examples.BytesSet.fillFrom`, moves the buffer from pass to pass, and a function that takes the buffer as owned and returns it, as `Demos.RandomChoice.putPicks` does, has a generated bound of 0 (`Demos.RandomChoice.putPicks_bound`).  Its call theorem is an `ImplementsA` theorem with `Moved LeanExe.Bytes` for the buffer, since `Verified.CallSpec` requires arguments that move no object, as [the entry on specification call theorems](../spec-call-theorem/README.md) describes.  `Demos.RandomChoice.putPicks_implements` applies `Verified.implementsA_congr` with a pattern of thirteen components for its four arguments, since the representation of a tuple nests a pair at each component.  [The entry on one buffer through a loop](../buffer-through-loop/README.md) applies the same rule of last uses to calls that fill a buffer.

A proof about the result of a sequence of updates states each byte as an element of a list.  `Demos.RandomChoice.set_getD` reads `(b.set p x).data.data.toList.getD i 0`, `Demos.RandomChoice.putLineBytes_getD` carries that form through a loop of updates, and `Demos.RandomChoice.list_eq_of_getD` and `Demos.RandomChoice.bytes_eq_of_toList` return to an equation of buffers, as `Demos.RandomChoice.putPicks_eq` does.  `LeanExe.Bytes.data_size_set` states that an update keeps the size, and [the entry on functions over `LeanExe.Bytes` as functions over lists](../bytes-as-lists/README.md) gives the readers of a buffer's bytes.

The compiler's proof of the update, `Verified.specX_bytesSet`, evaluates the index and the value into locals, takes the buffer with `Verified.specX_ownedVar`, and splits on the range test with `LeanExe.ProofKit.wpX_iff_cons`.  The branch that writes applies `Verified.Bytes.wpX_storeWord` and keeps the facts of `After` with `Verified.After.writeByte`, and `Verified.Ty.AlignedVal.bytesBlock` keeps the alignment of the buffer's block after the store.  `Verified.spec_bytesSet` states the result for the unaligned specification.  A new update form of the dialect follows the same three parts.
