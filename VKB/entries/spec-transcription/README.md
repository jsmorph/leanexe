# Transcriptions of published standards

A program that implements a published standard, such as a hash function of FIPS 180-4 or FIPS 202, CRC-32 of ITU-T V.42, SipHash, or XXH64, has a specification theorem that equates its result with a Lean transcription of the standard.  The theorem states nothing about the standard beyond what the transcription states, so the transcription follows the standard's text, runs on the standard's published vectors, and is proved equal to every other form that the proof or the tests use.  The entry applies to a program for a new standard and to a program whose specification cannot be evaluated on its test inputs.

Write the transcription in its own module, in the standard's sections, names, and order, on the standard's own objects.  `Library/Hashing/Sha3/Spec.lean` transcribes FIPS 202 on strings of bits, `Library/Hashing/Crc/Spec.lean` transcribes V.42 and RFC 3720 with Mathlib's polynomials over `ZMod 2`, and `Library/Hashing/SipHash/Spec.lean` transcribes §2 of the SipHash paper on `UInt64`.  An independent review compares the transcription with the standard, and the program's README records the result, as the READMEs of CRC, SHA-3, SipHash, and XXH64 do.  A constant of the standard is a closed fact that `decide +kernel` checks, such as `Library.Hashing.Sha3.Spec.rhoSteps_table2` for the offsets of Table 2 of FIPS 202, as [the entry on closed computations](../closed-computations/README.md) describes.

The program's theorem equates its result with the transcription directly or through a copied implementation.  `Library.Hashing.SipHash.Proof.siphash24_spec` and `Library.Hashing.XxHash64.Proof.xxh64_eq` state the program equal to the transcription applied to the message's bytes.  `Library.Hashing.Sha256.sha256_bytes` equates the program's digest bytes with `SHS.SHA256.Impl.sha256`, the implementation on bytes that `Library/Hashing/Sha2` copies from fips-180-4-lean, and `Library.Hashing.Sha256.sha256_spec` applies the copied equivalence `SHS.Equiv.SHA256.sha256_correct` to reach the transcription, as `Library.Hashing.Sha512.sha512_spec` does for SHA-512.

A transcription that cannot run, or runs too slowly for the vectors, gets a computable form proved equal to it.  CRC's transcription computes remainders of Mathlib polynomials, `Library.Hashing.Crc.Division.crc32_eq` equates it with `Library.Hashing.Crc.Division.crc32Eval`, a division one bit at a time, and `Library.Hashing.Crc.Proof.crc32_spec` reaches the program through it.  SHA-3's `Library.Hashing.Sha3.Spec.keccakP` applies the steps of Algorithm 7 to state arrays, and the `@[csimp]` theorem `Library.Hashing.Sha3.Spec.keccakP_eq_run` makes compiled code use `keccakPRun`, which holds the state between rounds as an array of bits and computes each round constant once, while the theorems keep `keccakP`.

The vector checks of `tests/TestSupport/Hashing`, which the executables `sha3-vectors`, `crc-vectors`, `siphash-vectors`, and `xxhash64-vectors` of `lakefile.lean` compile, run both the transcription and the program natively on the published vectors under `data/hashing`.  When a specification cannot be evaluated on test inputs, a reference proved equal to it computes the expected values of the cases.  `Library.Combinatorics.DancingLinks.countRef_eq` replaces the specification's sum over all sets of options by the recursion of Algorithm X, and `refPow_eq`, `powModRef_eq`, and `testRef_eq` of `tests/TestSupport/Modules/MillerRabin.lean` replace the power in `x ^ n % m` by repeated squaring.

A definition without published vectors gets a reference in another language that computes the expected values from the definition without the Lean specification, so that one misreading of the definition does not enter both.  `tests/cic/reference.py` computes the CIC decimation filter from its definition over Python's integers and as a cascade of 64-bit words that wrap, and its self-test includes a control that must fail: a constant input one bit past Hogenauer's bound must give a reading that differs from an exact output.  A mirror that judges runs transcribes the primary source and not a package that differs from it.  `tests/baremetal/delim_frame.py` transcribes StuffData of Cheshire and Baker and rejects the variant that the `cobs` package on PyPI writes, which omits the final `0x01` block, and `tests/baremetal/delim-mirror.sh` compares the mirror with the Lean definitions of `LeanExe/Requests/Delimited.lean`.  [The entry on checks that can fail](../discriminating-checks/README.md) gives the controls under which a reference's agreement counts as evidence.

A `@[csimp]` theorem changes only code compiled after it, so `keccakP_eq_run` precedes the definitions that call `keccakP`, and at the end of the file it changed nothing.  Lean compiles a definition with all its binders as arguments, so a state returned as `fun x y z => …` after a `let` recomputes the `let` at every bit.  A form of the transcription that stored each round's state in an array inside such a function rebuilt the array at every read and did not finish one round, and `keccakPRun` holds the state as a computed array instead.

Mathlib's `ring` cannot use the characteristic of `ZMod 2`, so the identities of `Library/Hashing/Crc/Division.lean` that need `p + p = 0` use `grind`, which finds `CharP (ZMod 2)[X] 2`.  The copied proofs of the SHA-512/224 and SHA-512/256 initial values used `native_decide`, which adds an axiom that trusts compiled code.  The copy proves them by `decide +kernel`, so that they depend on no axiom beyond `propext`, `Classical.choice`, and `Quot.sound` (`Library/Hashing/Sha2/NOTICE`).

The worked examples are SHA-256 and SHA-512 through the copied implementation, CRC-32 through the computable division, SHA-3 through `keccakP_eq_run` and `Library.Hashing.Sha3.Proof.sha3_256_spec`, and SipHash and XXH64 directly.  `Library/Hashing/README.md` lists every hashing program with its standard and its proved results.  The dancing-links count and the Miller-Rabin test are the examples of references proved equal to a specification for test cases.
