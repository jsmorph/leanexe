# An array fold proved by induction on its list

A program that folds over an array with `xs.foldl step init`, such as a fold whose state pushes onto an array, has to equal a specification stated by positions or by lists.  `LeanExe.IR.loop_induction` and the build lemmas of the `loop-combinators` entry do not apply, because the fold is neither a `LeanExe.loop` nor a `LeanExe.build`, and an induction on the array itself has no useful cases.

Rewrite the fold as a fold over the array's list with `rw [← Array.foldl_toList]`, which states `xs.toList.foldl step init = xs.foldl step init`.  Then prove what the list fold returns for every initial state by induction on the list, generalizing the state, since each step changes it.  In the step case, `List.foldl_cons` exposes the first step, `dsimp only` reduces the step's `let` and pair so that the induction hypothesis matches, and `List.range_succ_eq_map`, `List.take_succ_cons`, and `List.map_map` move a specification over `List.range` or prefixes past the first element.  Compare the arrays through their lists with `Array.toList_inj`, and `Array.toList_map` and `Array.toList_range` turn a specification of the form `(Array.range xs.size).map f` into a list.

State the list lemma for an arbitrary initial state, not for the program's own, because the induction hypothesis must apply to the state after the first step.  `Examples.RunningMax.foldl_largest` states it for the largest entry `m` and the result `out` so far, and `Examples.RunningMax.compute_eq` applies it at `(0, #[])`.  `SHS.Equiv.SHA256.Pipeline.foldl_compress_lift_gen` carries a per-block equation across `Array.foldl` in the same way, with two rewrites by `Array.foldl_toList` and an induction that generalizes the state.
