# Changes that keep statements and bytes

The entry applies when a shared definition must grow to serve a new case: the verified compiler, a back end's generator or initialization, a predicate that theorems state, or the premises of a general theorem.  Every board, Image, and Isla theorem and every emitted module and image may depend on such a definition, and a change that alters their statements or their bytes requires each of them to be checked and run again, many by drivers that the full check does not run ([the entry on theorems outside the full check](../out-of-build-checks/README.md)).  Shape the change so that existing theorems keep their statements and existing artifacts keep their bytes, and then show that they did.

Add the new case beside the old one, by means that keep the old values as instances.  An argument with a default keeps the existing calls: `LeanExe.A64.program_runs` takes the parameter types `ts` with the default `args.map fun _ => .i64` and the premise on `LeanExe.A64.entryOk` with the default `by decide +kernel`, and `Verified.compileWith` takes its literal pool and its least number of pages with defaults.  A list whose old value stays an instance keeps the old images: `LeanExe.M7.Nucleo.init` is `initConfig ++ [.write usartCr1 0xD]`, and `LeanExe.M7.Nucleo.initOvrdis`, which also disables USART3's overrun detection, is `initConfig ++ [.write usartCr3 0x1000, .write usartCr1 0xD]` beside it, with `LeanExe.M7.Nucleo.initConfig` the accesses that both share.  A general theorem whose old names are instances keeps the old statements: `LeanExe.M7.Nucleo.boardWith_run` takes the initialization as a list, and `LeanExe.M7.Nucleo.board_run` is its instance for `init`, as [the entry on Cortex-M7 board theorems](../m7-board-theorem/README.md) describes.  A predicate beside the old one keeps the theorems that need nothing new: `LeanExe.A64.Isla.AgreesAll` takes the meanings of a trace's abstract functions and lets the trace's paths end with different registers outside the model, while a form whose trace has one outcome and no abstract call keeps `LeanExe.A64.Isla.Agrees`.

A theorem that carries one checked case to the others removes repeated checks.  `LeanExe.A64.genImage_shift` states that the image that `LeanExe.A64.genImage` writes at `image + d`, for `d` a multiple of 4096 with both images in the RAM GiB, has the bytes of the image at `image` and its layout shifted by `d`, and `LeanExe.A64.bytesOk_shift` carries the kernel's check of a file at one address to every such address.  A change that moves an Image's load address within those conditions therefore keeps the file and its check.

Show that the change kept them.  Write every module and image from a baseline tree before the change and from the changed tree, and compare the bytes: `tests/verified/run.sh --check-bytes DIRECTORY` compares the emitted modules with saved reference modules ([the manual's section on types](../../../docs/verified-manual.md#types)), and the images that `a64-images.sh`, `m7-image.sh`, `m7-board.sh check`, and `m7-qemu.sh` write compare as files.  Compare the statement of each theorem that the changed definitions reach in the two trees after normalizing whitespace, and run the drivers of the file modules again, since they read the changed definitions.  For a change meant to alter code, show where the bytes differ, for a module by a comparison of the texts that `wasm-tools print` gives for the two trees, so that each difference lies at a changed form.  For bounds, evaluate each bound before and after the change, since a theorem that states an upper bound stays true when the bound rises.  A change that only reformats source, such as rewrapping its lines, keeps the type and the value of every constant, which hashes of both in the two trees show: `tools/sail/ConstDump.lean` writes the name and the two hashes of each constant of a Sail translation, and the dumps of two builds compare line by line after sorting.  Its selection of constants by a component of their names serves the translations, so another module needs its own selection, such as the constants that the module declares.

A comparison of statements alone misses a change of a definition that the statements name: `LeanExe.M7.Nucleo.board_run` names `init`, so a write added to the definition of `init` would keep its statement and change every board image's bytes and the initialization's trace.  A passing build shows that the theorems hold and says nothing about whether their statements, the artifacts, or the bounds changed.  The comparison of bytes covers what the comparison of statements misses, so the two run together.

The worked examples are `TestSupport.M7.Sha.sha_loop`, which applies `LeanExe.M7.Nucleo.areaBoard_run` with `init`, and `TestSupport.M7.Sha.shaOvrdis_loop`, which applies `LeanExe.M7.Nucleo.areaBoardWith_run` with `initOvrdis` to the same step, so that `sha.bin` and `sha-ovrdis.bin` both have board theorems.  `LeanExe/A64/Proof/ImageTheorem.lean` applies `bytesOk_shift` to an Image's check.  [The entry on image files](../image-file-checks/README.md) describes the kernel's checks of the files, which the drivers repeat on every run whether or not the bytes changed.
