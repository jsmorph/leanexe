What these measurements include

Prefill processes the prompt one token at a time. Its rate is prompt tokens divided by model-call time. Decode measures subsequent model calls, including synchronous host transfers for WGSL. The first generated token comes from the last prefill call, so a 16-token completion normally has 15 decode steps. Sampling and text decoding are timed separately.

First token starts after loading and tokenization and ends when the worker emits its first text token. Total elapsed also includes setup. Each run creates a new worker and, for WGSL, a new device. Shader compilation is setup; lazy GPU weight uploads occur during prefill. Compare both runs CPU Wasm first, then WGSL. Browser and OS caches may affect setup time.

Memory reports peak observed Wasm linear-memory capacity and explicitly allocated WebGPU buffer sizes, not total browser RAM or physical GPU residency. Auxiliary Wasm memory covers the tokenizer, sampler and conversion adapter. The KV cache is already included in model Wasm memory. The extra host weight copy is reported separately; JavaScript heap, temporary copies and driver overhead are not measured.

Temperature 0 uses greedy selection. The page checks generated token IDs when both runs use the same prompt and settings; GPU arithmetic can produce different results. Model and sampling arithmetic execute in Wasm/WGSL; JavaScript handles the interface, transfers and measurements.
