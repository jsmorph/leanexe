# Guarded Binary64 Dot-Product Example

This example moves beyond a single floating-point primitive to a small
numerical kernel generated by LeanExe.  It accepts four `UInt64` binary64
encodings and returns a two-word `CheckedBits` result containing a status and
result bits.

## Goal

Prove total behavior for a guarded two-term dot product:

```text
a0 * b0 + a1 * b1
```

Each input must encode a finite value whose absolute value is at most one half.
The program checks that domain directly on the raw binary64 bits.  On success
it returns status zero and the computed bits.  On rejection it returns status
one and zero bits without executing a floating-point operation.

For the accepted branch, the target numerical result is

```text
|value(result) - (value(a0) * value(b0) + value(a1) * value(b1))|
  <= 3 * 2^-52.
```

The theorem must also establish a finite result, fuel-independent termination,
and preservation of the WebAssembly store.

## Approach

The source function `LeanExe.Examples.Float64Bits.dot2CheckedBits` uses this
raw-bit guard for every operand:

```text
(bits & 0x7fff_ffff_ffff_ffff) <= 0x3fe0_0000_0000_0000
```

The proof first connects that encoding test to the mathematical facts that the
input is finite and has real magnitude at most `1/2`.  Those bounds leave
headroom for both rounded products and their rounded sum.

On the success path, the proof-visible result is the pure Talos expression

```text
Wasm.IEEE64.add
  (Wasm.IEEE64.mul a0 b0)
  (Wasm.IEEE64.mul a1 b1)
```

CodeLib's reusable dot-product error theorem composes the two multiplication
errors with the addition error.  The generated WAT proof separately follows
all four guard calls and both branches.  It then transfers the numerical
contract to the successful WAT execution.

[`Program.lean`](Program.lean) is generated from the actual compiler-emitted
WAT.  [`Spec.lean`](Spec.lean) is the handwritten proof entry point once the
behavior theorem is complete.

## Result

The generated program model is present and records the expected structure:
four raw-bit guard calls, two `f64.mul` operations, one `f64.add`, and a
two-`i64` result.  The source/runtime regression checkpoint also confirms exact
positive output, exact cancellation, rejection, and the intended instruction
counts.

The formal source and WAT numerical theorems are currently in progress.  This
section should be updated to name the checked theorems and their axiom reports
when that checkpoint passes; until then, the `3 * 2^-52` statement above is a
proof target rather than a claimed result.

## Proof boundary

As in the multiplication example, the source-facing contract uses Talos's pure
binary64 model.  It does not identify Lean's native `Float` evaluator with that
model.  Native floating-point execution is a regression oracle only.

The completed WAT theorem will concern the decoded WAT freshly generated from
the registered LeanExe entry and will use Talos's WebAssembly and IEEE-754
semantics directly.  The half-magnitude guard keeps every arithmetic event in
the finite domain, so the numerical theorem does not depend on native
floating-point evaluation or on a choice of NaN payload.

## Check

Once the specification is complete, run from the repository root:

```sh
tools/talos-proof.js check f64_dot2_checked_bits
```

The proof workspace and compiler are checked with Lean `4.34.0-rc2`.
